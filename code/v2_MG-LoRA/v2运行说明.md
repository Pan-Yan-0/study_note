# MG-LoRA v2 · Kaggle 运行说明

## 这一版改了什么（针对 v1 全量结果的两个问题）

| v1 的问题（全量结果） | v2 的改法 | 数学依据 |
|---|---|---|
| 门控几乎是常数（5–10% 缺失时 0.529，超过 50% 时 0.562）：轻度缺失时过度补偿，重度缺失时补偿有效 | 新配置 **mg2**：单调连续门控 g = 1 − exp(−aᵀφ)，a ≥ 0，φ 只含缺失比例和最长缺口比例；另把“不补偿”（epoch 0）也作为候选参与选择 | g(0)=0，处处连续、单调；g ≤ aᵀφ ≤ ‖a‖‖φ‖，所以轻度缺失时输出自动贴近阶段一模型 |
| 补偿把中性类压低（文本缺失档的中性召回：验证集 0.51→0.39，测试集 0.47→0.33），准确率反而上升 | **缺失感知的贝叶斯决策层**：ĉ = argmax_k w_k·p_k，完整输入和有缺失输入各一组权重。对 base / joint / mg / mg2 每个模型各自拟合，按视频分组做 5 折交叉验证 | 代价敏感分类的贝叶斯最优决策就是“对后验概率加权后取最大” |
| 问题三中，声学/视觉局部遮挡会触发门控，“删高分位置比删随机位置影响更大”只占 20–30% | 局部遮挡时**冻结门控**（按未遮挡时的缺失状态计算），只探测内容本身的贡献；同时给出冻结前后的对比 | 遮挡法解释的是“内容的边际贡献”，不应混入缺失补偿机制的开关效应 |

**新增的分析：**
- **Mondrian 共形预测**：按缺失严重度分四桶（完整 / ≤20% / 20–50% / >50%），强度给区间、极性给集合，桶内覆盖率有 ≥ 1−α 的保证，并在测试集上核验。
- **Shapley 交互指数**：T×A、T×V、A×V，以及三方交互项。
- **命题 3 的数值检验**：估计各模态的自相关 ρ(k)，把“连续缺失 vs 散点缺失”下池化均值偏差的理论值 aᵀΣa 与实测值对照；再看这种差异在整个模型的表示与预测上是否还存在。
- **低秩检验**：缺失引起的表示偏移，前 r 个方向占多少能量（与同形状随机矩阵对比）。
- **部署配置按事先定好的规则选择**：在验证集折外结果上，取 J = ½·完整宏 F1 + ½·(PM/SC/MS 平均宏 F1) 最高的配置，种子固定为 17。测试集只用于最后报告。

## 怎么跑

1. **导入**：Kaggle → New Notebook → Import Notebook，选 `mg_lora_v2_kaggle.ipynb`。设置 GPU（T4）并打开 Internet。
2. **Add Input：**
   - ① 比赛数据集（和 v1 一样）；
   - ② **v1 训练好的检查点**：把 v1 的 .pt 文件上传成一个 Kaggle Dataset（New Dataset → 拖入文件 → Create），再 Add Input 进来。**文件可以平铺放，不需要保持原来的文件夹结构。**
     - 需要的文件（共 13 个，每个约 4 MB）：`base_s17/29/43/71/97.pt`、`mg_s17/29/43/71/97.pt`、`joint_s17/29/43.pt`。
     - 位置：v1 运行时在 `/kaggle/working/outputs/ckpt/<8位签名>/` 下。同一个文件夹里的 `train_config.json` 最好也一起传，代码会用它核对配置，防止误用冒烟测试的模型。
     - 冒烟测试的检查点在 `outputs_smoke/ckpt/...`，不要传这些。
     - 如果 v1 的交互会话还开着，也可以直接把 v2 的代码贴进同一个 Notebook 运行：代码也会在 `/kaggle/working` 下找 v1 的检查点。

   日志第 B 节会打印“复用检查点：…”和“检查点：x/y 个已存在”（应为 13/18，剩下 5 个是要新训的 mg2）。如果 .pt 已经找不到了，也能直接跑，只是会全部重训（总时长约 3 小时）。第 C 节有一道合理性检查：如果 base 的验证集 F1 低于 0.45，会打印醒目的警告，说明读到的可能是冒烟模型。
3. **冒烟测试（可选）**：`SMOKE = True`，约 10 分钟。冒烟模式用小样本，签名不同，会重新训练，属于正常现象。
4. **全量运行**：`SMOKE = False`，然后 Save Version → Save & Run All。预计 1.5–2 小时。
5. **取结果**：下载 `/kaggle/working/outputs_v2.zip` 发回来。

## 看结果时重点看这几处

- **`REPORT_v2.md` 开头**：部署选了哪个配置，以及 mg2 各种子选中的 epoch。如果全是 0，说明“不补偿”胜出，补偿没有帮助。
- **第 3–4 节**：mg2 相对 base / mg 的种子配对差（argmax 口径）。
- **第 5–6 节**：加决策层之后各配置的比较，这是最公平的比较口径。
- **第 8 节**：门控系数 a，看哪种缺失最能“打开”补偿。
- **第 9 节 / 图 21**：扩展扫描上，文本缺失 0.1→1.0 时 mg2 是否“轻度时贴近 base、重度时接近 mg”。
- **第 10 节 / 图 24**：共形覆盖率是否达到目标。
- **第 11–12 节 / 图 25–26**：命题 3 与低秩检验。
- **图 27**：冻结门控后，声学/视觉局部证据的忠实性是否回到 0.5 以上。
