# v3.2 · Kaggle 运行说明（大小写恢复 + 两种输入的混合集成，量化后放进附件）

## 为什么这样改（依据 v3.1 全量结果）

- **只用 `text_bert` 的代价：** 还原出的文本是小写的，而 DeBERTa-v3 区分大小写。v3.1 单模型比 v3（读 raw_text）低约 1 个点。
- **v3.1 的集成：** 5 个小写成员的集成在验证集上不比单模型好，中性类召回反而下降。
- **目标（宏 F1 ≥ 0.70、Acc ≥ 0.70、MAE < 0.60，F1 按宏平均）：**
  - v3.1 部署的 s17 在验证集上 Acc 差约 1 个点，宏 F1 差 3.3 个点，MAE 已达标。
  - 宏 F1 的瓶颈是中性类（F1 约 0.48）。

## 这一版改了什么

| 改动 | 做法 |
|---|---|
| 规则化大小写恢复（新家族 `debtc`） | 对 `text_bert` 还原的文本做两件事：句首字母大写（开头以及 `.` `!` `?` 之后）；代词 i 及 i'm / i've / i'll / i'd 中的 i 大写。只改大小写，不读 `raw_text`，所有数据集走同一接口。重训 5 个种子 |
| 小写家族 `deb` | 与 v3.1 完全相同（签名一致），上传 v3.1 的检查点包就直接复用，不用重训 |
| 两种输入的混合集成 `mix_ens` | 两个家族各取种子 17/29/43，共 6 个成员。输入不同，成员之间差异更大 |
| 类别概率的来源 | 三选一：分类头；强度分布头（格点 <0、=0、>0 的概率和）；两者平均。每个家族用 5 个种子在 VS 上折外 J 的均值事先选定，需高出分类头 0.003 才换。强度分布头对中性（强度 = 0）有单独的概率，可能缓解中性类瓶颈 |
| 成员量化（可提交） | 每个 DeBERTa 成员：LoRA 4 bit、头部 8 bit，每 32 个数一个 fp16 尺度，约 4.4 MB（fp16 为 14.6 MB）。在 VS 上核对量化前后的一致性：集成类别一致率 ≥ 0.98 且宏 F1 不降超过 0.5 个点才采用，否则改 8 bit。**之后所有评估、规则层、部署与附件结果都用量化后的成员，与提交文件逐位一致** |
| 部署候选 | `mix_ens`（约 26 MB）、`debtc_ens` / `deb_ens`（各约 22 MB）、两个家族的种子 17 单模型（约 4.4 MB）。参数超过 28 MB 的不参与（10 个成员的 `mix10_ens` 只作参考）。按 VS 折外 J 选，集成需高出最好的单模型 0.003 |
| 其他 | 蒸馏默认关闭（v3.1 没有收益）。扩展扫描改到部署选定之后，只扫 base、naive 和部署模型用到的成员，省时间 |

**预期：** 这几项的收益都不确定，估计 0.5–1.5 个点。Acc ≥ 0.70 有可能达到；宏 F1 ≥ 0.70 仍然很难。报告第 5 节里 `debtc − deb` 的同种子配对差，会直接回答“大小写恢复有没有用”。

## 怎么跑

1. **把 v3.1 的检查点包上传成数据集（强烈建议）：**
   - Kaggle → Datasets → New Dataset，上传 `outputs_v31_ckpt.zip`。Kaggle 会自动解压并保留文件夹结构。
   - 里面有小写家族 5 个种子和 naive 3 个种子，能省约 70 分钟。
   - **不要把里面的 .pt 拆出来平铺上传**：没有同文件夹的 `train_config_deb.json` 核对配置，DeBERTa 检查点会被自动跳过。
2. **导入与设置：** Import Notebook，选 `gmcm_v32_kaggle.ipynb`；GPU 选 T4，**打开 Internet**。
3. **Add Input：**
   - 比赛数据集；
   - `some-pt`；
   - 上一步的 v3.1 检查点数据集。
4. **冒烟测试：** 第一行改 `SMOKE = True`，Run All，约 25 分钟。日志里看这几项：
   - `DeBERTa 词元映射：` 里同时有 `deb|train`（source `text_bert`）和 `debtc|train`（source `text_bert_tc`）。
   - `量化（deb）LoRA 4 bit：…`：冒烟时阈值放宽过，主要确认能走通。
   - `类别概率来源（deb）：… → 采用 …`。
   - `部署选择（v3.2）`，以及 `提交文件夹：` 里 `fp16_check` 的 `q2_class_agree` 为 1.0 或极接近。
   - 最后出现 `v3.2 全部完成`。
5. **全量运行：** 改回 `SMOKE = False`，建议用 Save & Run All。
   - 日志开头应看到 `DeBERTa（deb，文本 text_bert）检查点：5/5 个已存在`、`DeBERTa（debtc，文本 text_bert_tc）检查点：0/5 个已存在`。
   - 用时：有 v3.1 检查点约 4 小时；没有约 5 小时，会连小写家族一起重训。
6. **取结果：**
   - 下载 `/kaggle/working/outputs_v32.zip` 发回，提交文件夹也在里面。
   - `outputs_v32_ckpt.zip` 里是新训的 `debtc` 5 个种子（约 150 MB），建议也下载保存。

## 看结果时重点看这几处（`REPORT_v32.md`）

- **第 1 节 目标达成：**
  - valid（题面口径）、VC（留出）、test 三套；带“（部署）”的是实际提交的模型，附按视频的 95% 区间。
  - 宏 F1 是目标口径，加权 F1 同报。
- **第 2 节 部署选择：**
  - 各候选的 VS 折外 J 与参数体积；
  - 两个家族的量化保真表；
  - 类别概率来源的选择表。
- **第 5 节 种子配对差：** `debtc - deb` 是大小写恢复的直接 A/B，5 个种子一一配对。
- **第 6 节 视频配对重抽样：** `mix_ens` 对单模型、各集成对各自的 s17。
- **第 14 节 提交文件夹：**
  - 问题二文件名形如 `q2_mix_ens_int4.pt`；
  - `total_mb_decimal` 是按 10^6 字节算的总量。

## 附件总量（50 MB 以内）

| 部署 | 问题二参数 | 提交文件夹合计（10^6 字节） | 加问题一约 16 MB |
|---|---|---|---|
| `mix_ens` | 约 27.5 MiB | 约 30.5 MB | 约 47–48 MB（再加代码约 0.5 MB） |
| 5 成员集成 | 约 23 MiB | — | 约 43 MB |

余量不大。如果问题一的文件大于约 17 MB，把配置里的 `Q2_MAX_MB` 改成 24，就只会在 5 成员集成和单模型里选。

## 如果出问题

各步骤失败时会自动降级，原因记在报告第 16 节：

| 失败情况 | 自动处理 |
|---|---|
| `debtc` 训练失败 | 小写家族照常评估与部署 |
| 某个家族量化后一致率不达标 | 改 8 bit；8 bit 也不达标就保留 fp32 成员，这个家族的集成放不进附件，自动不参与部署 |
| 问题三融合头训练失败 | 改用问题二模型解释 |

需要手动调整的情况：

- **显存不足：** `DEB_BS` 改为 8，或 `RDROP_ALPHA` 设为 0。
- **时间紧：** `EXT_SPLITS=["valid"]`，省约 12 分钟。
