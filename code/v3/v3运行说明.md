# v3 · Kaggle 运行说明（DeBERTa-v3-large + 集成，外加 v2 结论补验）

## 这一版做两件事

### 1. 先把 v2 的结论核实清楚（只推理，不重训被审查的模型）

- **90% 文本缺失档逐样本分析：**
  - 记录每条样本删除后实际剩下的子词数和整词数；
  - 按“剩余整词数 0 / 1 / 2 / 3–4 / ≥5”分层，看 mg、mg2 相对 base 的收益。

  这一步用来检验“补偿需要残余语义作支点”这个假设。
- **补上 joint 对照**（常规缺失增广训练）：
  - 如果 joint 在 90% 档也有 +6 个点，收益就应归因于“用缺失样本训练”，而不是 MG 的门控结构；
  - joint 在 v1 只有 3 个种子，这次补训 s71、s97（约 15 分钟）。不想补训可设 `JOINT_FILL_SEEDS=False`。
- **原生缺失子集：** 报告门触发率、类别改变数、MAE/Acc 变化；无原生缺失子集仍核对逐位一致。
- **逐种子、逐面板指标表：** 标明哪些是 argmax 未校准、哪些经过规则层，并注明 mg2 在 v2 中选中的 epoch。
- **区间分两种写清楚：**
  - 种子 t 区间：5 个种子配对差，只反映训练随机性；
  - 视频区间：按源视频重抽样，反映样本不确定性。

### 2. 冲性能（目标 F1 ≥ 0.70、Acc-3 ≥ 0.70、MAE < 0.60）

| 改动 | 做法 | 为什么 |
|---|---|---|
| 文本主干 | DeBERTa-v3-large（通用预训练，没有用任何情感数据微调，符合题面“不得引入其他情感数据”），全部线性层加 LoRA（r=16，每层 6 处，共 144 处） | 瓶颈在文本；更强的编码器是最直接的提升 |
| 输入映射 | BERT 子词位置 → 原文字符区间 → DeBERTa 词元。某个 BERT 位置被删，与它字符重叠的 DeBERTa 词元全部视为缺失 | 缺失面板、附件3、问题三的逐位置遮挡都沿用同一套 50 个位置，与 v1/v2 完全可比；保守规则保证不泄漏被删内容 |
| 强度头 | 19 点有序分布（网格 −3..3，步长 1/3，与标注格点一致），点估计取分布中位数 | 中位数是绝对误差的最优点估计，直接针对 MAE |
| 损失 | 加权交叉熵 + 有序分布交叉熵 + L1 + 软宏 F1 + R-Drop；30% 样本做连续段缺失增广 | 软宏 F1 直接优化宏 F1（中性类是瓶颈）；R-Drop 增加稳定性 |
| 集成 | 5 个种子取平均：`deb_ens`；BERT 与 DeBERTa 各占一半：`mix_ens` | 集成通常能稳定地多拿 1–2 个点 |

### 事先锁定的协议（训练前写入 `PROTOCOL_v3.json`）

- **验证集按源视频对半分：**
  - 选择区 VS：选 DeBERTa 的 epoch、拟合规则层、选部署配置；
  - 校准区 VC：只做共形校准，不参与任何选择。
- **共形预测：**
  - 每个样本每个缺失桶至多一行，避免同一样本的多个缺失版本被当成独立校准点；
  - 测试覆盖率给按视频重抽样的区间，同时报告单元素集合比例。
- **决策层：** 沿用 v2 的事先规则（VS 内 5 折折外增益 ≥0.3 个点才启用）。不会因为 v2 的测试结果把它去掉。
- **测试集：** 只在所有选择完成后评估一次。之后若因测试结果改动任何设置，一律标为“探索性”。

### 问题三与附件4 的修正

- **部署模型没有门控时**（DeBERTa 或其集成），删除输入不会触发补偿机制，“内容效应”和“系统总效应”是同一个量。
- **部署模型有门控时**，两者分开报告。
- **删除检验改用绝对差值：** Δ = 删高分位置的概率下降 − 删随机位置的概率下降，附 bootstrap 区间。声学/视觉另报 |Δp| 的中位数、90 分位，以及超过 0.01/0.05 的样本占比。
- **证据按整词汇总：** `don ' t` 合并为 `don't`，纯标点不再作为证据片段。
- **附件4 的时间戳：**
  - 增加对齐置信度：路径平均字符概率，并与打乱词序后的得分比较；
  - 增加人工核验表：Q3-15 标为 rejected，不给秒级和帧级定位；Q3-02 标为 revised。
  - 输出同时保留“工具时间戳”和“最终时间戳”两列，并给出状态：rejected / revised / revised_pending / flagged_unverified / tool_unverified。
- **附件3 的样本号：** `3_01_test` 这类后缀自动去掉。

## 怎么跑

1. **导入与设置**：Kaggle → Import Notebook，选 `gmcm_v3_kaggle.ipynb`；GPU 选 T4，**打开 Internet**。首次运行会下载 DeBERTa-v3-large，约 0.9 GB。
2. **Add Input：**
   - 比赛数据集；
   - 之前上传的检查点数据集（`some-pt`：base / mg / joint 的 .pt 与 `train_config.json`）。

   如果还留着 v2 的 `mg2_s*.pt`，也放进去；没有的话 mg2 不参与，这不影响结论，因为 mg2 有 3 个种子本来就与 base 逐位相同。
3. **Q3-02 的修订量（可选）**：在配置单元 `ATT4_MANUAL` 里找到 sample="02" 那一行：
   - 填 `shift_s`：正数表示推后，负数表示提前；
   - 填 `evidence`：`"T"` / `"A"` / `"V"` / `"all"`。

   不填也能跑，状态会标为 `revised_pending`，只标注、不改时间。
4. **冒烟测试**：把 `SMOKE = True`，Run All，约 15–20 分钟，会用小样本重训所有模型。重点看日志里这几项：
   - `DeBERTa 词元映射：` 中的 `raw_aligned` 应占绝大多数，`bert_pos_without_token` 应接近 0；
   - `LoRA 模块 144 个`；
   - 最后出现 `v3 全部完成`。
5. **全量运行**：改回 `SMOKE = False`，预计 3–3.5 小时。
   - DeBERTa 5 个种子训练约 65 分钟，全部评估约 70 分钟，扩展扫描约 35 分钟。
   - 可以在交互会话里跑（保持页面打开），也可以用 Save & Run All。
6. **取结果**：下载 `/kaggle/working/outputs_v3.zip` 发回。
   - 另有 `outputs_v3_ckpt.zip`，里面是新训的 DeBERTa 与 joint 检查点，约 150 MB。建议也下载，以后上传到检查点数据集，就不用重训。

## 看结果时重点看这几处（`REPORT_v3.md`）

- **第 1 节：目标达成表**（测试集与 VC，均为加规则层之后）。部署模型另给按视频的 95% 区间。
  - VC 对 DeBERTa 是真正没参与任何选择的留出数据，可以当作第二个诚实估计。
- **第 5 节：90% 档分层补验。** 重点看 joint 与 mg 的收益是否相当，以及收益是否随剩余词数变化。
- **第 6 节：原生缺失子集。**
- **第 9 节：共形覆盖。** 重点看中、重度桶的覆盖区间是否包含 0.90，以及单元素集合比例。
- **第 10 节：问题三的删除检验**（绝对差值与区间）。
- **第 13 节：附件4 的时间戳状态。**

## 如果出问题

- **DeBERTa 某个种子训练失败**（比如显存不足、连续 25 步出现非有限损失）：只跳过这个种子，其余种子和已保存的检查点照常使用，报告第 16 节会记下原因。
  - 如果是非有限损失，把 `DEB_LR_LORA` 调到 1e-4 再跑；已训完的种子会自动读取，不会重训。
- **显存不足**：把 `DEB_BS` 改为 8，或把 `RDROP_ALPHA` 设为 0（关闭第二次前向）。
- **某一步出错**：会记在报告第 16 节，其余步骤照常完成。DeBERTa 整体失败时，BERT 部分和补验照样出结果。
