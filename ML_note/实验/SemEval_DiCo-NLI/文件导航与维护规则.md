# 文件导航与维护规则

## 阅读顺序与职责

| 层级 | 文件 | 维护内容 |
|---|---|---|
| 仓库首页 | [根README](../../../README.md) | 各项目进展、少量关键结果、下层入口；不放云端启动排期 |
| 跨项目总表 | [实验结果汇总](../../实验结果汇总.md) | 各项目正式结果条目；注明数据集、单折/OOF/dev、种子数；保留历史编号 |
| 项目总览 | [SemEval README](README.md) | 本项目全部阶段的结果、问题、下一步；当前表格必须完整更新 |
| 当前状态 | [实验状态与算力计划](实验状态与算力计划.md) | 完成清单、待办、触发条件、实际已知余额；唯一当前排期入口 |
| 本轮分析 | [英语五折联合验证结果](英语五折联合验证结果.md) | 详细比较、区间、逐类结果、错误得失、证据边界 |
| 当前计划 | [更大模型与数据扩充计划](更大模型与数据扩充计划.md) | 冻结的设计、判断规则、清单接口和分工；修改写进文末变更记录 |
| 已执行计划 | [SFT与蒸馏验证计划](SFT与蒸馏验证计划.md) | 冻结矩阵到实际完成输出的对应关系、故障与验收 |
| 自动登记 | [实验登记表](实验登记表.md)、metrics/registry.json | 从指纹、环境和预测生成，不手改；新运行加入code/registry.py |
| 原始证据 | [metrics/joint_validation](metrics/joint_validation/README.md)等 | 正式分数、概率、预测、训练历史与哈希；不把旧阶段包改造成完整包 |
| 实现 | code/、notebooks/ | 实际使用版本与历史入口分清；代码哈希绑定的源文件不因文档整理而改写 |
| 历史详录 | [早期实验详录](早期实验详录.md) | 第一至第四组完整表格、诊断、早期问题与来源；当时状态不作为当前待办 |
| 历史排期 | [历史联合验证排期](历史联合验证排期.md) | 冻结设计和预算快照；仅追溯，不重复执行 |

## 更新约定

1. 收到结果先复核，再更新原始证据、自动登记和详细分析。
2. 同一提交同步更新项目README、当前状态、上层结果汇总与根README中的实际表格，不只加“最新结果”提示。
3. 已完成项从当前待办移出；不再把开跑前预算写成当前余额。缺少账单则写未知。
4. 五折OOF、单折和dev分表；不同种子数和教师来源明确标记，不混为同一配置。
5. 原始输出与旧清单按原字节保留以便哈希复核；所在README解释其范围，并指向后续完整结果。
6. 旧计划独立归档，当前入口不保留失效启动指令；新增或迁移文件后检查相对链接。

此次规划没有移动code和metrics下的实验数据，也没有修改模型配置或分数。SST-2、IMDB等其他项目原结果保持不变。
