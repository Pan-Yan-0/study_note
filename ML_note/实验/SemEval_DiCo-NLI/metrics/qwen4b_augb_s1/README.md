# Qwen 4B 上的 +1 扩充 · 阶段 1（Q0 / Q-B1）

**为什么做**：mDeBERTa 上加 Haiku 生成的 +1 数据，sym WF1 涨了 2.9 个百分点（实验 B +1）。这一轮看同一批数据加到更强的 Qwen3-4B 上还有没有用。

**设置**：
- 两组只差训练数据：
  - Q0：原数据 fit；
  - Q-B1：fit 加上该折选用的 Haiku +1 生成行，清单 `b380b4a6…`，和 mDeBERTa 的 B1 是同一批。行数翻倍，所以每轮的更新次数也翻倍。
- 配方和 JOINT-QWEN 相同：Qwen3-4B-Instruct-2507 `cdbee75f…`，LoRA r16，lr 1e-4，3 轮，按内层验证原方向 WF1 选轮。
- 英语五折 × seed 42–44，各 15 项，共 30 项。
- 运行环境：阿里云 PAI-DSW A10，bf16，torch 2.6.0+cu124。
- 代码：`code/qwen4b_augb/` v1.1（代码身份 `adc19fa0…`），上游训练核心不变。
- 判定规则在运行前写进 `code/qwen4b_augb/README.md` 和冻结计划变更记录。

- **重抽样**：2,000 次，每次从 1,725 个家族里有放回地抽，两组和三个种子共用同一组抽样。区间只反映留出样本的抽样波动，不包含重新训练的随机性。`registry.py` 用独立实现算出同样的区间。
- **四类 F1 都没有升**：E / F / B / O 分别是 87.4 → 86.6、89.2 → 89.0、89.2 → 88.6、65.8 → 65.1。O 的漏判略多（151 / 146 / 170 → 162 / 157 / 180），误判略少（182 / 200 / 158 → 178 / 174 / 152）。这和 mDeBERTa 上 O 类明显改善不同。
- **选中轮和训练量**（两项分开的观察）：
  - Q-B1 的 15 项里有 6 项选在第 1 或第 2 轮，Q0 只有 1 项。
  - 每轮的更新次数，fold 0–2 是 137 → 274，fold 3–4 是 138 → 275。按"选中轮 × 每轮更新次数"算，Q-B1 选中的那份权重经历的更新次数，在 12 / 15 对里比 Q0 多，在 3 / 15 对里比 Q0 少。
- **工程核对**：
  - Claude 用 `code/claude_recheck_qwen4b_augb.py` 独立重建，30 项 0 问题。按 Codex 的建议补了三块检查，也都通过：
    - COMPATIBLE / SMOKE 回执：零样本核对 1,448 个输入、最大差 0；新旧入口 3 次更新逐一相同；探测训练了 16 个不重复 ID；SMOKE 从第 1 轮恢复并跳过写坏的检查点。
    - 逐任务：COMPLETE 的身份和封存文件；两组同种子同折的 val 有序相同，训练设置除留出折外都相同。
    - 用每轮 val_probs 重算内层验证 WF1，选中轮是最高分里最早的一轮。
  - 结果包 907 个文件的哈希都对得上。
  - 每组每个种子拼齐 3,042 行，留出和家族划分一致，训练和留出不共享家族。
  - Q-B1 的 fit 正好是 Q0 的 fit 加上本折选用的生成行，顺序也相同。
  - 从 `cache.jsonl` 重建的留出、dev 预测和 OOF，和队列保存的逐条相同；分数和保存的一致。
  - 43,608 条概率里，最大的一项都是答案字母，四个字母的概率和最小 0.998。
- **用时**：每项任务平均 17.9 分钟（Q0）和 33.9 分钟（Q-B1），阶段 1 约 13 个 A10 小时。
- **registry 登记**：Q4B-Q0 / Q4B-QB1；比较登记为 Q4B-CMP-QB1-Q0（单一计划改动）和 Q4B-CMP-Q0-JOINT（重复运行）。

## 问题

- **同一份数据，在 mDeBERTa 上有效，在 Qwen 4B 上看不出效果**。这是事后描述，不是检验结论，可能的原因有：
  - Qwen 4B 的起点已经高（Q0 85.0%，mDeBERTa B0 79.4%），生成数据带来的边际信息更少；
  - LoRA 的配方原本是按原数据定的；
  - 加数据后总训练量增加，选中的权重大多经历了更多次更新。

  这几条都是待验证的解释，没有单独检验。
- **重跑差和效应同量级**：同配方、不同入口的两次运行，Q0 比 JOINT-QWEN 高 0.65 个百分点（[+0.23, +1.06]），和这次 −0.53 的点估计差不多大。
- 只有英语。
