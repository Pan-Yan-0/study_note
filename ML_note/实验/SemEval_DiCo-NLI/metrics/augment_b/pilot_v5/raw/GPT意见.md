# 给 Claude：v5 修法与解释边界

## 两个问题

1. 同意先在生成提示词中匹配本批参考短语的长度与冠词比例。本轮沿用冻结 v5，不追加确定性的长度过滤。只删长样本不能保证消除标签与长度差的相关，还可能造成按标签不均匀的保留率；提示词约束是否有效仍需正式试点检验。调试的 5 词门槛只用于进入试点，不替代试点的整体分布与盲审检查。
2. 同意冠词比例只描述，不在看到 v5 结果后临时新增门槛；按类报告比只报总体比例更有解释力。它只能描述风格，不证明是否存在捷径。

## 建议收紧表述，不改本轮执行

- “不是样本量造成的”宜改成“所做的 100 次同规模抽样未能解释如此大的差距”。这不是排除全部抽样/分布因素的证明。
- “差距全部来自长度特征”宜改成“在当前线性探针与特征分组下，长度组提供主要可见信号”。全特征与长度组的分数不相等，分组实验也不是严格的因果归因或加性贡献分解。
- ref_stats 数值计算确实不读取标签，但生成 prompt 仍包含带标签参考对，并要求对齐“同标签参考对”的长度差。因此“新增数值摘要不看标签”准确，“整个 v5 修改不使用标签”则不准确。这里使用的是允许的本批 fit 标签，不等于引入额外留出标签。
- 一些批次可能没有某类参考对；“同标签参考对的长度差”在该类上缺乏直接参照。按冻结提示词执行即可，此轮不补例子或反馈。
- 已披露的全数据驱动流程选择应继续保留。即便后续通过检查，也不能据此宣称整个开发流程从未接触外层数据分布。

## 工程说明

包中 diagnose_pilot.py 导入 label_conventions.number_pair，但 ZIP 未包含 label_conventions.py。Claude 可在已包含该模块的原仓库环境运行；这个 ZIP 单独运行该诊断并不自含。9 项 CPU 测试通过不代表这一新诊断入口也已测试。本轮不修改冻结代码、不运行真实数据的 build/diagnose，不影响生成交接。

本意见不包含生成样本的逐条语义裁决，避免影响 P1 独立盲审。
