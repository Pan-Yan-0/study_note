# 实验 B Commit 2：+2 / +4 规模和类别构成的生成数据

mDeBERTa-v3-base CE（第五组 C0 配方），英语按家族五折 × 种子 42–44，Kaggle T4 x2、fp16，7 组共 105 项。训练代码和 Commit 1 相同（`train_augb_v3.py`，`c8ff912c…`），生成数据来自 Claude Haiku 5.5 的规模轮（清单 `24704e11…`，复审 P1C-R 通过，见 [规模轮数据](../haiku_scale/README.md)）。对照组（B0、step+2、step+4、Dup×5）在 [Commit 1](../train_c1/README.md)，用同一份代码和环境（torch 2.11.0+cu128、transformers 4.57.6、模型 revision `a0484667…`）。

| 组 | 训练数据 | 每折行数 | 对照 |
|---|---|---|---|
| B2-Haiku | fit + 生成数据第 1、2 层（+2） | 3·fit | step+2（fit 重复三遍，同行数同步数） |
| B4-Haiku | fit + 生成数据第 1、2、4 层（+4） | 5·fit | step+4（fit 重复五遍） |
| G-U4 / BAL / E1 / D1 / O1 | fit + 按 `mixquota-v1` 的构成取生成数据 | 2·fit | 同构成的 Dup_c（新增部分是 fit 的重复） |

- 规模是嵌套的：第 1 层和 +1 的选用（B1-Haiku）逐条相同，+1 ⊂ +2 ⊂ +4。
- G_c 和 Dup_c 每折每类新增的行数逐类相同，计划步数也相同，只差新增的那份是生成数据还是原数据的重复。
- G_R（按原比例的生成数据）就是 +1 的 B1-Haiku，Dup_R 是 +1 的 step+1，两者都来自 v2 代码（GPT 的 `train_augb.py`）。v3 和 v2 在 B0 上逐条相同，但生成数据的取用路径没有逐条对过，所以带 G_R / Dup_R 的比较要注明跨代码。

## 结果

Claude 用 `code/claude_recheck_augb_c2.py` 从每个任务的四类概率重建，105 项核对 0 个问题。核对内容：哈希、选轮、步数、task.json 和 Commit 1 的 B0 只差组相关字段；各组行数等于 fit 加该折应取的生成行，生成行在本折可用、上下文父样本都在本折 fit 里；G_c 新增部分的类别构成等于 Dup_c；B2 / B4 / G_c 的计划步数分别等于 step+2 / step+4 / Dup_c。训练日志里没有报错。

- **规模**：+2 和 +4 两条判断都通过，扩充有效。曲线在 +2 饱和：+1 82.27%、+2 83.21%、+4 83.14%，+4 对 +2 −0.07 [−0.85, +0.68]。B4 种子之间波动较大（对 step+4 是 +1.5 到 +3.5）。
- **生成数据和原数据重复**：同行数、同步数下，生成数据在每个规模、每个构成下都显著好于原数据重复（+1.2 到 +3.3 个百分点）。原数据重复在 +1 之后就饱和了（step+1 / +2 / +4 为 80.59% / 80.71% / 80.55%），生成数据饱和得晚一档。
- **O 类**：生成数据提高了 O 的 F1（58.6% → 63–64%），也提高了 O 的排序：AP 从 56.31% 升到 59–61%（B4 61.42%，三个种子都高于 B0）。这和 W4 不同，W4 的 O F1 升了但 AP 降了约 2.5 个百分点（Commit 1）。O 的预测数不比 B0 多（三种子合计 B0 1,625 条、B2 1,530 条、B4 1,466 条），所以 O 的提升不是靠把更多样本判成 O。
- **类别构成**：5 个构成里，没有一个对按原比例的生成数据（G_R）显著更好，按规则没有构成"值得生成"；构成 v2 第 4 节事先定的 +2 后续（c* 的 G 和 Dup 各跑一组）因此不触发。U4 的 Δ_c 区间不含 0，但 G-U4 − G_R 没通过；按事先的写法，只说"U4 下生成相对重复的优势比 R 下大"，它主要来自 Dup-U4 本身最差（对 Dup_R −1.06，Commit 1），不能推断四类均等的构成本身更好。BAL 和 O1 的 SoftCons / HardCons 比其他构成低约 2 个百分点，只报告。

## 问题

- **区间不包含重新训练的随机性**：重抽样只抽家族。规模比较三个种子同号，构成比较里 Δ_c 的种子 43 常常和另外两个反号，种子间波动和效应同量级。
- **G_R、Dup_R 跨代码**：+1 的 B1-Haiku 和 step+1 是 v2 代码。v3 和 v2 在 B0 上逐条相同，生成数据和重复的取用路径没有逐条对过，G_c − G_R、Δ_c 和 B2 − B1 只按描述看待。
- **多重比较**：规模的 4 条判断都远离 0；构成的 15 条比较没有校正，G_c − Dup_c 里最弱的 E1 下限只有 +0.26。
- **生成器 reasoning effort**：r4 的 b045–b136 是 `high`，其余 `medium`（规模轮 README 第 14 节，Pan-Yan-0 定保留）。这部分只在 +4 的第 4 层里（五折合计 21,936 行中 5,619 行，25.6%），+2 和 G 组都没有取到；没有单独拆开比较。
- **fp16 跳步**：每组 15 项合计跳过 49–66 次更新，只报告。选中轮平均：B2 第 9.4 轮、B4 第 8.3 轮、G 组第 7.0–8.0 轮。
- **规模曲线的步数不同**：B1 / B2 / B4 的每轮步数随行数增长，曲线比较的是"数据和步数一起增加"，和各自的 step+k 对照比才控制了步数。
