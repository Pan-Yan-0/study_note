# 实验 B Commit 6：DirEnt（四分类拆成两个方向的蕴含）对 NLIinit

**为什么做**：错误集中在 O 的边界上，而四个标签本身由两个方向是否蕴含组成。研究对齐 v2 的方向一提出：只学一个打分 s(x, y) = "x 蕴含 y"，再把两个方向组合成四类。这样换序一致性由结构保证，O 也不再是单独一类，而是"两个方向都不蕴含"。

同比赛已有公开先例（Le Duc Minh 的 entail2：同型号 NLI 检查点、双向训练后按同一公式合成四类）。这次只回答一个问题：在我们的设置下，单方向监督的分解相对 NLIinit 有没有收益。

**设置**：
- 两臂都和 Commit 4 的 NLIinit 用同样的编码器初值（`MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7`，revision `b5113eb3…`）、同样的行、顺序、计划更新次数和 B0 数据，只改头和损失：
  - **DEC**：新建 1 维打分头。初值来自独立生成器（init_seed + 30000），N(0, 0.02²)，偏置 0。
  - **DEC-H**：用 NLI 检查点自带的三类头，打分 s = z_ent − logsumexp(z_neu, z_con)。标签顺序从 `id2label` 读取：entailment / neutral / contradiction。
- **组合**：a = σ(s_ab)，b = σ(s_ba)。P(E) = ab，P(F) = a(1−b)，P(B) = (1−a)b，P(O) = (1−a)(1−b)，用 logsigmoid 计算。判定时 s > 0 才算蕴含，s 恰好为 0 算不蕴含。
- **损失**：只对本行的方向算 BCE，E / F 的目标是 1，B / O 是 0；在 fp32、autocast 外计算。单条 O 不补反向监督（Codex 的口径）。
- **选轮**：用各自原生四类的内层验证 WF1（DEC 用两个顺序合成的四类预测），同分取早。
- **对照复用**：NLIinit 的 SMOKE 和 Commit 4 归档逐格相同，15 个 Commit 4 任务的身份核对也通过，所以复用 Commit 4 的 NLIinit，正式只跑 DEC 和 DEC-H 各 15 项，共 30 项。
- **环境**：英语五折 × seed 42–44；Kaggle T4 x2、fp16，torch 2.11.0+cu128，transformers 4.57.6。
- **代码**：`train_augb_v7.py` v7.2（`80396fd9…`），由 `make_v7.py` 从 v6.1 精确替换生成，其他组的训练路径不变。Codex 验收了 v7 和 v7.1；v7.2 只改 DEC 组的 SMOKE 门槛。
- 判定规则在运行前写进冻结计划变更记录。

## 问题

- **E 和 O 变成了两个独立判定的"与"**：E 要两个方向都过 0，O 要两个方向都不过 0，只要一个方向判错，就会落到 F / B。四分类的 softmax 可以直接学"两个方向一起看"的特征，分解后只能各判各的。上表里，E → F / B 和 O → F / B 多出来的约 190 行，是分数下降的主要来源。这个解释和数据相符，但没有单独检验。
- **单条 O 的反方向没有监督**：训练时单条 O 只出现 (text1, text2) 一个方向，s_ba 从没被要求为负。O 判成 B 比判成 F 增加得更多（+56 对 +33），和这个解释相符，但 F 也在升，所以它最多解释一部分。E 的损失不受这一点影响。
  - 补监督的做法：把单条 O 的反方向也当作"不蕴含"。这用的是标签本身的含义（O 表示两个方向都不蕴含），只在训练时用，不是在测试时靠"单条即 O"的结构判定。但它算不算 Pan-Yan-0 说的"利用配对结构"，需要他定。
- **和先例不完全可比**：entail2 用双向训练、保留三类头。这次只测了单方向监督这一种分解，结论限于这个设置。
- **SoftCons 不能单独当好处报**：分解后 SoftCons 由结构保证，必须和 WF1、HardCons 一起看。
- 只有英语、只在 B0 数据上。

## 下一步计划

1. **按事先规则，DEC 和 DEC-H 都不进 +2，方向一到此结束。** 不在看过结果后继续调 DirEnt 的变体，比如补 O 的反向监督、在内层验证上调阈值。如果 Pan-Yan-0 想试补反向监督，先确认它不算利用配对结构，再事先登记成单变量的一臂（DEC + 反向 O 对 DEC）。预期它最多挽回 O 的一部分损失，补不回 E 的损失。
2. **英语工作配方不变**：B2；只用原数据时是 NLIinit。
3. **按 Codex 定的顺序，语义检索预检排在 DirEnt 之后，现在可以做**：冻结 NLI 编码器、mean pooling、k = 4，门槛比字面检索高 5 个百分点。它要用 torch，需要在 Kaggle 上跑一个小 notebook。
4. 研究对齐 v3 / v3.1 / v3.2（A 口径对齐重标、B 反事实最小对、C PiSSA、B2-LS）在等 Codex 审阅。
