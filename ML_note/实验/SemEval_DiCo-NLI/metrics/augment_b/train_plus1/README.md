# 实验 B +1：Haiku 生成数据的训练对照

mDeBERTa-v3-base CE（第五组 C0 配方：最多 12 轮、lr 2e-5、batch 32、max_len 96，按内层验证原方向 WF1 选轮），英语五折 × 种子 42–44，三组共 45 项，Kaggle T4 fp16：

- **B0**：每折只用原 fit。
- **B1-Haiku**：原 fit 加上该折选用的 Haiku 生成行（+1，行数和四类配额都等于 fit），数据来源和放行见 [haiku_full](../haiku_full/README.md)、[e_recheck](../e_recheck/README.md)。
- **step+1**：原 fit 每行重复两次，行数、每轮步数、学习率日程都和 B1-Haiku 相同。

判断规则在冻结计划第 1 节、看结果之前写定：同种子 sym WF1 差的均值大于 0、按 1,725 个家族配对重抽样的区间下限大于 0，才算提升；B1-Haiku 对 B0 和对 step+1 **都**满足，才算扩充有效。

## 结果

3,042 行折外预测，三个种子的均值（%）：

| 组 | plain WF1 | sym WF1 | sym SoftCons | sym HardCons | sym F1：E / F / B / O |
|---|---:|---:|---:|---:|---|
| B0 | 79.10 | 79.37 | 90.54 | 82.19 | 80.2 / 84.8 / 84.4 / 58.7 |
| step+1 | 80.26 | 80.59 | 89.86 | 82.84 | 81.3 / 85.9 / 85.9 / 59.9 |
| **B1-Haiku** | **81.84** | **82.27** | **92.54** | **85.23** | 82.8 / 87.2 / 86.8 / 64.0 |

配对比较（sym WF1，百分点；2,000 次家族重抽样，种子 20261021，和 `registry.py` 同一约定）：

| 比较 | 种子 42 / 43 / 44 | 平均 [95% 区间] | 按规则 |
|---|---|---|---|
| B1-Haiku − B0 | +3.19 / +2.65 / +2.89 | **+2.91 [+1.89, +3.89]** | 提升 |
| B1-Haiku − step+1 | +1.05 / +2.76 / +1.23 | **+1.68 [+0.73, +2.58]** | 提升 |
| step+1 − B0（描述） | +2.14 / −0.12 / +1.66 | +1.23 [+0.43, +2.04] | — |

- **两条比较都通过，按事先的规则，+1 扩充有效**，可以进入 +2 / +4。三个种子在两条比较里都是正的。原方向（plain）上结论相同：+2.74 [+1.80, +3.66]、+1.58 [+0.71, +2.42]。
- 只把原数据重复一遍（step+1）也有提升，所以 B1-Haiku 对 B0 的 2.9 个百分点里，约 1.2 来自更多的更新；扣掉这部分，生成数据本身的作用约 1.7 个百分点。
- 提升最大的是 NEGATIVE_OTHER：sym F1 比 B0 高 5.3 个百分点，比 step+1 高 4.1；E 高 2.6 / 1.5，F、B 各高约 2.4 / 1.1。之前所有方法共同的短板是 O 类（约 58–64%），这是第一次在五折上明显动到它。
- 一致性也升了：sym SoftCons 92.54%、HardCons 85.23%，step+1 的 SoftCons 反而比 B0 低。
- 次指标（只报告，不参与判断）：
  - 三种子概率平均后 sym WF1：B0 80.99、step+1 81.76、B1-Haiku 83.66。
  - 结构规则（单条判 O，成对的只在 E / F / B 里选）下：90.16 / 91.10 / 91.77；有了这条规则，差距缩小到 1.6 个百分点，提示生成数据的作用有一大块落在 O 和成对样本的区分上。
- 逐条预测：B1-Haiku 和 B0 的 sym 预测 87–89% 相同，和 step+1 88–89% 相同。
- 参照（不是本次的判断依据）：Qwen3-4B SFT 五折 84.37%、Qwen3-8B 84.87%，B1-Haiku 的编码器仍低约 2 个百分点。
- 训练记录：45 项都跑满 12 轮；B0 选中轮分散在第 5–12 轮，B1-Haiku 第 3–12 轮。每个任务 fp16 跳步 2–5 次，实际更新 + 跳步 = 计划步数；B1-Haiku 和 step+1 的实际更新次数同折同种子最多差 2 次（只报告）。合计训练约 4.4 小时（B0 55 分钟，另两组各约 103 分钟）。

## Claude 的独立复核

`code/claude_recheck_augb.py` 不用训练脚本的汇总代码，只读每个任务保存的文件，结果写在 `claude_recheck.json`，**没有发现问题**：

- 45 个任务都在；`done.json` 记录的预测哈希和文件一致；三组的代码（`385ed94b…`）、模型版本（`a0484667…`）、配置、数据哈希和稳定环境（T4、fp16）都相同，只有组名、训练行数和计划步数不同。
- 每折留出和仓库的家族五折（`metrics/diagnostics/families.json`）逐行一致，fit / 内层验证和实验 A 的 fold 0 相同；没有家族泄漏；五折留出拼起来正好 3,042 行。
- 每个任务选中轮是内层验证最高、同分取早的那一轮；用保存的内层验证概率重算的 WF1 等于记录的选轮分数。
- 测试概率：每行重新取 argmax 和保存的标签相同；反方向概率等于反方向那一行的原方向概率；对称化概率重算一致。
- 官方评分模块重算的 18 套分数和训练脚本的 `summary.json` 逐位相同；两条比较的均值也相同。区间端点差不到 0.05 个百分点，是两边重抽样的随机种子不同（20261021 对 20261106）。
- `registry.py` 登记为 AUGB-B0 / AUGB-B1-HAIKU / AUGB-STEP1，比较 AUGB-CMP-B1-B0、AUGB-CMP-B1-STEP1，自动归类为"单一计划改动、执行环境一致"，数字和上表相同。

## 问题

- **区间不包含重新训练的随机性**。同配方换一次环境，差别就可能接近 1 个百分点：B0 和第五组 CE（A10 bf16，同划分同种子）相比低 0.9 个百分点 [−1.7, −0.0]（AUGB-CMP-B0-JOINTCE；卡、精度、库版本和随机数流都不同，只作参照）。B1-Haiku 对 step+1 的 +1.68 比这个大，且三个种子都正，但两者量级接近，结论仍是探索性的。
- **审核不是独立双盲，E 的放行门槛是看完第一次 P1 后改的**（改为"和原数据比"，新门槛在新抽的样本上、看结果之前写定）。Claude 是派发方，也参与了 E 的复审。
- **生成器的初始上下文无法证明**：Haiku 子 agent 启动时可能读到仓库的 CLAUDE.md / AGENTS.md（里面有从训练标签归纳的计数规则描述）。提示词禁止只差数量的对，`number_pair` 统计为 0。
- **fold 0 和五折数据都参与过研究决策**（选配方、选生成方式），结论是探索性的，不是隐藏测试成绩。
- B0 用 `seed×1000+fold` 初始化、每轮独立的打乱生成器，和第五组 C0 的随机数流不同，B0 不是 C0 数字的复现；三组之间是一致的。
- 训练环境的 transformers 是 4.57.6（之前多语言 C0 那次是 5.19），只记录。

## 下一步计划

1. **+2 / +4**：按冻结计划第 3 节，两条比较都通过才做，现在条件满足。要先定三件事，由 Pan-Yan-0 决定后写进变更记录：
   - **父家族使用上限**：+1 已经用掉 1,699 个家族、其中 126 个用了 2 次（上限 2）。+4 要约 4 倍于 fit 的生成行，按现在的上限凑不够，要放宽上限（例如每个家族最多 4 或 8 次），并继续报告集中度。
   - **嵌套**：+1 ⊂ +2 ⊂ +4，+2 在现有 +1 上再补一倍，+4 再补两倍；提示词和流程沿用 v6 冻结版，不改。
   - **审核**：新增数据是否再抽样审核，用 `P1C-R` 同样的口径。
2. **训练**：B2、step+2、B4、step+4 共 60 项，按本次速度约 13–14 小时，超过 Kaggle 单次 12 小时，分两次 Commit（先 +2，再 +4）。
3. **类别加权 W2 / W4**（之前和 GPT 定的设计）：本次的 B0 就是 T4 fp16 上的 W1，可以复用；但训练脚本要先加 λ=1 时和原 CE 分支逐位相同的检查。是否和 +2 / +4 同时排，由 Pan-Yan-0 定。
