# 实验 B Commit 5："B2 + NLIinit" 对 B2

**为什么做**：Commit 4 里，NLI 检查点初始化只用原数据就比 B0 高 3.22 个百分点。按当时事先写好的规则，过线的改动要再和 +2 的生成数据（B2）叠加，看两个改动能不能一起用。

**设置**：
- 两组只差初值：
  - B2-Haiku：普通 mDeBERTa 初始化，数据是原始 fit 加 +2 规模的 Haiku 生成行，和 Commit 2 的 B2 相同；
  - B2-NLIinit：同样的行、同样的顺序、同样的计划更新次数，编码器和池化层换成 `MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7`（revision `b5113eb3…`），和 Commit 4 的 NLIinit 完全相同。
- **B2 在同一队列里重跑**：Commit 2 没有留 B2 的 SMOKE，没法先核对复用。
- 英语五折 × seed 42–44，各 15 项，共 30 项；Kaggle T4 x2、fp16，torch 2.11.0+cu128，transformers 4.57.6。
- 代码 `train_augb_v6.py` v6.1（`50c80062…`），由 `make_v6.py` 从 v5.2 精确替换生成，训练路径不变。Codex 审过 v6 后补了两处 SMOKE 门槛。
- 判定规则在运行前写进冻结计划变更记录。

## 结果

**按事先规则，叠加没有通过：在 +2 数据上没有检测到 NLI 初始化的额外增益。** 三个种子的差都是正的，但 95% 区间含 0。

| 组 | sym WF1 | sym SoftCons | sym HardCons | plain WF1 | O 的 F1 | O 的 AP（三个种子） |
|---|---|---|---|---|---|---|
| B2-Haiku（重跑） | 83.21 | 92.38 | 86.30 | 82.74 | 63.69 | 59.1 / 59.9 / 60.3 |
| B2-NLIinit | 83.59 | 93.40 | 87.08 | 83.25 | 64.76 | 60.9 / 59.5 / 62.5 |

| 比较（sym WF1） | 逐种子差（42 / 43 / 44） | 均值 | 95% 区间 | 判定 |
|---|---|---|---|---|
| **B2-NLIinit − B2-Haiku** | **+0.52 / +0.23 / +0.40** | **+0.38** | **[−0.61, +1.36]** | **不算提升** |
| plain 方向（描述） | +0.70 / +0.36 / +0.45 | +0.50 | [−0.43, +1.42] | — |
| 重跑的 B2 − Commit 2 的 B2（复现性） | 0 / 0 / 0 | 0 | [0, 0] | — |
| B2-NLIinit − Commit 4 NLIinit（描述） | +1.00 / +1.28 / +0.73 | +1.00 | [+0.12, +1.90] | — |
| B2-NLIinit − B0（描述） | +4.51 / +4.00 / +4.17 | +4.22 | [+2.93, +5.53] | — |

- **重抽样**：20,000 次，每次从 1,725 个家族有放回地抽，同一组抽样在各组和三个种子之间共用。区间只反映留出样本的抽样波动，不包含重新训练的随机性。
- **B2 的重跑完全复现了 Commit 2**：15 项的留出预测、内层验证预测和额外 logits 都和 Commit 2 逐字节相同。所以两组之间的差全部来自初值。
- **O 类有小的变化**：
  - 预测为 O 的行数从 531 / 508 / 491 降到 484 / 491 / 463，误判（金标不是 O、判成 O）从 210 / 190 / 186 降到 172 / 176 / 160；
  - 漏判从 157 / 160 / 173 变成 166 / 163 / 175，基本持平；
  - O 的 F1 从 63.7 升到 64.8。
  
  这些和 Commit 4 的方向相同，但幅度小得多。其余三类的 F1 变化都在 0.6 个百分点以内。
- **更新次数**：两组的计划更新次数相同。实际更新次数（扣掉 fp16 跳步）逐项的差在 −2 到 +2 之间，每项跳步 3–5 次。
- **工程核对**：
  - Claude 用 `code/claude_recheck_augb_c5.py` 从概率独立重建，30 项 0 问题；脚本在运行前写定，`--selftest-c4` 和 Commit 4 的归档逐位一致。
  - B2-NLIinit 每项都载入了 200 个张量、278,809,344 个参数，只保留原来的分类头。
  - 每项任务平均约 10.3 分钟。
- **registry 登记**：AUGB-C5-B2 / AUGB-B2-NLIINIT。

## 问题

- **两个改动的增益大部分重合**：
  - 单独用，NLI 初始化 +3.22，+2 数据 +3.84（都是对 B0）；
  - 叠在一起是 +4.22，只比 B2 多 0.38，而且区间含 0。
  
  一种可能的解释是：两者都在改善同一类错误（O 的误判），先用了一种，另一种能补的就不多了。这是事后描述，没有检验。
- **区间宽度**：区间宽约 2 个百分点，比这次的点估计大得多。三个种子都是正的，但按事先规则只能说"没有检测到额外增益"，不能说"没有增益"。
- **外部数据**：NLI 检查点用了外部 NLI 数据，如果采用要在系统论文里披露（见 Commit 4 的 README）。
- 只有英语。

## 下一步计划

1. **按规则，英语的工作配方仍是 B2**：B2-NLIinit 没有证明比 B2 好。要不要因为 O 误判更少、三个种子方向一致而另作选择，由 Pan-Yan-0 定，不能写成检验结论。
2. **只用原数据时，NLI 初始化仍然是有效的改动**（Commit 4 的结论不变）。如果其他赛道不做数据扩充，可以考虑单独用它；西语和跨语言赛道要不要试，由 Pan-Yan-0 和导师定（这个检查点不含巴斯克语）。
3. 实验 B 已登记的 mDeBERTa 训练到此全部完成。
