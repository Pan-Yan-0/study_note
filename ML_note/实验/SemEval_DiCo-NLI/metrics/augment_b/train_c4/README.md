# 实验 B Commit 4：B0 数据上的三臂（O 潜在分量头、NLI 检查点初始化、双向辅助 BCE）

**为什么做**：Qwen 4B 多数票的错误大多出在 Other 和 E/F/B 之间；数据扩充到 +2 后不再上涨，Focal 和 Dice 也没有用。所以这一轮改模型本身，在只用原始英语 fit 数据的条件下，比较三种改法各自有没有用。

**设置**：
- 三个臂各改一处，其余和 B0 完全相同：数据、种子、更新次数、选轮规则（内层验证原方向 WF1）都一样，随机数流也和 B0 相同。
- mDeBERTa-v3-base，英语按家族五折 × 种子 42–44，Kaggle T4 x2、fp16，三个臂共 45 项。
- 代码是 `train_augb_v5.py` v5.2（`7f3e01b3…`），由 `make_v5.py` 从 v4.1 精确替换生成，B0 的路径不变。
- 设计由 Codex 在研究对齐 v1 里提出，实现细节双方确认后写入冻结计划变更记录（11-12）；Claude 实现，Codex 审查了三版代码。

| 组 | 唯一改动 |
|---|---|
| B0（复用 Commit 1） | CE，普通 mDeBERTa 初始化 |
| OLat4 | O 一个 logit 改为 4 个分量，z_O = logsumexp(z_O1..4) − log 4；4 个分量由 B0 的 O 行加标准差 0.002、沿分量中心化的扰动初始化 |
| NLIinit | 编码器和池化层的初值换成 `MoritzLaurer/mDeBERTa-v3-base-xnli-multilingual-nli-2mil7`（revision `b5113eb3…`，MIT）；4 类头、tokenizer、前向配置沿用 B0 |
| BiBCE | CE + 0.25 · ½[BCE(m_AB, t_AB) + BCE(m_BA, t_BA)]，m 是从同一组四类 logits 算出的"A 推出 B""B 推出 A"的边际 logit |

## 结果

**按事先定的规则，NLI 检查点初始化有效：sym WF1 + 3.22 个百分点，Bonferroni 98.33% 区间 [+1.56, +4.86]，三个种子都升。O 潜在分量头和双向辅助 BCE 都不算提升。**

| 组 | sym WF1 | sym SoftCons | sym HardCons | plain WF1 | O 的 F1 | O 的 AP（三个种子） |
|---|---|---|---|---|---|---|
| B0 | 79.37 | 90.54 | 82.19 | 79.10 | 58.65 | 56.3 / 54.9 / 57.8 |
| OLat4 | 79.15 | 90.22 | 81.93 | 78.87 | 58.11 | 56.3 / 56.3 / 53.2 |
| **NLIinit** | **82.59** | **93.42** | **86.09** | **82.17** | **64.25** | **59.5 / 59.5 / 59.4** |
| BiBCE | 79.63 | 91.00 | 82.71 | 79.15 | 59.01 | 55.6 / 56.2 / 57.8 |

| 比较（sym WF1） | 逐种子差（42 / 43 / 44） | 均值 | Bonferroni 98.33% | 判定 |
|---|---|---|---|---|
| OLat4 − B0 | +0.46 / −1.19 / +0.08 | −0.22 | [−1.06, +0.63] | 不算提升 |
| **NLIinit − B0** | **+3.51 / +2.72 / +3.44** | **+3.22** | **[+1.56, +4.86]** | **提升** |
| BiBCE − B0 | +1.04 / −0.71 / +0.48 | +0.27 | [−0.63, +1.16] | 不算提升 |

重抽样 20,000 次：每次从 1,725 个家族有放回地抽，同一组抽样在四组和三个种子之间共用；先算每个种子的差，再取三个种子的平均。区间只反映留出样本的抽样波动，不包含重新训练的随机性。plain 方向的结论相同：NLIinit + 3.07 [+1.49, +4.63]，其余两臂的区间都含 0。

- **NLIinit 的提升四类都有**：E / F / B / O 的 F1 分别升 2.7 / 2.8 / 2.9 / 5.6 个百分点。
  - O 的误判（金标不是 O、判成 O）从 224 / 274 / 230 降到 148 / 178 / 180；漏判从 191 / 168 / 178 降到 174 / 170 / 172。
  - 预测为 O 的行数变少，O 的 AP 升了约 3 个百分点，所以不只是判定阈值在移动。
- **NLIinit 只用原数据就接近 B2**：B2 用了 +2 的生成数据，sym WF1 是 83.21%。NLIinit − B2 = −0.6 [−1.8, +0.5]，看不出差别。这是两种不同改动的系统比较，只作描述。
- **OLat4 的 4 个分量没有分化**：训练完以后，金标 O 的行上各分量的平均责任度都是 0.25 左右，熵约等于 log 4。所以这次只能说明"按这种方式初始化的潜在头没有用"，推不出"把 Other 拆成子类没有用"。
- **工程核对**：
  - Claude 用 `code/claude_recheck_augb_c4.py` 从概率独立重建，45 项 0 问题；脚本在运行前写定，`--selftest-c3` 和 Commit 3 的归档逐位一致。
  - B0 复用通过：SMOKE 的三个预测文件和 Commit 1 归档逐字节相同。OLat1（K = 1）和 B0 也逐字节相同。
  - NLIinit 每项都载入了 200 个张量、278,809,344 个参数，只保留 B0 的分类头。
  - 每项任务平均约 3.8 分钟。
- registry 已登记为 AUGB-OLAT4 / AUGB-NLIINIT / AUGB-BIBCE。

## 问题

- **NLI 检查点用了外部数据**：模型卡写明训练数据是 26 种语言各 105,000 对（共 2,730,000 对），加英语 105,000 对、10% 跨语言对和 XNLI 验证集，总计 3,287,280 对。英语来源是 MultiNLI、Fever-NLI、ANLI、LingNLI、WANLI，不含 SNLI 和 iSTS / PhrasIS。官方规则允许外部资源，但要在系统论文里披露。这些来源和任务数据有没有逐条重合，还没有检验。
- **只在英语上试过**：这个 NLI 检查点覆盖西班牙语，但没有巴斯克语。另外三个赛道上效果如何，不能从这次推断。
- **OLat4 的设计有缺陷**：扰动太小，加上 4 个分量的梯度几乎对称，分量一直分不开。要真正检验"Other 子类"这个想法，需要换一种做法（比如用 PhrasIS 原来的细标签做辅助监督，或者加分量多样性项），这得另行登记。
- **BiBCE 没有效果**：两个方向的边际概率本来就是四类 softmax 的函数，辅助项改变的只是不同错误的梯度权重，没有带来新的信息。这和 Codex 事先的判断一致。
