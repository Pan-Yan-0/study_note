# mDeBERTa CE：西语、巴语、跨语言五折三种子

## 结果

导师要求把其他三个赛道也跑全量。配方和英语五折的 CE 相同（第五组 C0：mDeBERTa-v3-base，最多 12 轮，lr 2e-5，batch 32，内层验证原方向 WF1 选轮），划分和英语相同（按英语短语家族分 5 折，每折再按家族留 10% 作内层验证），种子 42–44，共 45 个任务。在 Kaggle T4 上用 fp16 autocast 运行，训练会话合计约 7.2 小时（西语 58 分钟、巴语 57 分钟、跨语言 314 分钟）。

## 问题

1. **西语、巴语、跨语言的划分有少量文本重合**。家族是按英语文本合并的；不同的英语短语对翻译后可能变成同一个西语或巴语短语对，落在不同的折里。留出行里文本也出现在同折训练 / 内层验证里的：西语 68 行（2.2%）、巴语 69 行（2.3%）、跨语言 273 行（1.5%），绝大多数标签相同。这些行的准确率约 .90–.94，其余约 .73–.78，所以整体分数大约偏高 0.3–0.4 个百分点。第五组和第四组在这三个赛道的 fold 0 结果用的是同一划分，同样受影响；英语没有这个问题。
2. **T4 fp16 在四个赛道上都比 A10 bf16 高约 1 个百分点**（12 个种子里 9 个为正）。卡、精度、torch 版本同时不同，不能归因到 bf16；但这说明不同卡上的结果不能直接相减，比较方法时要在同一环境里配对。
3. **单折单种子的波动很大**：fold 0 只有 608 行（跨语言 3,648 行，但只有 343 个家族），同配方两次运行的单个种子可差 3 个百分点以上。其他赛道以后比较方法时，应该看五折折外的结果。
4. **这次运行的驱动代码不在仓库里**：任务记录里的代码身份是 multilang 驱动的哈希（`8554642853d6…`），日志显示它调用了一份 mDeBERTa 训练脚本的副本。训练变量和第五组的任务记录逐项相同，但源码要补进 `code/` 才能复现。

## 文件与来源

`formal/` 是 45 个任务的配置、训练历史、logits、逐折预测和官方评分；`aggregate/` 是每个赛道每个种子拼好的折外预测和官方评分；`logs/`、`smoke/`、`timing/` 是运行日志、三个赛道的 SMOKE 和测速；`MANIFEST.json` 是全部文件的 SHA-256。

实验由 Pan-Yan-0 在 Kaggle T4 上运行。训练配方来自第五组脚本（Claude 编写、GPT 审阅）；multilang 驱动的源码和作者还没归档。Claude 从逐折 logits 重建了全部预测和折外拼接，核对了每折留出行和家族划分一致、MANIFEST 哈希全部一致，官方评分复算和记录逐项相同：`python3 code/claude_recheck_multilang.py metrics/mdeberta_multilang_oof <官方仓库目录>`。
