# 更大模型与数据扩充：冻结计划

本阶段有两个实验：**A. 换更大的 Qwen**；**B. 用大模型生成数据扩充训练集**（导师清单第 3 项："用 DeepSeek 扩充，越多越好，增加的过程中看性能会不会升"）。设计由 Claude 起草，GPT 审了两轮后收敛，下面是冻结版本。执行中如果要改，在文末"变更记录"里写明改了什么、为什么。

## 1. 共同口径

- **主指标**：英语五折折外预测（3,042 行）的对称化 WF1，只用文本；种子 42–44，和**同一环境**的基线按种子配对；按 1,725 个家族配对重抽样 2,000 次求近似区间（`code/registry.py` 的约定）。原方向和对称化的 WF1 / SoftCons / HardCons、逐类 F1 都报告。
- **次指标**：都用同一份概率事后计算，不影响训练和选轮。
  - 结构规则下的分数：单条的判 NEGATIVE_OTHER，成对的只在 E / F / B 里选。用不用这条规则，等主办方回复、由 Pan-Yan-0 和导师决定。
  - 多种子概率平均后的分数。
- **判断规则**：新设置相对基线，同种子差的均值大于 0，并且家族重抽样区间下限大于 0，才算"有提升"。
  - 区间只反映样本抽样，不包含重新训练的随机性。
  - 选生成来源、选扩充规模都属于方法选择。最终报告保留全部尝试，不把入选方案的区间当作独立的确认性证据。
- **dev 只报告**，不用来选方法。fold 0 和五折数据都参与过研究决策，所以结论都是探索性的。
- 每次运行都登记进 `registry.py`，只在同一环境里配对比较。

## 2. 实验 A：Qwen3-8B

| 项目 | 设定 |
|---|---|
| 模型 | `Qwen/Qwen3-8B`，关闭思考模式（`enable_thinking=False`） |
| 对照 | `JOINT-QWEN`：Qwen3-4B-Instruct-2507，A10 bf16，英语五折 × 种子 42–44 |
| 配方 | 和 4B 完全相同，不调参：LoRA r16 / α32 / 7 个投影 / dropout 0，lr 1e-4，有效 batch 16，最多 3 轮，内层验证选轮，只在答案字母上算损失 |
| 运行 | A10 bf16，英语五折 × 3 种子共 15 个任务，按种子排序（先跑完 seed 42 的五折） |
| 性质 | 系统比较：模型、分词器、聊天模板、后训练方式都变了，只说"在这组设置下哪个更好" |

**工程验收（SMOKE，正式运行前必须全部通过）**：
1. 打印渲染后的提示词，确认空 think 块和 "Answer:" 的位置。
2. 四个答案字母各是单个 token，拼到提示词后面不和前面合并。
3. 损失只落在最后一个真实 token 上，ForwardCheck 的两条前向路径一致。
4. 用最长的一批输入跑完整的训练步，记录峰值显存（包括优化器状态）；还要跑内层验证评分，重新加载选中的权重并逐位核对。
5. 微批先试 8 × 2，放不下才改 4 × 4（有效 batch 不变）。正式运行前定死，写进指纹。
6. **新旧代码一致性**：
   - 用新代码加载 4B，在 dev 上读零样本概率，和 A10 已缓存的零样本结果逐条比较。
   - 用同一份已有的 4B LoRA 权重，在固定的小批次上比较旧、新代码的输入、标签掩码、损失和输出；再在同样的批次顺序下做几步参数更新，比较更新后的参数。
   - 如果旧权重拿不到，就在结果里写明这一项没有验证。
   - torch、transformers、peft 和 CUDA 的版本逐项列出，有不同就标出来。

**估时**：每步约 4.8 秒，每个任务约 38–40 分钟，15 个任务约 10 小时、约 70 计算时，以 SMOKE 实测为准。

**之后（另行安排）**：巴斯克语上比较 8B 和 4B，要先在同一环境补 4B 的巴语五折；HiTZ 的 Latxa-Llama-3.1-8B-Instruct 留作巴斯克语专项候选，用之前先核对许可证和训练数据来源。

## 3. 实验 B：生成数据扩充

### 3.1 两个生成来源

- **DeepSeek**：走 API，由 Pan-Yan-0 运行。每个批次一次无状态调用，保存响应里返回的实际模型标识。
- **GPT6Luna**：由 Luna 开不继承对话历史的子 agent，每个子 agent 只拿到一个批次的提示词文件。
  - 子 agent 和主 agent 共享工作区和工具，**技术上不能禁止它访问仓库或网络**。我们能做到的是：全新上下文、只提供本批输入、指令禁止访问其他资料、保留运行记录。论文里如实这样写。
  - 主 agent 只分发文件、原样收回输出，不改写、不补全、不自己生成。
  - 调度记录要保存：哪个子 agent 拿了哪个批次、起止时间、显示的模型名。
- 两个来源用**完全相同的批次、逐字相同的提示词、同样的配额**。

### 3.2 防泄漏：按可用折签名分批

- **签名**：一个家族在哪些折里属于训练部分，即不在那一折的留出部分，也不在那一折的内层验证里。
  - 签名从实际的 fit / val / test 清单计算，不写死。
  - 内层验证划分只由划分种子和折号决定，不随训练种子变化，所以三个训练种子共用一套签名。
  - 目前英语一共 30 种签名。
- **同一批只放签名相同的父样本**，每批 10–20 个。
- 每个子样本保存整批的 `context_parent_ids`。只有全部上下文来源都在第 k 折的训练部分里，才在第 k 折使用。训练入口再检查一遍，不只相信生成脚本。
- **示例、重试和返工反馈都算上下文**：提示词里的例子只用我们手写的、不来自数据集的材料；不拿其他批次的输出来示范或纠错。
- 保存划分清单的哈希；划分一变，旧的生成数据就不能再用。
- 生成结果按规范化文本、两个方向，和全部训练集、dev 去重；子样本和父样本相同的也去掉。
- **提示词调试只用手写材料**：用我们自己写的短语对调试提示词，冻结之后才在真实父样本上生成。如果冻结后还要修改，就在变更记录里写明，并把结果标为在开发过程中用过这些信息的探索性结果。

### 3.3 生成什么

- 新的短语对，不是父样本的改写。领域相同（图片描述、新闻标题），长度分布和短语块风格相近。
- **标签按原训练集的行分布配额**：E 约 26%、单向蕴含（F + B）约 58%、NEGATIVE_OTHER 约 16%。
  - E 和单向蕴含的短语对加两个方向（对调后标签互换），NEGATIVE_OTHER 加一个方向，和原数据格式一致。
  - 抽样以完整短语对为单位，不为凑行数拆开两个方向。
- 每批生成多少对、各类多少，由配额脚本计算，初始多备约 25%；不够时按固定规则补生成。
- O 定向增强、反事实最小改动对，都不放进主线，以后单独成组。
- 先只做英语。

### 3.4 过滤和质量

- **主线只用确定性的过滤**：格式、标签取值、长度、去重、上下文检查。
  - 主线回答的问题是：在统一的格式、去重和来源检查下，两个生成流程各自提供的数据能不能改善模型。它不保证每条生成标签都正确。
- **验证器只作诊断**：另一个提示词给生成数据逐条打标签。
  - 报告混淆矩阵、每类 precision / recall 和拒绝率，并写明参照的是生成器的标签、模型辅助审核的标签还是官方金标。
  - 验证器和生成标签一致，不等于验证器准确。"加不加语义筛选"以后作为单一改动单独测。
- **模型辅助审核**：两个来源走同一个流程，隐藏来源。
  - Claude 和 GPT 各自独立标注；Pan-Yan-0 裁决分歧，并随机抽查一部分两者一致的样本，以发现共同错误。
  - 这是模型辅助审核，不称为人工金标；结果按审核人分开报告。
  - 规模：试点每个来源 60 对（E、单向、O 各 20）；正式在最终保留的 +1 数据上每个来源按类分层抽 150 对。
  - 审核只用来测量质量，不悄悄修正或删除被抽中的样本。确实要修订，就建一个新的数据版本，两个来源用同一规则。
- **模板偏差检查**：比较每类的长度、词重叠等分布；用浅层特征训一个探针，看生成数据的标签是不是比原数据更容易从表面特征猜出来。

### 3.5 运行顺序

1. **试点**：约 200 个父样本 × 2 个来源，过 3.4 的检查。
   - 事先定的停止条件（任一来源出现就先修流程，不进入训练）：
     - 一次重试后仍不合格的批次超过 5%；
     - 和原数据或已生成数据完全重复的短语对超过 10%；
     - 模型辅助审核里，两位审核者一致、却和生成标签不同的比例，在任一类里超过 30%；
     - 浅层探针在生成数据上的准确率比原数据高 15 个百分点以上；
     - 平均词数偏离原数据 50% 以上。
   - 试点里某个来源略差，不等于另一个胜出。
2. **+1 比较**：两个来源都没触发停止条件，就各生成完整的 +1，在 mDeBERTa 上比较。
3. **规模曲线**：选中的来源做 +2、+4。
4. **再决定 Qwen 上的扩充**：用哪个规模、哪个模型，另行安排。

**规模的定义**：+k 是第 j 折新增 k ×（该折训练部分行数）行生成数据，按过滤后的实际行数算，嵌套抽样（+1 ⊂ +2 ⊂ +4），按标签分层，允许很小的舍入误差，记录实际倍率。

**训练矩阵**：mDeBERTa CE，第五组 C0 配方，Kaggle T4 fp16，英语五折 × 3 种子。

| 组 | 训练数据 | 任务数 | 估时（单卡） |
|---|---|---:|---:|
| B0 | 原数据（同环境基线） | 15 | 约 1 小时 |
| B1-DeepSeek、B1-Luna | 原数据 + 各来源 +1 | 30 | 约 3.9 小时 |
| step+1 | 原数据重复采样到和 +1 相同的实际行数 | 15 | 约 2 小时 |
| B2、B4（选中的来源） | +2、+4 | 30 | 约 7.8 小时 |
| step+2、step+4 | 和 +2、+4 相同的实际行数 | 30 | 约 7.8 小时 |

- 内层验证只用原数据。
- 每个 step+k 和对应的 +k 每轮步数、学习率日程和验证频率都相同。
- 合计约 22 GPU 小时，加 20% 失败重试约 27 小时；Kaggle 两张 T4 并行约 14 小时墙钟。
- **判断**：+k 相对 B0 和相对 step+k 都满足第 1 节的规则，才算扩充有效。曲线形状照实报告。

**费用**：DeepSeek 按小试的实际用量估算。按第三方汇总的价格，整套生成加验证在十几到几十元人民币。

## 4. 训练清单接口

生成侧（Claude）和训练侧（GPT）之间只通过清单文件交接。每个数据版本有一份清单和一份元数据。

**清单**：一行一条训练记录。

| 字段 | 含义 |
|---|---|
| `sample_id` | 训练记录编号 |
| `pair_uid` | 短语对编号，同一对的两个方向相同 |
| `direction` | original / flipped |
| `text1`、`text2`、`label` | 文本和标签 |
| `source` | deepseek / luna |
| `generator_model` | API 返回或界面显示的模型标识 |
| `batch_id` | 批次编号 |
| `parent_family` | 父样本的家族 |
| `context_parent_families` | 整批的上下文来源 |
| `usable_folds` | 可用的折 |
| `tier_by_fold` | 每一折里属于 +1 / +2 / +4 的哪一层，不可用为空 |
| `data_version` | 数据版本 |

**元数据**：划分清单的哈希、提示词的哈希、过滤规则版本、各折各层的实际行数和倍率、清单文件的哈希。

**step+k 的重复采样清单**：也由生成侧给出，按折列出原数据的记录编号和重复次数，训练侧照单使用。

训练入口要再次核对：可用折、上下文来源、清单哈希和划分哈希。

## 5. 要保存的来源记录

- 完整的生成输入和输出（原样），批次和上下文来源，过滤原因。
- 模型辅助审核的标注和裁决，各规模的样本清单。
- 模型标识、训练步数、选轮依据、运行成本。
- Luna 子 agent 的调度记录。

## 6. 分工

- **Claude**：生成和分批脚本、配额、过滤、去重、审核材料、清单和元数据、registry 登记和复核脚本。
- **GPT**：A1 的 A10 队列（8B，包括第 2 节的验收），B 的 Kaggle mDeBERTa 队列（读清单，带 step+k 对照）。
- 互相审代码，SMOKE 通过才跑全量。

## 7. 变更记录

（冻结后的修改写在这里。）

- A10 的 10 月余额只剩约 35 计算时（约 5 个 A10 小时，10-31 作废）。A1 的工程验收（SMOKE 和新旧代码一致性检查）用这部分余额在 10-31 前做；15 个正式任务等 11 月的新额度。不改到 Kaggle T4：8B 的 fp16 权重放不进单张 T4，两张卡拆分每个任务约 90 分钟，还要在 T4 上补跑 4B 的五折基线，一周的 Kaggle 额度不够。实验 B 照计划在 Kaggle 上进行。
- 10-28：A1 工程验收在 A10 上全部通过（[结果](metrics/qwen8b_acceptance/README.md)）。选定批 8 × 2，峰值显存 17.0 GiB；正式运行估计约 10 小时、约 70 计算时。运行的代码是 GPT 的 v4，v2 之后的改动在 11 月正式运行前由 Claude 补审。
