## 原则（Pan-Yan-0 转达、双方共同遵守）

1. **以 Pan-Yan-0 的阅读进度为准。** [`../阅读表/`](../阅读表/) 是 Claude 的预读，是准备材料，不能代替他自己读；他读完对应那一遍之前，不引用里面的结论，也不提前给答案。
2. **解释要标证据强度。** 实测（直接从已有输出算出）、推断（实测加论文说法推出，未经实验检验）、待验证（要实验才能回答）。例：多个模型共同犯错，不能证明金标有问题；教师概率尖锐，不能证明它就是蒸馏持平的原因。
3. **交接要能独立接续。** 写清读到哪、他已经理解什么、还有什么疑问、哪些解释待核实。只有讨论或审阅文字时交一份 Markdown；涉及代码或多份材料时打包 ZIP 并附入口 README（见根目录 `AGENTS.md` 的交接约定）。

## 分工（v3，按学习阶段；Pan-Yan-0 定，GPT 已确认）

| 阶段 | 主要负责方 | 内容 |
|---|---|---|
| 论文初步学习 | Claude | 依据实验选文，一次一篇；组织三遍阅读、补讲基础、出题批改；维护本文件、进度表和每篇笔记，帮他学到可以开始写文章的程度 |
| 公众号写作 | GPT 与 Pan-Yan-0 | 从他已形成的理解出发选切入点、组织结构、解释概念、打磨表达、核查原文和实验引用 |
| 写作中的进一步理解 | GPT 与 Pan-Yan-0 | 讨论写不清的概念和新疑问，必要时回读原文；新理解、纠错或实验想法整理回传，注明已核实 / 待讨论 |
| 新实验 | SemEval 实验对话 | 接收实验卡片，决定是否运行 |
| 经验与画像 | Claude | 私有 cognitive-tutoring，不进仓库；GPT 不另建画像、不计算经验 |
| 发表 | Pan-Yan-0 | 审阅文章，决定是否、何时发表 |

- 复核不是日常必经环节：GPT 写作时核对文章用到的解释和数字，发现与原文或记录不一致，再给 Claude 提具体问题。
- 写作也能产生新理解：旧笔记没记录不等于不能写；但 GPT 或 Claude 的解释都不直接算他已掌握，要有他自己的表述。
- 何时开始写，由他的实际理解和意愿决定，不以"三遍读完"为门槛。

### 进入写作时 Claude 交给 GPT 的内容

论文信息、原文入口和当前阅读位置；他能用自己的话说明的内容及支撑的回答或复述；未解决的疑问和要避免混淆的概念；可用于文章的实验事实及来源路径；已有意向的文章主题。

### 草稿位置

早期草稿以独立 Markdown 交给 Pan-Yan-0 审阅；适合公开的版本归档到 `论文研究/文章/`（与 `精读/` 并列、互相链接），建目录时再定。
