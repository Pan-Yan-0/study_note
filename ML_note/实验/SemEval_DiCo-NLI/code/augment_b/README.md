## 2. 执行顺序

1. **先跑 `debug_b00`**：用一个全新子 agent 跑一次，交回 Claude。
   - 它只用来确认提示词能产出合格格式、内容像样，不进入任何数据版本。

2. **再跑 15 个试点批次**：每批一个全新子 agent，按第 3 节的规则执行。

## 3. 调度规则（对应 GPT 意见第 4–6 条）

- **隔离**：每次尝试都开一个不继承对话历史的子 agent，只给它这一批的 `prompt` 字段全文，不给其他文件。
  - 提示词里已经写明不访问文件和网络。
  - 共享工作区下这是**流程隔离，不是技术隔离**，报告里如实写明。
- **主 agent 的职责**：只分发、原样保存，不改写、不补全、不自己写短语对。
- **格式检查**：以 `check_format.py` 的判定为准（`python check_format.py batches/<id>.json outputs/<id>/attempt_1.txt`，退出码 0 为合格）。
  - **格式不合格**指以下几种情况：不是完整的 JSON 对象（外面恰好包一层 ``` 代码块可以接受）、batch_id 不对、缺 pairs、缺字段或有空文本、标签不在本批允许的范围、各标签对数和配额不完全相等。
  - 不合格时，换一个全新子 agent、用同一完整提示词重试**一次**。不附加任何反馈或其他批次的内容。
  - 重试后仍不合格，就标记失败、原样保留，不再处理。
- **不算格式错误的情况**：重复、过长、照抄父样本等。这些不触发重试，由 Claude 用确定性规则过滤。
- **基础设施错误**：空回复、超时、工具报错，记为 `infra_error`。可以再派一次（同一提示词、全新子 agent），不占用那一次格式重试的机会，但每次都要记录。
- **不足额**：试点不补。全量阶段的补充用新批次号、按固定规则下达配额（第 5 节），不是从几次输出里挑一个好的。

## 4. 交回的内容

- `outputs/<batch_id>/attempt_<n>.txt`：每次尝试的原文，一字不改。格式不合格的也保留，不覆盖第一次失败的输出。
- `dispatch_log.jsonl`：每次尝试一行，字段如下：

  ```json
  {"batch_id": "pilot_b01", "attempt": 1, "agent_id": "...", "start": "ISO 时间", "end": "ISO 时间",
   "requested_model": "gpt-6-luna", "visible_model": "界面实际显示的模型标识", "prompt_sha256": "批次文件里的值",
   "status": "ok | format_fail | infra_error", "reason": "失败原因（格式错误照抄 check_format 的输出）"}
  ```

- 一个简短的 README：实际执行方式、并发数、每批耗时，以及任何偏离第 3 节的地方。
- `debug_b00` 的输出放在同样的位置，即 `outputs/debug_b00/`。

## 5. 上下文、可用折和配额

- **签名**：一个家族在哪些折里属于 fit，就是它的签名。一共 30 种。可用 1 / 2 / 3 / 4 折的家族分别有 10 / 80 / 498 / 1137 个。
- **可用折**：一批只放同一签名的父样本；每条子样本的可用折等于整批上下文来源可用折的交集（`build_pilot.py` 按交集计算，不靠"同签名"这个假设）。
  - 手写示例和模板不来自数据，不算上下文。
  - 重试用同一提示词，上下文不变。
  - 训练入口仍要再核对一次：只有整批上下文来源都在第 k 折的 fit 里，才能在第 k 折使用。
- **配额以短语对为单位，标签定义为 text1 → text2**：
  - EQUIVALENCE 展开成两行，都是 E；
  - FORWARD_ENTAILMENT 展开成原方向 F、反向 B；
  - NEGATIVE_OTHER 只保留生成的那一个方向。
  - 展开由 `process_outputs.py` 确定性完成，主 agent 不手工改标签。生成器不直接写 BACKWARD。
  - 父样本里原方向标为 BACKWARD 的，在提示词里交换两侧、按 FORWARD 展示，只为和生成标签用同一形式。
- **试点规模**：15 批，每批 13 个父样本、各 14 对（E 3 / 单向 7 / O 4），共 210 对（E 45 / 单向 105 / O 60）。
  - 前 10 批取 5 种最大的 4 折签名，各 2 批；后 5 批取 5 种最大的 3 折签名，各 1 批。
  - 批次之间不重复使用父样本。
- **全量 +1（以后用，现在只是计划）**：
  - 按签名下达，每种签名的计划行数为"该签名父样本行数 × 1.25"，按原训练集的行比例分到 E / 单向 / O。
  - 过滤前，每折每类的计划产出是需求的 1.21–1.31 倍（见 `demand_plus1.csv`）。
  - 过滤后逐折逐类精确验算。E 和单向都按整对取，不拆对凑数。哪一折哪一类不够，就按缺口 × 1.25 对相应签名下达补充批次（新批次号、同一规则）。

## 6. 过滤、审核和停止条件（事先固定）

### 6.1 确定性过滤

`process_outputs.py` 按顺序检查，命中第一条就去掉：

1. 两侧规范化（转小写、合并空白）后相同；
2. 任一侧的词数不在 1–20；
3. 和本批的父样本是同一短语对（任一方向）；
4. 和官方训练集或 dev 的短语对相同（任一方向）；
5. 和前面已保留的生成短语对相同。

另外报告"复用了父样本或官方数据里的某个短语"的比例，只作诊断。

### 6.2 停止条件

任一条成立，就先修流程，不进入训练：

| 条件 | 门槛 | 怎么算 |
|---|---|---|
| 重试后仍失败的批次 | > 5% | 15 批里失败 1 批即为 6.7%，触发 |
| 和原数据或已生成数据完全重复 | > 10% | 过滤里第 3–5 条去掉的对数 ÷ 交回的对数 |
| 审核不一致 | 任一类 > 30% | 见 6.3 |
| 浅层探针 | 生成数据比原数据高 15 个百分点以上 | 11 个表面特征（长度、词重叠、包含关系等）上做逻辑回归，五折交叉验证的平衡准确率。原数据把原方向的 B 换成 F 形式后为 50.1%（三类随机水平是 33.3%） |
| 平均词数 | 偏离原数据 50% 以上 | 按每个短语的词数平均 |

### 6.3 审核

- **抽样**：从保留下来的对里，每个生成标签抽 20 对，共 60 对，种子 20261104。展示方向随机，隐藏生成标签和父样本。
- **标注**：可以填 E / F / B / O，或"无法确定"。"无法确定"单独计数，不静默排除。
- **两种协议**，由 Pan-Yan-0 **在看到输出之前**选定其一：
  - **P1（GPT 建议）**：Claude 和 Pan-Yan-0 各自独立标注全部 60 对，然后讨论分歧。停止统计：两人都给出确定标签且一致的项里，和生成标签不同的比例。
  - **P2（较省力）**：Claude 独立标注全部 60 对。Pan-Yan-0 裁决所有"Claude 和生成标签不同"的项，另外随机抽查 10 个一致项（种子同上）。停止统计：最终标签（有裁决用裁决，否则用 Claude 的）里，和生成标签不同的比例。
- **两种协议的计算都写在** `process_outputs.py score`。P1 和 P2 是不同的协议，结果不和旧的"双模型一致率"混在一起比较。
- **GPT 可以做补充审核**，但要用隔离的上下文、看不到生成标签，结果单独报告，并注明它和生成器出自同一供应方。
- **审核只是测量质量**：被抽中的坏样本不悄悄删掉或改掉。真要改，就建新的数据版本，所有数据用同一规则处理。
- **Claude 的限制**：提示词和父样本都是 Claude 选的，Claude 只按审核表标注，但无法证明自己完全不受影响，报告里写明这一点。
