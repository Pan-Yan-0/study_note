## 3. 调度规则

- **隔离**：每次尝试一个不继承历史的子 agent，只给它这一批 `prompt` 字段的全文。共享工作区下这是流程隔离，不是技术隔离。
- **主 agent**：只负责分发和原样保存，不改写、不补全、不自己写短语对。
- **格式检查**：以 `check_format.py` 的判定为准。
  - 以下都算格式不合格：
    - 不是完整的 JSON 对象，包括 `null`、数组、字符串；
    - 空回复：模型正常结束却没有内容；
    - batch_id 不对，或缺 pairs；
    - 缺字段，或文本为空；
    - 标签不合法；
    - 各标签的对数和配额不完全相等。
  - 外面恰好包一层 ``` 代码块可以接受，会记录下来。
- **尝试上限**：每批最多 1 次基础设施重派、1 次格式重试，**总共不超过 3 次**。
  - 只有能证实的基础设施故障（超时、工具报错、连接中断）才能记为 `infra_error`。
  - 模型正常结束但内容不好，不能改记成基础设施错误。
  - 部分输出也要原样保留。
- **重试的方式**：换全新子 agent、用同一提示词，不附加任何反馈。重试后仍不合格，就标记失败、原样保留。

## 4. 交回的内容

- **每次尝试的原文**：`outputs/<batch_id>/attempt_<n>.txt`，一字不改，不覆盖之前的尝试。
- **`dispatch_log.jsonl`**：每次尝试一行，下面这些字段**都必须有值**，缺任何一个，`process_outputs.py` 都判协议违规、不放行。

  ```json
  {"batch_id": "pilot_b01", "attempt": 1, "agent_id": "...", "start": "调用前的 UTC 时间", "end": "返回后的 UTC 时间",
   "requested_model": "gpt-6-luna", "visible_model": "工具或界面实际返回的模型标识", "prompt_sha256": "批次文件里的值",
   "status": "ok | format_fail | infra_error", "reason": "...", "raw_sha256": "原文的 SHA-256"}
  ```

  如果工具确实不返回模型标识，就填 `"visible_model": "工具未返回"`，并在 README 里说明。这样记录是完整的，只是如实写明缺这一项。
- **一个简短的 README**：实际执行方式、并发数，以及任何偏离第 3 节的地方。

## 5. 上下文、可用折和配额

- **签名**：一个家族在哪些折里属于 fit，就是它的签名，一共 30 种。一批只放同一签名的父样本。
- **可用折**：每条子样本的可用折取整批上下文来源可用折的交集。手写示例不算上下文。训练入口还要再核对一次。
- **配额以短语对为单位**，标签都按 text1 → text2 的方向定：
  - E 展开成两行，都是 E；
  - FORWARD 展开成原方向 F、反向 B；
  - O 只保留生成的那一个方向。
  - 展开由脚本完成。生成器不直接写 BACKWARD。父样本里原方向标为 B 的，交换两侧、按 F 展示。
- **试点规模**：15 批，每批 13 个父样本、各 14 对（E 3 / 单向 7 / O 4），共 210 对。批次之间不重复使用父样本。
- **全量 +1**：按签名下达，计划行数为"该签名父样本行数 × 1.25"。过滤前，每折每类的计划产出是需求的 1.21–1.31 倍。
- **补充批次**：过滤后按 `supplement.py` 的确定性算法规划，规则写在文件开头：
  - 按 E → 单向 → O 的顺序处理缺口；
  - 每次选覆盖缺口折数最多的签名，相同时选家族数多的，再相同按签名字符串排序；
  - 每批 14 对、只含一个组；预计保留率取该组实际保留率，向下取到 0.05 的倍数；
  - 父样本优先用没用过的；
  - 补充总行数超过 +1 计划的 20% 就停下、等人决定；最多补两轮。

## 6. 过滤、停止条件、审核和放行

### 6.1 过滤

`process_outputs.py` 按顺序检查，命中第一条就去掉：

1. 两侧相同；
2. 任一侧的词数不在 1–20；
3. 和本批的父样本是同一短语对；
4. **任一侧照抄了本批父样本的短语**（v2 新增，对应提示词第 1 条）；
5. 和官方训练集或 dev 的短语对相同；
6. 和已保留的生成短语对相同。

### 6.2 停止条件

| 条件 | 门槛 |
|---|---|
| 重试后仍失败的批次 | > 5%（15 批里失败 1 批即触发） |
| 和原数据或已生成数据完全重复（第 3、5、6 条） | > 10% |
| 审核不一致 | 任一类 > 30%（见 6.3） |
| 浅层探针（11 个表面特征的逻辑回归，平衡准确率） | 生成数据比原数据高 15 个百分点以上（原数据为 50.1%） |
| 平均词数 | 偏离原数据 50% 以上 |

第 4 条"照抄父样本短语"的比例单独报告。

### 6.3 审核（P1，已选定）

- **抽样**：每个生成标签抽 20 对，共 60 对，种子 20261104。展示方向随机，隐藏生成标签和父样本。
- **标注**：Pan-Yan-0 和 Claude 各自独立标注全部 60 对，可以填 E / F / B / O / U（U 表示无法确定）。
- **校验**：标注表必须恰好覆盖 60 个编号、没有重复、标签合法，否则判为 `invalid`。
- **每一类的判定**：
  - 抽样不足 20 对，或两人都给出确定标签且一致的项少于 **10** 个 → `insufficient`，不放行。这条低覆盖规则是事先定的。
  - 在两人一致的项里，和生成标签不同的比例超过 30% → `fail`。
  - 否则为 `pass`。
  - 同时报告分母、两人分歧数和"无法确定"的数目。
- **P2 的计算**也保留在代码里：裁决表必须覆盖全部待裁决项。但这次不用。
- **GPT 的补充审核**（如果做）：用隔离的上下文、看不到生成标签，结果单独报告，并注明它和生成器出自同一供应方。

### 6.4 放行门槛

- `manifest.csv` 只是候选。能不能进训练只看 `gate.json` 里的 `ready_for_training`。
- 以下检查都是 `pass` 才放行：协议、失败批次、重复、探针、词数、审核。
- `fail`、`not_run`（例如缺 sklearn，探针没法跑）、`pending`、`invalid`、`insufficient` 都不放行。

## 7. 怎么跑测试

```bash
cd augb_pilot_v2/code
DICO_OFF=<官方仓库目录> DICO_PKG=.. python -m unittest test_augment_b -v
```

- 一共 8 项：
  - 用包内输入重建整个包，逐字节一致；
  - 批次结构和可用折；
  - 格式检查，包括 `null` 和空回复；
  - 6 种过滤；
  - 协议违规：缺时间字段、合格后又重试；
  - 探针缺依赖时不放行；
  - 审核表校验（空表、缺项、重复、非法标签、全部无法确定）和 P1 / P2 计分；
  - 补充规划的确定性和预算上限。
- 没有设 `DICO_OFF` 时，测试直接报错，不会静默显示"跑了 0 项"。

## 8. 相对 v1 的修改（对应 GPT 调试复核）

| GPT 指出的问题 | v2 的处理 |
|---|---|
| 测试依赖仓库里的 families.json，包内跑不起来 | 包里带上 `inputs/families.json`；`build_pilot.py` 接受 `--families`、`--split-manifest`；测试在包内重建并逐字节比对；缺官方数据时直接报错 |
| `check_format` 把 `null` 判为合格 | `null`、数组、空回复都判为格式不合格；没得到合格的 pairs 就不是 ok |
| 空标注表算出 stop=false | 标注表要覆盖全部编号、没有重复、标签合法，否则 `invalid`；可判定项不足 10 个为 `insufficient`；都不放行 |
| 探针缺依赖、日志哈希不符只进 problems | 统一用 `gate.json` 的 `ready_for_training` 放行；协议问题、`not_run`、审核没做完都不放行 |
| 输出照抄了参考短语（a young dog） | 提示词第 1 条写明连单侧也不能照抄；过滤加第 4 条，确定性去掉 |
| 结构雷同（a pair of → two），E 三对都是"动词 / is 动词-ing" | 提示词加第 2 条：话题和差别类型要多样，同一种模式不超过两对。手写参考对里的 3 个 E 原来都是动词时态变化（这是 Claude 的问题），改成三种不同类型 |
| 调试提示词把手写参考称为"真实样本" | 模板里改为 `{reference_source}` 占位：真实批次写"real examples from the dataset"，调试批次写"hand-written examples in the style of the dataset" |
| 补充批次只写了"缺口 × 1.25" | 写成确定性算法 `supplement.py`，见第 5 节 |
| 基础设施重试和格式重试的上限 | 照 GPT 的意见：各最多 1 次，总共不超过 3 次，代码里检查 |
| 调度记录缺时间和模型标识 | 第 4 节：所有字段都必须有值；工具不返回模型标识时如实写"工具未返回" |

提示词第 2 条会不会让生成数据偏离原数据的分布（原数据里本来就有很多时态变化的 E），由第 6.2 节的探针和词数检查来量；一次调试的 14 对说明不了总体偏差。
