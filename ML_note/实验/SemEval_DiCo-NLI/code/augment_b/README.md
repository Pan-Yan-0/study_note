## 2. 执行顺序

1. **先跑 `debug_b05`**：一个全新子 agent 跑一次，按第 3 节的规则最多格式重试一次。不进入任何数据版本。
2. **直接接着跑 15 个试点批次，不用先交回 Claude**，条件是 `debug_b05` 同时满足：

## 3. 调度规则

- **隔离**：每次尝试一个不继承历史的子 agent，只给它这一批 `prompt` 字段的全文。共享工作区下这是流程隔离，不是技术隔离。
- **主 agent**：只负责分发和原样保存，不改写、不补全、不自己写短语对。
- **格式检查**：以 `check_format.py` 的判定为准。
  - 以下都算格式不合格：
    - 不是完整的 JSON 对象，包括 `null`、数组、字符串；
    - 空回复：模型正常结束却没有内容；
    - batch_id 不对，或缺 pairs；
    - 缺字段，或文本为空；
    - 标签不合法；
    - 各标签的对数和配额不完全相等；
    - 第 k 对的标签和第 k 个参考对 Rk 的不同（v6 新增）。
  - 外面恰好包一层 ``` 代码块可以接受，会记录下来。
- **尝试上限**：每批最多 1 次基础设施重派、1 次格式重试，**总共不超过 3 次**；出现合格输出之后，不得再追加任何尝试，包括基础设施重派。
  - 只有能证实的基础设施故障（超时、工具报错、连接中断）才能记为 `infra_error`。
  - 模型正常结束但内容不好，不能改记成基础设施错误。
  - 部分输出也要原样保留。
- **重试的方式**：换全新子 agent、用同一提示词，不附加任何反馈。重试后仍不合格，就标记失败、原样保留。

## 4. 交回的内容

- **每次尝试的原文**：`outputs/<batch_id>/attempt_<n>.txt`，一字不改，不覆盖之前的尝试。
- **`dispatch_log.jsonl`**：每次尝试一行，下面这些字段**都必须有值**，缺任何一个，`process_outputs.py` 都判协议违规、不放行。
  - start / end 用 ISO 格式，结束不早于开始。
  - 模型完成的尝试必须有 raw_sha256，且等于原文的哈希。
  - 失败（format_fail、infra_error）必须写 reason。
  - infra_error 还要写 `has_partial_output`：有部分输出就保存原文并填 raw_sha256，没有就填 false。

  ```json
  {"batch_id": "pilot_b01", "attempt": 1, "agent_id": "...", "start": "调用前的 UTC 时间", "end": "返回后的 UTC 时间",
   "requested_model": "gpt-6-luna", "visible_model": "工具或界面实际返回的模型标识", "prompt_sha256": "批次文件里的值",
   "status": "ok | format_fail | infra_error", "reason": "...", "raw_sha256": "原文的 SHA-256"}
  ```

  如果工具确实不返回模型标识，就填 `"visible_model": "工具未返回"`，并在 README 里说明。这样记录是完整的，只是如实写明缺这一项。
- **一个简短的 README**：实际执行方式、并发数，以及任何偏离第 3 节的地方。

## 5. 上下文、可用折和配额

- **签名**：一个家族在哪些折里属于 fit，就是它的签名，一共 30 种。一批只放同一签名的父样本。
- **可用折**：每条子样本的可用折取整批上下文来源可用折的交集。手写示例不算上下文。训练入口还要再核对一次。
- **配额以短语对为单位**，标签都按 text1 → text2 的方向定：
  - E 展开成两行，都是 E；
  - FORWARD 展开成原方向 F、反向 B；
  - O 只保留生成的那一个方向。
  - 展开由脚本完成。生成器不直接写 BACKWARD。父样本里原方向标为 B 的，交换两侧、按 F 展示。
- **试点规模**：15 批，每批 14 个父样本、各 14 对（E 3 / 单向 7 / O 4，一个父样本对应一对），共 210 对。父样本在签名内打乱后按标签分层取，批次之间不重复使用。
- **全量 +1**：按签名下达，计划行数为"该签名父样本行数 × 1.25"。过滤前，每折每类的计划产出是需求的 1.21–1.31 倍。
- **补充批次**：过滤后按 `supplement.py` 的确定性算法规划，规则写在文件开头：
  - 按 E → 单向 → O 的顺序处理缺口；
  - 每次选覆盖缺口折数最多的签名，相同时选家族数多的，再相同按签名字符串排序；
  - 每批 14 对、只含一个组；预计保留率取该组实际保留率，向下取到 0.05 的倍数；
  - 父样本按组取：单一组的批次，14 个父样本都来自这个组，一个父样本对应一对（该组家族不够 14 个时少取，对数随之减少）；
  - 只允许第 1、2 轮；**两轮合计**补充行数超过 +1 计划的 20% 就停下、等人决定；
  - 台账持久保存：累计行数、各"签名-组"的游标、已下达的批次号；
  - 父样本按游标循环取用（每个签名、每个组的家族按固定种子打乱一次）；
  - 最后逐折逐类核对 E / F / B / O 四类，不只看三组总数。

## 6. 过滤、停止条件、审核和放行

### 6.1 过滤

`process_outputs.py` 按顺序检查，命中第一条就去掉：

1. 两侧相同；
2. 任一侧的词数不在 1–20；
3. 和本批的父样本是同一短语对；
4. **任一侧照抄了本批父样本的短语**（v2 新增，对应提示词第 1 条）；
5. 和官方训练集或 dev 的短语对相同；
6. 和已保留的生成短语对相同。

### 6.2 停止条件

| 条件 | 门槛 |
|---|---|
| 重试后仍失败的批次 | > 5%（15 批里失败 1 批即触发） |
| 和原数据或已生成数据完全重复（第 3、5、6 条） | > 10% |
| 审核不一致 | 任一类 > 30%（见 6.3） |
| 浅层探针（11 个表面特征的逻辑回归，平衡准确率） | 生成数据比原数据高 15 个百分点以上（原数据为 50.1%） |
| 平均词数 | 偏离原数据 50% 以上 |

第 4 条"照抄父样本短语"的比例单独报告。

### 6.3 审核（P1，已选定）

- **抽样**：每个生成标签抽 20 对，共 60 对，种子 20261104。展示方向随机，隐藏生成标签和父样本。
- **标注**：Pan-Yan-0 和 Claude 各自独立标注全部 60 对，可以填 E / F / B / O / U（U 表示无法确定）。
- **校验**：标注表必须恰好覆盖 60 个编号、没有重复、标签合法，否则判为 `invalid`。
- **每一类的判定**：
  - 抽样不足 20 对，或两人都给出确定标签且一致的项少于 **10** 个 → `insufficient`，不放行。这条低覆盖规则是事先定的。
  - 在两人一致的项里，和生成标签不同的比例超过 30% → `fail`。
  - 否则为 `pass`。
  - 同时报告分母、两人分歧数和"无法确定"的数目。
- **P2 的计算**也保留在代码里：裁决表必须覆盖全部待裁决项。但这次不用。
- **GPT 的补充审核**（如果做）：用隔离的上下文、看不到生成标签，结果单独报告，并注明它和生成器出自同一供应方。

### 6.4 放行门槛

- `manifest.csv` 只是候选。能不能进训练只看 `gate.json` 里的 `ready_for_training`。
- **审核结果和候选绑定**：`review_result.json` 记下 `manifest.csv`、`review_sheet.csv`、`review_key.json`、`report.json` 的哈希，任何一个变了，审核就失效（stale）。本试点只认 P1 的审核结果。
- **重建会清空旧结果**：在同一目录重建时，先删掉旧的审核、放行和裁决文件。
- **训练入口还要再核对一次**：`manifest.csv` 的 SHA-256 必须等于 `gate.json` 里 `bound_to` 的值，防止审核后清单被替换。
- 以下检查都是 `pass` 才放行：协议、失败批次、重复、探针、词数、审核。
- `fail`、`not_run`（例如缺 sklearn，探针没法跑）、`pending`、`invalid`、`insufficient`、`stale` 都不放行。
- **探针的解释边界**：探针和词数只能检查一部分表面特征和标签捷径。通过不等于"分布没有偏差"，报告里也不这样写。

## 8. 修改记录

### v5 → v6（对应 v5 试点没过停止条件；改生成方式）

- **按父样本仿写**：每个父样本 Rk 对应生成一对 Gk。提示词第 1–4 条要求 Gk 和 Rk 标签相同、两侧的关系方式和共享词的多少相同、长度和风格相近、内容换成别的场景（不改写、不翻译 Rk，不重用它的实词）。原来的"同一种变化不超过两对"和按批的长度统计段去掉了，因为构造方式和长度现在都跟着各自的父样本走。
- **分批**：每批 14 个父样本，按配额分层抽、顺序打乱。批次文件新增 `ref_labels`。父样本和 v4、v5 不同（那两版每批 13 个、不分层）。
- **格式检查**：第 k 对的标签必须等于 Rk。
- **跳过只差数量的父样本**：用 `label_conventions.number_pair` 判断，因为仿写它就会违反提示词第 6 条。
- **示例**：3 个格式示例换成 2 个手写的仿写示例（"参考对 → 新对"）。
- **补充规划**：一个父样本对应一对，所以父样本按组取。
- **诊断**：`diagnose_pilot.py` 增加构造类型对比，以及 Gk 和 Rk 构造类型相同的比例、实词重叠的分布。

为什么这样改：v5 说明，按标签自由生成时，生成器会自己选一种"标准"的构造方式（O 换一个词，单向删修饰语），再往提示词里加数字要求，就是对着探针的特征调参。仿写让每一对的构造方式都来自一个真实的父样本，分布自然跟着原数据走；抽出的 210 个父样本里，单向的删词占 40%、O 两侧没有共同词的占 30%，和原数据（45%、25%）接近。

代价和风险，事先写明：
- Gk 可能离 Rk 太近，变成换几个词的改写。提示词禁止重用实词，过滤会去掉照抄的短语；诊断报告 Gk 和 Rk 的实词重叠，只描述、不设门槛。
- 一个父样本对应一对。+1 全量按计划要约 2,200 对（含余量），只有 1,725 个家族，平均每个父样本要用约 1.3 次（有的签名 2 次），+2、+4 约 2.5 到 5 次。试点每个父样本只用一次；全量怎么重复使用，等试点过了再定。
- 这仍然只是提示词层面的约束，生成器照不照做，要看试点。

### v4 → v5（对应 v4 试点没过停止条件）

只改提示词：

- **新增"LENGTH AND STYLE OF THIS BATCH"一段**。`build_pilot.py` 的 `ref_stats` 从本批 13 个父样本的 26 个短语算出：平均词数、四分位数、最长的词数、以 a / an / the 开头的个数、同一对两侧词数差的平均。提示词要求：
  - 平均长度和参考短语相同，任何短语不超过本批最长的参考短语；
  - 同一对两侧的长度差和同标签的参考对差不多；
  - 以冠词开头的比例和参考短语差不多。
- **第 3 条**改为"照上面这一段写"；**第 7 条**的自查加上长度上限。
- **3 个格式示例**改短，也不再以冠词开头（原来 6 个短语里 5 个以冠词开头，平均 3.7 词）。

为什么这样改：

- 第 9 节的诊断显示，在当前的线性探针和特征分组下，长度这一组提供了主要的可见信号，而长度在 v4 里只有"和参考短语差不多"一句话。
- 15 批父样本的平均长度在 2.4–3.5 词之间，最长的在 5–10 词之间。所以长度要求按批写，不用全数据的统计。
- 新增的数值摘要（`ref_stats`）只用本批父样本、不读标签。但提示词本来就带着有标签的参考对，又要求对齐"同标签参考对"的长度差，所以整个 v5 的修改不是完全不用标签：它用的是本批父样本的标签。父样本都在本批可用折的 fit 里，没有用到额外的留出标签。
- 冠词开头的比例不是停止条件，也没有被探针用上（这一组特征在两边都是 33%，相当于瞎猜）。但这是很明显的分布差别，原数据 15–20%、生成数据 74–88%，所以一起改，结果只描述、不设门槛。

没有改的：父样本和配额（15 批逐项相同）、划分、过滤、停止条件和门槛、审核和放行。

### v3 → v4（对应 `debug_b02`）

只改提示词：

- **第 5 条（新增）**：不写只差一个数字或数量的对，例如 five lanterns / eight lanterns。
  - 原因：这个数据集对数量的标法是从训练标签里归纳出来的，大致是"数大的一侧推出数小的一侧"，读数类除外。如果写进提示词，等于把包括各折留出部分在内的全部训练标签信息带进生成，破坏可用折的隔离。
  - 不写进去、又让模型自由生成数量对，生成的标签很可能和数据集的标法相反（`debug_b02` 把它标成了 O）。
  - 所以干脆不生成这类对。代价是生成数据里缺少数量差异的例子。
- **第 7 条（新增）**：作答前自查每类的对数，以及每对都有三个字段。
  - 原因：三次调试里有两次格式不合格，一次漏了全部标签，一次少一对。按试点的停止条件，15 批里只要有 1 批重试后仍失败就要停下。

### v2 → v3（对应 `debug_b01` 的复核）

| GPT 指出的问题 | v3 的处理 |
|---|---|

### 为什么冻结 v4、不再改提示词

- 三轮调试里，明确的标签错误从 1 对（`debug_b01`）降到 0 对；剩下的都是"严格逻辑 vs 数据集近义标法"的边界，提示词再收紧，只会把生成的 E 推得比原数据更严格，第 9 节 `debug_b01` 后面已经写了这个取舍。
- 每轮只有 14 对，继续按调试样本改提示词，等于对很小的样本调参，改动的效果也说不清。
- 试点本来就有判断 E 质量的门槛：P1 审核里 E 类一致项和生成标签不同的比例超过 30% 就停（第 6.3 节）。所以 E 的问题交给试点来量，不在调试阶段预先下结论。

试点前固定两条口径，都只报告、不改过滤、不触发停止，在看到试点输出之前定下：

1. **只差数量的对**（提示词第 5 条）：用 `code/label_conventions.py` 的 `number_pair`（两侧各只差一个词，且两个词都是数字或数字词）统计违反的对数，按生成标签分开报告。只删掉数量词、或者数量词和别的修饰一起变的对（如 `third consecutive victory → victory`）不算违反。这类对不额外过滤，P1 审核时和其他对一样标注。
2. **多样性**（提示词第 2 条）：报告单向对里"text2 的词是 text1 的子集"的比例，以及其中只删一个词的比例；只作描述，用来解释 B1 和 B0 的比较。

**数量规则的来历（照 GPT 11-05 的意见如实记录）**：数量的标法是 Claude 此前在全部英语训练标签上检查时归纳的（`code/label_conventions.py`），这些标签包括各折的留出部分。v4 没有把这条规则写进提示词，但"不生成只差数量的对"这个设计决定本身是受那次全数据观察启发的，所以不能说生成侧完全没接触留出信息。报告里要区分两件事：没有把标签规则直接注入生成；方法选择受过数据观察的影响。从现在起流程冻结，不再根据留出结果调整提示词或过滤。

  O 两侧没有共同词的比例高于原数据（41% 对 25%）。抽出的 60 个 O 父样本里是 30%，所以生成器把一部分"部分重叠"的 O 写成了毫无共同词。
- **仿写的程度**：Gk 和对应的 Rk 构造类型相同的，E 81%、单向 89%、O 85%。Gk 和 Rk 的实词重叠：平均 Jaccard 0.03，85% 完全不重叠，没有一对 ≥ 0.5。所以没有出现"换几个词的改写"。

- 事先定的两条口径：只差数量的对 0 个；单向对里删词的 45 / 102（44%，原数据 44.8%），其中只删一个词的 31 对。

**解释边界**（GPT 11-06 的意见）：探针和构造类型通过，只说明这些表面特征和原数据对得上，不等于 NLI 标签的语义质量已经确认，也不保证训练有收益。语义质量看 P1。
