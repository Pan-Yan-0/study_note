## 想法 1：深度剪枝和宽度剪枝，谁更好？结论为什么会反过来

### 观察

- ShortGPT（不做恢复训练）：删整层（深度剪枝）比 LLM-Pruner、SliceGPT（宽度剪枝）好。
- Minitron（蒸馏恢复后）：宽度剪枝更准（Llama 3.1 8B → 4B：MMLU 60.5 对 58.7，GSM8K 41.2 对 16.8），深度剪枝更快（吞吐 2.7 倍对 1.8 倍）。

### 方法：结论冲突时，先把所有不同之处列出来

每一处不同都是一个候选原因。

| 不同之处 | ShortGPT | Minitron |
|---|---|---|
| ① 恢复方式 | 主结果不恢复 | 蒸馏，94B token |
| ② 剪掉多少 | 约 27%（Llama2-7B） | 深度剪枝删一半（32 层 → 16 层）；宽度剪枝 8B → 4.5B |
| ③ 深度剪枝怎么选层 | 按 BI 挑层 | 删连续的一段（第 16–31 层），按 Winogrande 选 |
| ④ 宽度剪枝用的方法 | LLM-Pruner、SliceGPT（LLM-Pruner 原本的恢复被去掉了） | 自己的方法，按激活值打分 |
| ⑤ 模型 | Llama2、Baichuan2 | Llama 3.1 8B（训练了 15T token）、Mistral NeMo 12B |
| ⑥ 评测 | 14 个任务，多数是多选题；基线数字抄自 LaCo | MMLU、GSM8K、HumanEval 等，全部自己跑 |

例：② 也可能单独让结论翻转。剪 27% 时深度剪枝还撑得住，剪 50% 时也许就撑不住，这和恢复方式无关。

### 检验"恢复方式"这一个原因的实验设计

- **固定**：模型、剪枝比例、深度剪枝的选层方法、宽度剪枝的方法、评测；还有恢复用的数据、训练量，以及恢复后的模型大小。
- **只改**：恢复方式。候选：不恢复、LoRA、用轻量 MLP 替换被删的层再训练（ShortGPT §4.6）、蒸馏（Minitron）。
- **每种恢复方式，深度和宽度各做一次**：4 × 2 = 8 组。
- **判定结论翻转**：在同一个模型上，不恢复时深度剪枝更好，加上某种恢复后宽度剪枝更好，两个条件同时出现。

注意：
- 用轻量 MLP 替换会把参数加回去（ShortGPT Table 6：删除比例从 27.1% 变成 24.0%），模型大小要对齐。
- 恢复方式里还混着两个变量：训练哪些参数（LoRA / 全量），用什么训练信号（交叉熵 / 蒸馏）。要分开控制。

### 一个衍生的想法

如果加上恢复后宽度剪枝更好，可能说明"深度剪枝的恢复还有提升空间"。但同一个结果还有另一种解释：删掉整层，丢掉了恢复训练也补不回来的东西（容量真的少了）。要区分这两种解释，需要新的实验。
