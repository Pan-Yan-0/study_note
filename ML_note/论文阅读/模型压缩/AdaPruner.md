## 2. 两篇论文的重要性指标

| | ShortGPT：BI | AdaPruner：泰勒重要性 |
|---|---|---|
| 衡量什么 | 这一层把输入改变了多少 | 把参数置为 0 以后，损失变化多少 |
| 怎么算 | 1 − 输入和输出的平均余弦相似度 | 一阶近似：\|梯度 × 参数值\|；二阶还要加 Hessian（用 Fisher 信息近似） |
| 要不要梯度 | 不要，只做前向 | 要：先在无标签文本上算预测下一个 token 的损失（公式 1），再求梯度 |
| 粒度 | 整层 | 权重向量（粗）和权重元素（细），再汇总到耦合结构组 |

小例子：某个权重 θ = 0.5，损失对它的梯度是 0.2，一阶重要性是 |0.2 × 0.5| = 0.1。

ShortGPT 在引言里批评"有的剪枝方法需要梯度信息"，指的就是这一类方法。

### 一阶泰勒重要性

想法：把一个参数置为 0，损失大约变化多少？泰勒展开给出近似：

- 损失的变化 ≈ 梯度 × 参数的变化量：ΔL ≈ g × Δθ
- 置为 0 时 Δθ = −θ，所以 ΔL ≈ −gθ；重要性 I = |gθ|

| 权重 | θ | g | ΔL ≈ g × (−θ) | I = \|gθ\| |
|---|---|---|---|---|
| A | 0.8 | 0.05 | −0.04 | 0.04 |
| B | 0.1 | 0.6 | −0.06 | 0.06 |
| C | −0.5 | 0.2 | +0.10 | 0.10 |

- 按泰勒重要性先剪 A；只看权重大小 |θ| 会先剪 B。两种做法选的不同。
- 为什么要看梯度：梯度的**大小**是损失对这个参数的敏感度。重要性 = 敏感度 × 改动有多大。A 权重大但不敏感，B 权重小但很敏感，只看权重会错删 B。
- ΔL 带符号，I 取绝对值，是两样东西。
- 梯度来自校准集上预测下一个 token 的损失，只算梯度、不更新参数；比 BI 多一次反向传播。
- 它只是局部近似：把很大的权重直接置 0 是一大步，近似可能不准，所以公式 (2) 还加了二阶项。

**组合多个指标、或者学出一个判断器？** AdaPruner 本身就是把粗、细粒度指标按系数组合再搜索；也可以给每个结构配可学习的开关（mask）来训练，例如 Sheared LLaMA。代价是更贵：ShortGPT 的卖点是一次前向就够，AdaPruner 是多花搜索代价换来更好的选择，并不是更快。

## 3. 第二遍（上）：方法和搜索空间

### 3.1 读方法前要懂的四个概念

| 概念 | 要点 |
|---|---|
| 校准数据 | 只用来给结构打分（算梯度），不用来训练。AdaPruner 认为选哪几段文本会影响打分，所以也去搜 |
| 依赖组（耦合结构，沿用 LLM-Pruner） | 宽度剪枝要一组一起删。删第 j 个注意力头：q、k、v 投影删这个头产生的 128 **行**，o_proj 删读取这个头的 128 **列**；共享的输入 x 和残差的 4096 维不删。LLaMA-7B 一个头的组共 4 × 128 × 4096 = 2²¹ 个参数。`nn.Linear` 的权重形状是 [输出, 输入]，行对应输出，列对应输入 |
| 向量级与元素级泰勒 | 向量级 $I(W)=\lvert\sum_k g_k w_k\rvert$：一组同时删时的损失变化，正负会抵消。元素级 $I(w_k)=\lvert g_k w_k-\tfrac12 w_k H_{kk} w_k\rvert$，$H_{kk}\approx g_k^2$（Fisher 近似），每个权重单独算，再聚合 |
| 贝叶斯优化与 TPE | 目标函数 f(配置) = 剪完后的 PPL，每次评估都很贵。TPE 把已试过的配置按结果分成好组和差组，下一次选"在好组里占比 ÷ 在差组里占比"最大的取值 |

**聚合**：一个依赖组有几部分（q、k、v、o），每部分各有一个分数，要合成一个分数才能排序：求和、乘积、最大值，或只看最后一部分。合成方式不同，删掉的结构就可能不同。

### 3.2 搜索空间（Solution Space for Structured Pruning、Implementation Details、附录 B）

每次试验同时定下所有旋钮，再用剪完的 PPL 评价整个组合。

| 旋钮 | 可选值 | 位置 |
|---|---|---|
| 校准数据 | BookCorpus，过滤掉信息少的短文本；选 10 个样本，每个 128 token。**怎么表示"选哪 10 个"、候选池多大，论文没写** | Solution Space、Implementation Details、附录 B |
| α₁、α₂（粗粒度、细粒度的比重） | [0, 1] | Implementation Details |
| 聚合方式 | 求和、乘积、最大值、只看最后一个 | 公式 5 附近 |
| 对齐因子 | 原文写作 (e5, e6, e7)、(e-2, e-3)、(1e-4)，**三组各作用在哪个分数上没写清** | Implementation Details |

**对齐因子**：两种分数的数量级可能差很多（例如 0.0002 和 30），直接加权求和时小的那个几乎不起作用，α 就失去意义。先乘一个系数（如 10⁵）把它们调到同一量级，α 才能真正调比重。道理同特征缩放。

### 3.3 每次试验做什么、要花多少（Adaptive Pruning via Bayesian Optimization、Implementation Details、图 2）

1. 贝叶斯优化（BO-TPE）选出一组配置：校准数据、α₁、α₂、聚合方式、对齐因子。
2. 用这组配置给依赖组打分，剪掉 20%。
3. 在 WikiText-2 和 PTB（较小的评测子集）上测剪完的 PPL，作为目标函数的值，返回给贝叶斯优化。**不做 LoRA。**
4. 收敛后（论文说不到 150 次；随机搜索约 300 次），用最好的配置剪一次，**最后只做一次** LoRA 恢复（Alpaca，2 轮，batch 128，学习率 1e-4），再报告零样本常识任务和 PPL。

图 2 也是这样画的：剪枝 → 评测（WikiText-2、PTB）→ 贝叶斯优化，构成循环；微调单独放在循环外。

**成本粗估**（论文没有报告总搜索时间，以下是我们的估计）：
- 每次试验按"剪枝约 5 分钟 + 测 PPL 约 2 分钟"算：150 次约 17.5 小时，300 次约 35 小时。
- 训练时间的粗估规则：每个 token 约 6 × 参数量 FLOP。LoRA 恢复：约 2000 万 token × 6 × 5.4×10⁹ ≈ 6.5×10¹⁷ FLOP，按 3090 实际约 30 TFLOPS 算，约 6 小时（量级估计）。
- 如果每次试验都做 LoRA 再测准确率：150 × 约 6 小时 ≈ 38 天，不可行。所以目标函数只能用剪完直接测的 PPL。
- **按这个估计，搜索本身比最后的恢复贵约 3 倍。**"同样的时间花在搜索上还是恢复上更划算"值得一问。

### 3.4 第二遍发现的问题

| 问题 | 说明 |
|---|---|
| 选择偏差 | 搜索用 WikiText-2 / PTB 的 PPL 挑配置，报告里也有这两个 PPL，像拿练习过的题来考试，PPL 那几列的提升要打折扣。主要结论看的是 7 个零样本任务的平均准确率（20% 时 61.44% 对 LLM-Pruner 60.07%），这些任务没参与搜索，受影响较小；但没有报告多次运行的方差 |
| 只剪第 4–29 层 | 首尾的层（第 0–3、30–31 层）不剪。这沿用了 LLM-Pruner 的设置，和 ShortGPT 测到"首尾层 BI 偏高"是同一现象的不同证据。剪哪些层是人工定的，不在搜索空间里 |
| 延迟 4.93 秒 → 2.40 秒 | LLaMA-7B，3090，剪 20%（参数降 19.4%，MACs 降约 20%），序列长度 64。剪掉约 20% 的参数和计算量，不论访存受限还是计算受限，正常上限都在约 1.25 倍，报告的约 2 倍对不上。测量条件（batch、精度、重复次数、预热）没写清，存疑 |
| 剪的单位 | 正文只说"依赖关系自动识别并分组耦合结构"，没写是头还是通道。图 2 示意为宽度剪枝（LayerNorm 和注意力都按通道变窄一部分），但图里省略了 MLP |

**MACs**：乘加运算次数，一次乘加约等于 2 FLOP，衡量计算量。

### 3.6 搭桥：把 BI 删层实验里的 BI 换成泰勒重要性

| 步骤 | BI | 泰勒（元素级一阶 \|g·w\|） |
|---|---|---|
| 准备 | 校准数据 input_ids | 另外准备 labels（= input_ids，模型内部错位算下一个 token 的交叉熵） |
| 前向 | `no_grad` 下前向，钩子抓每层输入输出 | 不能 `no_grad`；前向得到 loss |
| 反向 | 不需要 | `loss.backward()`，权重的 `.grad` 里是梯度 |
| 算分数 | 1 − cos，累加 | 对每个权重算 \|g·w\|，按组或按层求和，累加进分数表 |
| 清理 | 不需要 | `model.zero_grad()` 再处理下一个 batch |

- **两种累加方式结果不同**：先把所有 batch 的梯度累积起来再算 \|g·w\|（梯度会正负抵消），或者每个 batch 先算分数再相加（不抵消），道理同三角不等式。
- **显存**：Qwen3-8B FP16 的梯度和权重一样大，16.38 GB；权重加梯度共 32.76 GB，两张 T4（约 31 GB）连激活都还没算就放不下。
- **时间**：AdaPruner 的校准是 10 × 128 = 1,280 个 token，BI 实验是 64 × 2048 = 131,072 个（约 102 倍）。BI 只做前向用了 2.3 分钟；泰勒做前向加反向约 3 倍，按 AdaPruner 的校准量约几秒。**泰勒打分卡在显存，不在时间。**
- **放不下的办法**：给每个参数挂梯度钩子，梯度一算出就转成分数并释放；只对要打分的层打开 `requires_grad`，或分批反向（用时间换显存）；梯度检查点省激活；换小模型（结论不一定能迁移到 8B）。注意：损失只是一个标量，反向真正占显存的是前向保存的激活；某层的梯度要从损失一路反传经过它后面的所有层才能算出。
- 亲手实现见 [泰勒重要性小实验](../../原理笔记/PyTorch/泰勒重要性小实验学习笔记.md)。

## 5. 易混点

| 容易说错的 | 正确说法 |
|---|---|
| 每次试验里都做了 LoRA | 搜索时每次只剪枝加测 PPL；LoRA 只在最后做一次 |
| 零样本常识任务是搜索的目标 | 搜索的目标是 WikiText-2 / PTB 的 PPL；零样本任务只在最后报告 |
| 搜索挑配置会让"参数"适配评测集 | 搜索不训练参数，是被挑出的**配置**偏向评测集（选择偏差） |
| q、k、v 删一个头时行和列都要删 | 只删这个头产生的行；列对应共享的输入 x，不能删 |
| sum / max / prod 是选校准数据的方式 | 它们是依赖组内部把几部分分数合成一个的聚合方式；校准数据是另一个旋钮 |
| α₁、α₂ 和对齐因子是一回事 | α 决定两种分数各占几成；对齐因子先把两种分数调到同一量级 |
| 贝叶斯优化是数学上推出最优解 | 公式 (6) 把目标写成优化问题，但求解靠反复"选组合 → 剪枝 → 测困惑度"的黑盒搜索，类似超参数搜索 |
| "单一指标"说不通，明明有好几种 | 以前的方法各自固定只用一种；AdaPruner 把几种按系数组合起来再搜索 |
| WikiText2、PTB 是分类任务 | 它们测困惑度，越低越好（表头的 ↓） |
| 规模定律是数学证明 | 规模定律是用实验数据拟合出的经验规律 |
