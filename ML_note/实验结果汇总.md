## 1. 本仓库的实验结果

### 1.1 SST-2：指令学习与 DeBERTa 微调对照

任务来自导师的《1-使用大模型进行指令学习》：不训练模型，用 Alpaca 格式的指令让模型直接回答 -1 或 1，在 GLUE SST-2 验证集全部872条（正面444、负面428）上统计准确率；另用 DeBERTa 微调做对照。详见 [SST2 目录的 README](实验/SST2/README.md)。

- Gemma 和 DeepSeek（R7）、Qwen 4b、Qwen 9b 都没有显著差别（p = 0.38、0.31、0.090）。Phi-4、Llama 和 Qwen 4b、9b 差不多（p = 0.17–0.78），但都显著低于 DeepSeek（p = 0.007）。Mistral 显著低于 Qwen 4b、9b、DeepSeek、Gemma 和 Phi-4，和 Llama 差别不显著（p = 0.15）。
- Mistral 偏向判负面，Llama 偏向判正面。Phi-4 的26条无效全是回答 `0`。Mistral 把负面写成 “-1 (Negative sentiment)”，旧解析规则不认，曾只有39.68%；规则补上这种写法后为90.60%，用新规则重新判分，R7–R11 没有一条改变。
- cot 模板（前200条）：Gemma 95.0% → 95.0%，Phi-4 93.0% → 93.5%，都没有差别；Mistral 91.0% → 68.5%、Llama 92.5% → 83.5%，主要因为很多回答没有按规则写出明确答案（无效56条、23条）。就算把这些回答最后一行里的 ±1 都算作答案，也只有84.0%、87.0%，仍低于 basic。

- 后来在另一个 Kaggle 会话里用同样的设置重跑了一次 R8，872条预测完全相同。

R9 用 DeepSeek 跑了材料里的三个模板（basic、要求逐步推理的 cot、再加角色设定的 role_cot）× 思考开关，每组872条：

| --- | ---: | ---: |
| basic | 95.18%（830） | 96.10%（838） |

- 开思考：basic +0.92、role_cot +0.57 个百分点，cot −0.23 个百分点（对8192那次），McNemar 检验都不显著（p = 0.096、0.27、0.75）；模板之间也没有显著差别。7次运行两两比较的21对里，唯一 p < 0.05 的是关思考的 basic 对 cot + 思考的重复运行（p = 0.035），同一设置的另一次运行只有 p = 0.26，不能当作显著。

### 1.2 IMDB：Qwen3-4B-Base 指令微调

[Qwen3-4B Notebook](实验/IMDB/notebooks/imdb-qwen3-4b-sft.ipynb)：Alpaca 指令模版，模型在 `### Response:` 后接 `positive` 或 `negative`；训练时只在这一个答案 token 上算交叉熵，预测时读两个答案词的概率之比。fp16 冻结底座，q/k/v/o/gate/up/down 七个投影层加 LoRA（$r=16$，$\alpha=32$）；影评超过512个 token 时保留开头128 + 结尾384；1轮，有效 batch 16，学习率1e-4，前5%步数warmup。划分与 2.2 相同。环境为 Colab 单张 T4，训练222分钟。

| 实验 | 验证 accuracy | 验证 AUC [95% 区间] | Kaggle AUC |
| --- | ---: | --- | ---: |
| 零样本（训练前） | 0.9440 | 0.984729 [0.9816, 0.9877] | — |
| 指令微调后 | 0.9686 | 0.994138 [0.9924, 0.9957] | 0.99493 |

- 零样本的验证 AUC 已高于 R4（0.979953），但两个答案词平均只占答案位置43.6%的概率；微调后占99.98%，错例从280条降到157条（McNemar 精确检验 p ≈ 5×10⁻¹⁹）。
- 与 R2–R4 相比，底座（40亿参数的解码器）、输入长度（512对128–256）和损失形式同时不同，Qwen3 的预训练语料也可能包含 IMDB 影评，差距不能只归因于训练方法。区间是按条重抽样2,000次得到的，详见 [IMDB README](实验/IMDB/README.md) 第4节。

### 1.3 IMDB 情感分析：BERT 全量、BERT LoRA、DeBERTa-v2-xxlarge LoRA

三个模型由[官方 Trainer Notebook](实验/IMDB/notebooks/imdb-three-models-official-trainer.ipynb)一次依次训练，共用条件：分层划分 20,000 训练 / 5,000 验证（`random_state=42`）；3个epoch；AdamW，学习率2e-5，权重衰减0.01，线性衰减，前10%步数warmup；fp16；有效 batch 16；每轮验证，按验证AUC选最佳轮次；提交正类概率。环境为 Kaggle 单张 T4。

| 实验 | 底座与训练方式 | 长度 / batch × 梯度累积 | 可训练参数 | 最佳轮次 | 验证 accuracy / AUC | Kaggle AUC |
| --- | --- | --- | ---: | ---: | --- | ---: |
| BERT 全量 | `bert-base-uncased`，全量微调 | 256 / 8 × 2 | 109,483,778 | 2 | 0.9206 / 0.974062 | 0.97522 |
| BERT LoRA | 同一BERT；query、value加LoRA（$r=8$，$\alpha=16$，dropout 0.05）；分类头一并训练 | 256 / 8 × 2 | 296,450 | 3 | 0.8766 / 0.949744 | 0.95315 |
| DeBERTa-v2-xxlarge LoRA | `microsoft/deberta-v2-xxlarge`；FP16冻结底座；query_proj、value_proj加LoRA（同上）；pooler与分类头一并训练 | 128 / 16 × 1 | 4,723,202 | 3 | 0.9334 / 0.979953 | **0.98294** |

逐轮验证 AUC：BERT 全量 0.971985 → 0.974062 → 0.973945；BERT LoRA 0.935947 → 0.947399 → 0.949744；DeBERTa 0.975361 → 0.979054 → 0.979953（逐轮 loss 与 accuracy 见[IMDB README](实验/IMDB/README.md)和[逐轮CSV](实验/IMDB/metrics/pretrained_three_models_epochs.csv)）。显存峰值（allocated）2.69 / 1.24 / 4.44 GiB，用时约18分钟 / 14分钟 / 2.3小时。

- **全量微调对 LoRA（R2 对 R3）**：同底座、同划分、同长度、同学习率，只差训练方式。LoRA 只训练0.27%的参数，验证AUC低0.024，Kaggle AUC低0.022；它的验证AUC到第3轮仍在上升，而学习率沿用了全量微调的2e-5，论文 GLUE 实验里 RoBERTa-base 的 LoRA 学习率是4e-4–5e-4（1.8节）。学习率偏小、训练不足是候选解释，尚未验证。
- BERT 全量第2轮后验证loss上升（0.2525 → 0.3468），按AUC选回第2轮。
- DeBERTa-v2-xxlarge 最好，但底座、分词方式和截断长度同时不同，差距不能只归因于 LoRA。
- 可训练参数与公式一致：BERT 为 $2\times12\times8\times(768+768)=294{,}912$ 个 LoRA 参数加分类头1,538；DeBERTa 为 $2\times48\times8\times(1536+1536)=2{,}359{,}296$ 加 pooler 2,360,832 与分类头3,074。
- 三个模型的 Kaggle AUC 都比验证AUC高0.001–0.003。R1 提交的是0/1标签，与这里的概率 AUC 不能相减；按准确率看，BERT 全量的验证0.9206比六模型最好的约0.90高2个点左右（两组的验证划分不同）。

更早一次 BERT 全量微调用的是[单模型 Notebook](实验/IMDB/notebooks/imdb-bert-deberta-lora.ipynb)与[共用代码](实验/IMDB/code/imdb_pretrained.py)：不分层划分（`random_state=0`），没有学习率调度，其余设置相同，没有提交分数。三轮验证 accuracy 0.9090 / 0.9140 / 0.9128，AUC 0.972725 / 0.973270 / 0.973673（[日志CSV](实验/IMDB/metrics/bert_full_kaggle_report_2026-10-11.csv)），与上表的 BERT 全量接近。

### 1.7 GMCM：缺失鲁棒性

文本缺失扫描（v1 / v2 文档，与 base 的同种子配对差，单位为宏F1百分点，括号内为5种子 t 区间，另附差值为正的种子数 / 5）：

|---|---|---|---|---|

| mg2 − base（测试） | −0.2 [−0.8, 0.4] | 0.0 [−0.6, 0.5] | +2.2 [−1.9, 6.3]，2/5 | +0.2 |
| mg − base（验证） | +1.2 [0.3, 2.1] | +3.2 [1.9, 4.5] | +8.0 [5.5, 10.5]，5/5 | −0.5 |

v3 的补验（90%文本缺失，与 base 的差，宏F1百分点，括号内为视频区间）：

| | 测试 | 验证 |
|---|---|---|
| mg（v1 门控） | +5.9 [4.2, 7.6]，5/5 个种子为正 | +8.0 [6.2, 9.6]，5/5 |
| joint（常规缺失增广训练） | +4.7 [3.6, 5.8]，5/5 | +4.9 [3.4, 6.2]，4/5 |
| mg2（单调门控） | +2.2，2/5（种子区间跨 0） | +2.6，2/5 |

- mg 在 90% 文本缺失时的收益（测试集 +5.9 为 v3 文档、+6.0 为 v1 / v2 文档）里，joint（常规缺失增广训练）已占 +4.7，v3 文档据此认为大部分收益来自“用缺失样本训练”，而不是 MG 结构；MG 在 joint 之上只多约1–3个点，独有的优势是完整路径逐位不变。mg2 的 +2.2 不显著（2/5 个种子为正）。
- “残余语义作支点”的假设不成立：收益并不随剩余词数增加（测试集 mg：剩1个词 +9.7，2个 +5.0，3–4个 +4.2，≥5个 +8.0）。更符合数据的解释是 base 对“几乎为空但不为零”的文本表示会系统性误判（分布外）。
- 文本整段缺失（100%）时，谁都没有收益。v1 / v2 文档的表述是：补偿收益集中在“仍保留少量文本”的严重缺失条件，轻中度缺失时没有观察到稳定收益；这与上表的测试集一致（50%、75% 的区间跨0），但验证集上 mg 在50%、75% 的差值为 +1.2、+3.2（区间不含0）。
- 63档 PM 面板（≤50%连续缺失）上 base 平均只掉约2个F1点（验证0.620→0.599，测试0.648→0.628）；没有“去掉掩码池化”的对照，不做因果归因。

### 2.2 不能直接比较的地方

1. **可训练参数的口径。** 论文的 $\lvert\Theta\rvert$ 只数 LoRA 增量，表2的0.3M、0.8M与公式复算一致，不含任务头；本仓库的数字含任务头：GMCM v3.1 约7.68M，IMDB 的 BERT LoRA 为296,450（LoRA 294,912 + 分类头1,538），DeBERTa-v2-xxlarge LoRA 为4,723,202（含 pooler 与分类头）。
2. **指标。** GLUE 的 Avg. 是8项（准确率、MCC、Pearson，均乘100）的简单平均；GMCM 用宏F1、Acc-3、MAE；IMDB 用 accuracy 和 AUC。同一数字（例如0.89）在不同指标下含义不同。
3. **验证集、测试集与排行榜。** IMDB 的验证 AUC（5,000条）与 Kaggle 测试集 AUC（25,000条）评价数据不同；六模型提交0/1标签、预训练模型提交概率，两组 Kaggle AUC 也不能相减。GMCM 的验证、VC、测试三个集合要分别列明，且所有模型的测试 MAE 都高于验证 MAE。
4. **统计方式。** 论文：GLUE 为5种子中位数，GPT-2 为3种子均值，GPT-3 只给典型波动。本仓库：阶段A是单种子；GMCM 中单种子、多种子指标均值、集成、最终部署单模型是四种不同的东西；v1 / v2 文档的区间是5个种子的 t 区间，v3 起的区间是按源视频的 bootstrap，两种区间不能混用（例如 90% 文本缺失下 mg − base 在 v1 / v2 文档中为 +6.0 [4.4, 7.6]，在 v3 文档中为 +5.9 [4.2, 7.6]）。
5. **方案比较与控制变量。** 从 BERT + LoRA 到 DeBERTa + LoRA，主干、秩、任务损失、EMA 与选模方式同时变化；IMDB 的 BERT 与 DeBERTa-v2-xxlarge 在底座、分词和长度上也同时不同。这些都不是只改变 LoRA 的对照。
6. **全量微调对照。** 论文的全量微调基线多数来自既有工作（`*`）。本仓库唯一同条件的配对是 IMDB 的 BERT 全量对 BERT LoRA（单次运行，LoRA 用了全量微调的学习率）；GMCM 只比较了冻结 BERT 与 LoRA。
7. **IMDB 的两次 BERT 全量。** 官方 Trainer Notebook 分层划分（`random_state=42`），更早的共用代码版本不分层（`random_state=0`）且没有学习率调度；两次的验证集不同。
8. **指令学习与微调。** R7–R11 和 R14 不训练任何参数，每种设置单次运行（开思考时同一设置重跑结果也会不同）；论文 SST-2 列是在训练集上微调、5个种子取中位数、每次取最佳 epoch 的结果；R12 是本仓库的微调对照，3个种子取均值、报告最后一步，不挑 epoch。三者都在 SST-2 的872条验证集上评测，可以对照量级，但不是控制变量的比较；R7 与 R8 之间、R10 的各尺寸之间也同时改变了模型大小、量化方式（Q8_0 与 Q4_K_M）和推理服务。R11 只用前200条。
