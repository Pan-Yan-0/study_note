## 1. 上下文：模型能看到什么

### 1.1 生成时只能看到已经存在的 token

解码器一个 token 一个 token 往后写。写第 n 个 token 时，注意力只能看到第 1 到第 n−1 个，后面的还不存在。

```text
位置：1 … 50   51 … 450          451 … 460       461
内容：[指令]   [4 条带答案的例子]  [要判断的影评]  ### Response: → 在这里生成答案
```

- 少样本的例子要放在问题前面，`### Response:` 放在最后、紧挨着答案的位置。例子如果写在 `### Response:` 后面，模型会以为回答已经开始了，格式就乱了，“读第一个 token 的概率”也会失效。
- 聊天时，你的消息不管把信息放在开头还是结尾，都在我回复的前面，所以对我没区别。“只能看前面”是相对于正在生成的那个 token 说的，不是指你消息内部谁先谁后。
- cot 有用，靠的是“推理写在答案前面”这个顺序：写答案时，注意力能用上前面的推理。反过来“先给答案再解释”，答案生成时解释还不存在，解释只是为已经写下的答案找理由，效果接近 basic。

### 1.2 请求之间没有记忆，推理也不是微调

| | 推理（聊天、跑 SST-2） | 微调（训练） |
|---|---|---|
| 做什么 | 只有前向计算 | 前向计算 + 损失 + 反向传播 |
| 参数 W_q、W_k、W_v…… | 完全不变 | 被梯度更新 |
| 输入的 token、q、k、v、x | 这次请求现算，用完就丢 | 也是现算现丢 |
| 能留到下一次的东西 | 没有 | 改过的参数 |

- 一次请求之内，模型能通过注意力用上全部上下文；请求结束什么都不留。跑 SST-2 时，每条影评都是一次独立请求，所以少样本的例子每条请求都要重复带上。
- 聊天能“记得”前面，是因为每一轮都把之前的整段对话重新发一遍，放在这一轮输入的前面。
- Ollama 和 DeepSeek 会缓存相同开头已经算好的 k、v，下次不用重算，DeepSeek 对命中缓存的输入也收费更低。这只是省计算，结果和重算一遍完全一样，不是学习。
- **KV cache 存的是激活，不是参数。** 生成时，每个 token 在每一层算出的 k、v 留在显存里，生成后面的 token 时直接拿来用。存的是这些 k、v 向量（提示词的 token 也算在内），不是 token 本身。
  - 参数（W_q、W_k、W_v……）是训练出来的，所有输入共用，推理时不变。
  - 激活是这一次输入算出的中间结果，例如 k = x · W_K 中的 k。
  - 开新对话时，KV cache 从零重算，参数还是原来那些。

### 1.3 提示内部的位置：跟模型能力有关的软影响

- 长上下文里，开头和结尾的信息用得最好，中间的最容易被忽略（Liu 等，2023）。
- 少样本例子换个顺序，准确率可能从接近最好掉到接近随机（Lu 等，2022）。
- 模型倾向于跟着最后几条例子的答案走，也倾向于跟着例子里出现最多的答案走（Zhao 等，2021），所以例子要正负各半、打乱顺序。

“只能看已经存在的 token”是硬规则，所有解码器都一样；这三条是软影响，模型越小越明显。

### 1.4 agent：在模型外面管理上下文

| 组成 | 做什么 |
|---|---|
| 模型 | 读上下文，决定下一步说什么、做什么；参数固定 |
| 工具 | 运行命令、读写文件、上网、调用 API |
| 循环 | 模型要做一件事 → 外面的程序去做 → 结果放回上下文 → 再调用模型 |
| 上下文管理 | 每次调用前决定放什么：对话历史和工具结果；太长了就压缩成摘要；长期的东西写进文件（如 `AGENTS.md`），新会话开始时读回来 |

agent 的“记忆”和“学习”都靠往上下文里放什么，参数一次都不变。上下文要压缩、要挑着放，有四个原因：

1. 上下文窗口有上限，放不下。
2. 中间的信息容易被忽略，压缩后把重点放在开头或结尾更好。
3. 噪音：softmax 给每个 token 的权重都大于 0、加起来等于 1。无关的 token 越多，分走的权重越多，有用的 token 分到的越少，混进 Δx 的杂质越多。在数学题里加一句无关的话，正确率会明显下降（Shi 等，2023）。
4. 成本和速度：每调用一次都要把整个上下文重新发一遍。调用 50 次、每次带 10 万 token，就是 500 万输入 token，约 5 元；自注意力的计算量和长度的平方成正比，上下文长一倍，注意力计算约变成 4 倍。

## 2. 成本和时间（§5.4）

> 费用 = 输入 token 数 × 输入单价 + 输出 token 数 × 输出单价
>
> 用时 = 请求条数 × 每条秒数 ÷ 同时发几条

DeepSeek 单价：输入每百万 token 1 元，输出 4 元；工作日 9–12 点和 14–18 点为高峰，价格翻倍。SST-2 实测（872 条，8 路并发）：

| 设置 | 每条输入 token | 每条输出 token | 每条秒数 | 872 条用时 | 872 条费用（空闲时段） |
|---|---:|---:|---:|---:|---:|
| basic，不思考 | 120 | 2 | 1.0 | 约 2 分钟 | 0.11 元 |
| basic，思考 | 146 | 80 | 1.4 | 约 3 分钟 | 0.41 元 |
| cot，不思考 | 128 | 124 | 1.8 | 约 3 分钟 | 0.54 元 |

- 不思考的 basic，钱几乎都花在输入上；开思考或用 cot，输出成了大头，输出单价是输入的 4 倍。
- IMDB 测试集 25,000 条、basic 不思考：输入 25,000 × (300 影评 + 110 指令) = 1,025 万 token，输出 2.5 万 token，约 10.35 元（高峰约 20.70 元）。用时：API 8 路约 52 分钟；Ollama 单路按每条 0.4 秒估计约 2.8 小时。
- 少样本也加钱：4 条短例子约多 400 个输入 token，25,000 条就是多 1,000 万 token，约多 10 元。

## 3. 解码器的结构

### 3.1 两种“mask”

| | MLM 的遮词 | 注意力掩码 |
|---|---|---|
| 改的是哪里 | 输入：把 15% 的词换成 [MASK] | 注意力分数：softmax 之前把某些格子填成 −1e6 |
| 作用 | 出题：让模型猜被遮住的词 | 规定每个词能看到哪些词 |
| 谁在用 | BERT 预训练；DeBERTa-v3 的生成器 | 所有模型 |

注意力掩码又分两种：padding 掩码（补齐的空位谁都不能看）和因果掩码（第 i 个词只能看第 0 到第 i 个）。因果掩码只按位置决定，和语义无关，对每个句子都是同一个下三角。

`[CLS] not bad` 某一层某个头的分数，双向和因果的 softmax 权重：

| | 分数 | 双向权重 | 因果权重 |
|---|---|---|---|
| [CLS] 行 | [1.0, 2.0, 0.5] | [0.231, 0.629, 0.140] | [1, 0, 0] |
| not 行 | [0.5, 1.0, 1.5] | [0.186, 0.307, 0.506] | [0.378, 0.622, 0] |
| bad 行 | [0.2, 2.0, 1.0] | [0.108, 0.652, 0.240] | [0.108, 0.652, 0.240] |

遮的方式由训练任务决定，目的都是不让模型偷看答案：MLM 的答案是被遮的词本身，所以遮输入；解码器预训练是因果语言建模，第 i 个位置预测第 i+1 个词，所以要挡住后面的位置。DeBERTa-v3 是编码器，预训练任务是 RTD（判断每个词有没有被换过），答案不藏在后面的词里，所以用双向注意力，只有 padding 掩码。

### 3.2 一层解码器

以 GPT-2 这类标准解码器为例（Qwen 的具体版本会有改动）：

```text
词嵌入 → N 层 × [ RMSNorm → 带因果掩码的自注意力（Q、K、V、W_o）→ +残差
                  → RMSNorm → 前馈层 → +残差 ]
       → 最后一个 norm → LM 头 → 每个位置预测下一个词
```

和 BERT 的层相比有三处不同：注意力加了因果掩码；归一化放在子层之前（Pre-LN）；最后接 LM 头，不是分类头。

```text
BERT（Post-LN）：x → 子层 → x + Δx → LayerNorm        归一化在残差加法之后
Qwen（Pre-LN）： x → Norm → 子层 → Δx，然后 x + Δx    归一化在子层之前，加完不再归一化
```

两个子层都是这样，所有层跑完以后 Qwen 再做一次最后的 Norm。子层内部一样：W_o 在并头之后、残差之前。每层有一个 W_o（注意力子层）和一个 W₂（前馈子层），残差和归一化各两次；36 层的 Qwen 有 36 个 W_o。LoRA 只是在 W_o 等矩阵旁边加一条支路，原来的矩阵还在。

**为什么大模型改用 Pre-LN**：Post-LN 每次加完残差都要过一次 LayerNorm，梯度从顶层往回传，每一层都得穿过归一化，层数一多，前面几层的梯度容易不稳，要靠 warmup 慢慢起步。Pre-LN 的残差这条路 x → x + Δx 从底到顶不经过归一化，梯度能沿着它直接传回最前面，几十层也训得稳。

**RMSNorm**：不减均值，只除以均方根，最后乘 γ（没有 β）。

| | [1, 2, 3, 4] 的结果 |
|---|---|
| LayerNorm（减均值 2.5，除以标准差 1.118） | [−1.34, −0.45, 0.45, 1.34] |
| RMSNorm（除以 √7.5 = 2.739） | [0.365, 0.730, 1.095, 1.461] |

[2, 4, 6, 8] 经过 RMSNorm 的结果和 [1, 2, 3, 4] 一样，缩放不变性还在；少了减均值，计算更省，效果和 LayerNorm 差不多（Zhang & Sennrich, 2019）。

**LM 头**：最后一层的向量 h 乘一个“隐藏维度 × 词表大小”的矩阵，得到词表里每个 token 的分数，softmax 后是下一个 token 的概率。Qwen3-0.6B 的 h 是 1024 维，词表 151,936，LM 头有 1024 × 151,936 ≈ 1.56 亿个参数，约占全模型 5.96 亿的 26%，和词嵌入表共用同一个矩阵。所以 LM 头是一个 15 万类的**分类器**，用交叉熵训练，不是回归。§5.2 读 P(“1”) 和 P(“-1”)，就是在这 15 万类里只看两类。

### 3.3 分类时取哪个位置

- 因果掩码下，开头的 [CLS] 每一层都只能看到自己，它的输出和影评内容完全无关，接线性层所有影评都得到同一个预测，不能用。问题不在于它是中间结果（BERT 的 [CLS] 输出也是中间结果），而在于它看不到什么。
- 只有最后一个 token 看过整条影评，所以解码器做分类取最后一个非 padding token 的输出接分类头（transformers 的 `Qwen2ForSequenceClassification` 就这样做）。
- 反过来，BERT 是双向注意力，取句尾 [SEP] 也能看到全句，可以用。残差把 [SEP] 原来的向量保留着，不存在“丢掉 [SEP] 的内容”的问题。和 [CLS] 的区别：[CLS] 在 NSP 预训练里专门学过概括句子，起点更好；[SEP] 的位置随长度变化，取的时候要按长度找。

## 4. cot 模板与概率

### 4.1 cot 模板是什么

CoT 是 chain of thought（思维链）。材料里的 cot 模板比 basic 多一句 “Before answering, think carefully about the question and create a step-by-step chain of thoughts …”，去掉了“不需要解释”，影评放在 `### Input:` 下。同一句影评，Qwen 4b 的两种回答：

| 模板 | 回答 | 输出 token |
|---|---|---:|
| basic | `1` | 2 |
| cot | `To determine the sentiment polarity … "charming" … "affecting" … the overall sentiment is positive.`（省略中间）`1` | 122 |

cot 是写在正文里、由提示词要求的推理；“开思考”是模型自带的、放在单独思考通道里的推理，两者是两个独立的开关。

### 4.2 每个 token 都有概率，问题是读哪个位置

生成每个 token 时 LM 头都给出一整张概率表，所以概率一直存在，只是我们的脚本只保存了文字。basic 下第一个 token 就是答案，可以直接读 P(“1”)；cot 下第一个 token 是 “To”，这个位置上 “positive”、“1” 的概率每条影评都接近 0，拿来排序没有意义，要读也得读最后答案那个位置。

### 4.3 实验里看到的

- 关思考时，cot 对 basic：Qwen 0.8b +3.5 个百分点（p = 0.36）、2b +5.5（p = 0.061）、4b +2.5（p = 0.23）、9b −0.5（p = 1）；DeepSeek +0.9（p = 0.096）。方向大多向上，都不显著。
- 模型越大越常无视“一步步推理”这句话：9b 有一半多的条目直接只答一个数字。
- cot 每条要多写一百到两百个 token，Qwen 4b 每条从 0.24 秒变成 3 秒左右。
- cot 再开思考，模型要推理两遍，很多条目写满 4096 个 token 还没给出答案，各尺寸准确率都下降。

### 4.4 开思考为什么常被截断

开思考时，输出上限（max_tokens，这里是 4096）是思考和正文加在一起算的。cot、role_cot 模板又要求在正文里一步步推理，等于推理两遍。Qwen3.5 9b 这两组输出 token 的中位数在 3,300 左右，约 30% 写到上限还没给出答案，按错误计：cot 开思考 68.0%，关思考 93.5%。被截断的条目关思考时约 90% 能答对，所以掉分主要来自截断，不是句子难。补跑或续跑时 max_tokens 要和原来一致：它算在实验指纹里，改了就是另一个实验。数字见 [SST-2 实验](../../实验/SST2/README.md) 结果三。

## 5. 让大模型学起来（§5.5）

### 5.1 少样本和微调：学到的东西存在哪

| | 少样本 | 微调 |
|---|---|---|
| 用多少标注 | 几条 | IMDB 训练集 20,000 条 |
| 例子起什么作用 | 作为这次请求的输入 x，经过 Q、K、V 影响注意力分配 | 经过反向传播改参数 |
| 存在哪里 | 上下文里；请求结束就没了，每条请求都要重新带上、重新付费 | 参数的改动里（全量微调改 W，LoRA 改旁路 B、A）；推理时上下文只放影评 |

微调也不一定要变成分类器：保留 LM 头，训练它在 `Response:` 后面写出 1 或 -1，叫指令微调（SFT）。

### 5.2 三种做法

| 做法 | 改谁的参数 | 学到的东西存在哪里 | 要什么数据 |
|---|---|---|---|
| LoRA 分类器 | 大模型（只改 LoRA 旁路）和分类头 | LoRA 的 B、A 和分类头 | 标注数据 |
| 嵌入 + 逻辑回归 | 只训练逻辑回归 | 1,025 个权重 | 标注数据 |
| 蒸馏 | 只训练学生 DeBERTa | DeBERTa 的参数 | 老师给的分数即可，无标签影评也能用 |

### 5.3 嵌入 + 逻辑回归

大模型完全冻结，每条影评过一遍模型，取最后一个 token 最后一层的向量 h（Qwen3-0.6B 是 1024 维）当特征，用 20,000 条标注训练 sklearn 逻辑回归：每一维一个权重加一个偏置，1,025 个参数。

- 零样本：分数 = h · (w₁ − w₋₁)，w₁、w₋₁ 是 LM 头里 “1”、“-1” 两行，预训练时为预测下一个词定下的，方向固定。
- 逻辑回归：分数 = h · w + b，w 用标注专门学出来。零样本的方向也是逻辑回归能学到的一个解，所以标注够多时逻辑回归至少一样好。标注很少时就不一定：DeBERTa 只用 16 条训练只有 61.6%，学出来的方向可能不如大模型自带的。
- 它不如 LoRA 分类器的原因：h 是为预测下一个词算出来的，逻辑回归只能在这个固定的特征空间里画一个超平面；LoRA 能改 Q、V 投影，让注意力专门关注情感词，特征本身也变了。
- 在影评后面接上 “The sentiment of this review is” 再取最后一个 token 的向量，它要预测的下一个词就和情感直接相关，特征通常更好。

### 5.4 蒸馏与 KL

大模型当老师，给每条影评打正面概率 p_T；训练 DeBERTa 当学生，让它的 p_S 贴近 p_T：

> 损失 = −[p_T · ln p_S + (1 − p_T) · ln(1 − p_S)] = H(p_T) + KL(p_T ‖ p_S)

| p_T = 0.8 时 | 交叉熵 | 其中熵 H(p_T) | 其中 KL(p_T ‖ p_S) |
|---|---:|---:|---:|
| 学生输出 p_S = 0.6 | 0.592 | 0.500 | 0.092 |
| 学生输出 p_S = 0.8 | 0.500 | 0.500 | 0 |

- 学生输出 p_S = p_T 时损失最小，最小值是老师的熵 0.500，不是 0；只有老师给 0 或 1 时熵才是 0。训练时 H(p_T) 是常数，最小化交叉熵就是最小化 KL(p_T ‖ p_S)。导师提到的“反向 KL”是把两个分布的位置反过来，KL(p_S ‖ p_T)。
- 老师越拿不准，熵越大。两类时 q = (0.5, 0.5) 的熵最大，等于 ln 2 ≈ 0.693，比 q = (0.8, 0.2) 的 0.500 大。这时学生输出 p = (0.8, 0.2)，交叉熵 0.916 = 熵 0.693 + KL 0.223。
- 用硬标签 1 训练，损失是 −ln p_S，只有 p_S = 1 时为 0，学生被推向 1，“神作”和“还行吧”被当成一样正面。
- 老师不需要人工标注，50,000 条无标签影评也能拿来训练。

### 5.5 软标签与 AUC

AUC 只看排序。手设的例子：2 条正面、3 条负面，两个学生判断的方向一样（P2 和 N3 都判反了），分数的极端程度不同：

| | P1 神作 | P2 还行吧 | N1 烂片 | N2 | N3 | 准确率 | AUC |
|---|---:|---:|---:|---:|---:|---:|---:|
| 软标签学生 | 0.95 | 0.48 | 0.05 | 0.40 | 0.52 | 3/5 | 5/6 = 0.83 |
| 硬标签学生 | 0.99 | 0.03 | 0.02 | 0.04 | 0.97 | 3/5 | 4/6 = 0.67 |

软标签教给学生“0.97 和 0.62 都是正面，但前者更正面”，判错时分数也离中间不远，输掉的配对少。这里的分数是故意夸大的：实际用硬标签训练的模型输出的仍是概率（BERT 全量微调用人工硬标签，Kaggle AUC 0.975），措辞相近、标签不同的影评也能让它间接学到哪些句子拿不准；软标签是把这层信息逐条直接给它。

硬标签训练和交 0/1 标签都丢掉了信心度，区别是：

| | 丢的是谁的信心度 | 在哪一步丢的 | 能不能找回 |
|---|---|---|---|
| 硬标签训练 | 老师的 | 算损失时 | 不能，学生的参数已经按 0 和 1 训练好了，只能重新训练 |
| 交 0/1 标签 | 学生自己的 | 提交时被阈值切掉 | 能，改交概率即可，模型没变 |

### 5.6 指令微调（SFT）

SFT 是 Supervised Fine-Tuning（监督微调）。大模型训练的三步：

```text
预训练：海量文本 → 预测下一个 token，每个位置都算损失               → 学会续写
SFT  ：人写好的"指令 + 标准回答" → 仍是预测下一个 token，只在回答上算损失 → 学会按指令回答
对齐  ：按人的偏好继续调（如 RLHF），这里不展开
```

SFT 和预训练用同一个损失（下一个 token 的交叉熵），模型结构不变；不同的只有数据（每条带标准答案，这就是"监督"）和算损失的位置。

**为什么只算答案 token。** IMDB 的一条样本约 300 个影评 token 加 1 个答案 token。设每个影评 token 的损失约 3.0、答案 token 0.7：

| | 损失 | 答案 token 的权重 |
|---|---:|---:|
| 整段都算 | (300 × 3.0 + 0.7) / 301 ≈ 2.99 | 1/301 ≈ 0.33% |
| 只算答案 | 0.7 | 100% |

整段都算时，梯度几乎都用在续写影评上；只算答案时，梯度全部用在"这条该接 positive 还是 negative"上。实现上，常见做法是把提示部分的 label 设成 −100（不计损失）。因为因果掩码，答案位置的预测只看前面的 token，所以也可以干脆不把答案喂进去，只取提示最后一个位置的输出和答案算交叉熵，两者等价，还省掉其余位置约 15 万维的 logits。

**和 BERT 分类的区别。** BERT 微调是在 [CLS] 上新加一个 768 → 2 的分类头，标签是 0/1；SFT 不加新部件，标签是 `positive`、`negative` 这两个词，由原来的 LM 头输出。

**IMDB 上的结果**（Qwen3-4B-Base，LoRA，1 轮，见 [IMDB README](../../实验/IMDB/README.md) 第 4 节）：

| | 答案位置的平均交叉熵 | 几何平均下正确答案的概率 | 两个答案词的概率之和 | 验证 AUC | Kaggle AUC |
|---|---:|---:|---:|---:|---:|
| 零样本 | 0.999 | e^(−0.999) ≈ 0.37 | 0.436 | 0.9847 | — |
| SFT 后 | 0.093 | e^(−0.093) ≈ 0.91 | 0.9998 | 0.9941 | 0.99493 |

零样本时两个答案词只占答案位置不到一半的概率，但只比较这两个词，排序已经很准；SFT 主要是让模型按格式回答，并把判断变得更确定。

**SFT 与全量 / LoRA 是两件事。** SFT 说的是用什么数据、在哪里算损失；全量还是 LoRA 说的是改哪些参数。两者可以任意组合：上面的 Qwen3-4B 是 SFT + LoRA，40 亿个原始参数冻结，只训练 3,303 万个（0.81%）。

**SFT 的完整流程**（以 IMDB 的 Qwen3-4B 为例）：

| 步 | 做什么 | IMDB 实验里 |
|---|---|---|
| 1. 数据 | 每条 = 提示（指令 + 影评）+ 标准答案 token | 答案是 `positive` / `negative` |
| 2. 前向 | 整条输入 Qwen；每个位置由 LM 头给出 151,936 类的概率 | |
| 3. 损失 | 只取答案位置，L = −ln p(正确的词)；提示位置的 label 设成 −100，不计损失 | 答案位置的交叉熵 0.999 → 0.093 |
| 4. 反向 | 只有答案位置的 ∂L/∂z = p − q 不为 0，从这里往回传 | 见[反向传播学习笔记](../反向传播/反向传播学习笔记.md) |
| 5. 更新 | 全量：全部参数；LoRA：只改 A、B | LoRA，3,303 万个参数（0.81%） |
| 6. 使用 | 读答案位置两个词的概率，在两者之间归一化 | 验证 AUC 0.9941 |

SFT 决定第 1、3 步，全量还是 LoRA 决定第 5 步。

**交叉熵里的 q 和 p。** 交叉熵 = −Σ q·ln p：q 是正确答案的分布，p 是模型给的分布。

| 词 | 正确答案 q | 模型 p | q·ln p |
|---|---:|---:|---:|
| positive | 1 | 0.6 | ln 0.6 |
| negative | 0 | 0.3 | 0 |
| 其他词 | 0 | 0.1 | 0 |

SFT 的标签是硬标签（一个 1，其余全是 0），所以只剩一项：损失 = −ln 0.6 ≈ 0.511，永远 ≥ 0。蒸馏的软标签 q = (0.8, 0.2) 有两个非 0 的位置，就剩两项。−Σ p·ln p 用的是模型自己的分布，那是模型分布的熵，衡量模型自己多拿不准，没有用到正确答案，不能当损失。硬标签、软标签不是蒸馏专用的说法，凡是用交叉熵训练分类都可以这样分；把 1 改成 0.9 的“标签平滑”也是软标签。

**为什么 p(positive) 只在两个词之间算。** 预测时只关心正负，分给 “The”“It” 这些词的概率和判断无关。p(positive) = p_pos / (p_pos + p_neg) 就是“假设模型一定在这两个词里选一个，选 positive 的概率”，两者相加为 1，也不受无关词分走多少的影响。AUC 只看排序，所以零样本时两个答案词只占 0.436，AUC 仍有 0.9847。

### 5.7 在 T4 上要跑多久

每个 token 的运算量约是参数量的倍数：推理只做前向，约 2N；带梯度检查点的训练做前向、重算一次前向、反向，约 6N。Qwen3-4B 去掉词表约 N = 36 亿。

| | token 数 | 运算量 | 实测 | 折算 |
|---|---:|---:|---:|---:|
| 训练 20,000 条 × 315 token | 630 万 | 6N × 630 万 ≈ 1.36×10¹⁷ | 222 分钟 | 约 10 TFLOPS |
| 测试推理 25,000 条 × 310 token | 775 万 | 2N × 775 万 ≈ 5.6×10¹⁶ | 87 分钟 | 约 11 TFLOPS |

T4 的 fp16 理论峰值 65 TFLOPS，实际只用到六分之一左右，估时间时按 10 TFLOPS 算更接近。

## 7. 易混点

- **MLM 遮词与注意力掩码**：前者改输入，用来出题；后者改注意力分数，规定谁能看谁。
- **因果语言建模**：按前文预测下一个词，不是“因果分析”。
- **长上下文中间被忽略**不叫幻觉；幻觉是编造不存在的事实。
- **上下文变长影响的是这一次的注意力权重和 Δx**，参数不变。
- **上下文能力与跨请求记忆**：一次请求之内能看到全部上下文，请求之间什么都不留；缓存只省计算。
- **LM 头是分类器**，15 万类，用交叉熵，不是回归。
- **cot 模板与开思考**：一个是提示词要求在正文里推理，一个是模型自带的思考通道。
- **硬标签训练与交标签**：丢的是谁的信心度、能不能找回，见 5.5。
- **SFT 与预训练**：损失相同（下一个 token 的交叉熵），不同的是数据（带标准答案）和算损失的位置（只算回答）。
- **新加的分类头与 LM 头**：BERT 微调加 768 → 2 的新层，标签是 0/1；SFT 用原有的 LM 头，标签是词。
- **训练损失与读出的概率**：损失对整个词表算，p(positive) 只在两个答案词之间算，见 5.6。
- **交叉熵与熵**：交叉熵 −Σ q·ln p 的 q 来自正确答案、p 来自模型；−Σ p·ln p 两边都是模型自己的分布，是熵，不是损失。
- **硬标签与软标签**：说的是正确答案 q 的样子（一个 1 还是好几个非 0），不只用在蒸馏；SFT 和 BERT 微调用的都是硬标签。
- **SFT 与全量 / LoRA**：前者是数据和损失的位置，后者是改哪些参数；本仓库的 Qwen3-4B 是 SFT + LoRA，不是全量微调。
- **“调参”与“更新参数”**：调参一般指调学习率、batch size 这类超参数；训练改的是模型参数，叫更新参数。
- **max_tokens 与截断**：开思考时上限含思考内容，写满了没有答案按错误计，见 4.4。
- **参数与激活**：参数是训练出来的 W，所有输入共用；激活是这一次输入算出的中间结果（q、k、v、Δx……），用完就丢。KV cache 存的是激活。
- **熵的大小**：分布越平均熵越大；两类时 (0.5, 0.5) 最大，等于 ln 2 ≈ 0.693。
- **KL 的方向**：KL = 交叉熵 − 熵，一定 ≥ 0；算出负数就是减反了。
- **损失和梯度**：损失是一个数，表示离正确答案多远，式子里有 ln；梯度是一组数，表示每个分数往哪边动、动多少，softmax 加交叉熵时就是 p − q，没有 ln。
- **Pre-LN 与 Post-LN**：BERT 加完残差再归一化；Qwen 进子层之前归一化，残差这条路不经过归一化。
- **W_o 的个数**：每层一个，属于注意力子层；W₂ 属于前馈子层。"两者都是子层的出口"说的是角色，不是两个 W_o。
- **软标签在哪里停**：梯度 p − q 在 p = q 时为 0，所以蒸馏的学生停在老师的信心度上；硬标签则一直推向 1。
