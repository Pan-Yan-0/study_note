# 泰勒重要性小实验学习笔记

在一个很小的 MLP（结构同 LLaMA / Qwen 的 MLP）上，亲手计算一个中间通道的泰勒重要性，并和"真的删掉它"之后的损失变化对比，检验"泰勒展开是近似"这句话。代码在 CPU 上就能跑。概念见 [AdaPruner 笔记](../../论文阅读/模型压缩/AdaPruner.md) 第 3 节。

---

## 1. MLP 和中间通道

MLP 就是 Transformer 每层里的前馈层（FFN）。LLaMA / Qwen 用 SwiGLU：

```
h = down_proj( SiLU(gate_proj(x)) × up_proj(x) )
```

| 矩阵 | 对应 BERT 的 | 形状（LLaMA-7B） |
|---|---|---|
| up_proj | W₁ | 4096 → 11008 |
| gate_proj | 新增的"门" | 4096 → 11008 |
| down_proj | W₂ | 11008 → 4096 |

第 i 个中间通道由 gate_proj、up_proj 的第 i 行产生，由 down_proj 的第 i 列读取；删掉它要三处一起删（一个依赖组）。MLP 约占一层参数的三分之二。

## 2. 代码

```python
import copy
import torch
import torch.nn as nn

class TinyMLP(nn.Module):
    def __init__(self, hidden=8, inter=16):
        super().__init__()
        self.gate_proj = nn.Linear(hidden, inter, bias=False)
        self.up_proj   = nn.Linear(hidden, inter, bias=False)
        self.down_proj = nn.Linear(inter, hidden, bias=False)
    def forward(self, x):
        return self.down_proj(nn.functional.silu(self.gate_proj(x)) * self.up_proj(x))

torch.manual_seed(0)
mlp = TinyMLP()
x = torch.randn(4, 8)
y = torch.randn(4, 8)

def compute_loss(model):
    pred = model(x)
    return ((pred - y) ** 2).mean()

def channel_importance(model, i):
    # 向量级泰勒重要性：三部分各自 |Σ g·w|，再用 sum 聚合
    gate = (model.gate_proj.weight[i, :] * model.gate_proj.weight.grad[i, :]).sum().abs()
    up   = (model.up_proj.weight[i, :]   * model.up_proj.weight.grad[i, :]).sum().abs()
    down = (model.down_proj.weight[:, i] * model.down_proj.weight.grad[:, i]).sum().abs()
    return (gate + up + down).item()

def taylor_delta(model, i):
    # 删掉通道 i（Δw = −w）后，一阶泰勒估计的损失变化 −Σ g·w（带符号）
    gate = (model.gate_proj.weight[i, :] * model.gate_proj.weight.grad[i, :]).sum()
    up   = (model.up_proj.weight[i, :]   * model.up_proj.weight.grad[i, :]).sum()
    down = (model.down_proj.weight[:, i] * model.down_proj.weight.grad[:, i]).sum()
    return -(gate + up + down).item()

def true_delta(model, i, scale):
    # 在副本上把通道 i 乘以 scale，返回损失的真实变化；只要数值，全部放进 no_grad
    model_copy = copy.deepcopy(model)
    with torch.no_grad():
        model_copy.gate_proj.weight[i, :] *= scale
        model_copy.up_proj.weight[i, :]   *= scale
        model_copy.down_proj.weight[:, i] *= scale
        base_loss = compute_loss(model)
        copy_loss = compute_loss(model_copy)
    return (copy_loss - base_loss).item()

# 算一次梯度：要梯度的前向不能放进 no_grad
mlp.zero_grad()
base_loss = compute_loss(mlp)
base_loss.backward()
```

`channel_importance`、`compute_loss`、`taylor_delta` 和 `true_delta` 的初版由 Pan-Yan-0 编写；`true_delta` 最后的整理版和脚手架由 Claude 给出。

**自测**：
- `channel_importance` 用人工设定的权重和梯度：每部分内部同号时应为 2.0；gate 部分内部一正一负时应为 1.6（向量级会抵消）。只有第一个测试分不出向量级和元素级。
- `true_delta` 不能改到原模型；scale = 1 时损失变化为 0；×0.999 的微小扰动下，泰勒估计和真实变化相差应小于 5%。

## 3. 结果

微小扰动（×0.999，通道 9）：泰勒估计 −2.111×10⁻⁴，真实变化 −2.106×10⁻⁴，相差约 0.2%。

整个删掉（×0）：

| 通道 | 泰勒估计 ΔL | 真实 ΔL | 比值 |
|---|---|---|---|
| 0 | −0.0432 | −0.0109 | 4.0 |
| 2 | +0.0056 | +0.0042 | 1.3 |
| 4 | +0.0242 | +0.0097 | 2.5 |
| 5 | −0.0552 | −0.0149 | 3.7 |
| 7 | −0.0073 | −0.0028 | 2.6 |
| 9 | −0.2111 | −0.0540 | 3.9 |
| 10 | −0.1013 | −0.0288 | 3.5 |
| 11 | +0.0000 | +0.0000 | — |

## 4. 读到的结论

1. **扰动小时一阶很准，整个删掉时高估 3–5 倍。** 一个通道的输出是 down × SiLU(gate) × up 三个因子相乘，三个因子同时归零，一阶估计会把影响算约三次；被扔掉的高阶项此时不能忽略。
2. **排名基本对，数值不准。** 最该删的两个（11、15）和最重要的三个（9、14、10），两种排法一致。对剪枝来说，排名比数值更重要。
3. **Pan-Yan-0 的发现：同号之间排名都对，正负混在一起就会乱**（通道 2 和 7 按绝对值的顺序颠倒）。被忽略的高阶项把所有通道往同一个方向偏，负值大约缩小 3–5 倍，正值只缩小 1.3–2.6 倍，取绝对值后，正负之间的相对位置就变了。
4. **大部分 ΔL 是负的**（删掉反而损失下降），因为这个模型随机初始化、没训练过，离损失的最低点很远。**训练好的模型在最低点附近，梯度 g ≈ 0**，一阶估计对所有结构都接近 0，排名就失效了，所以要用二阶（Hessian）。经典工作：OBD（1989，Hessian 对角线）、OBS（1993，完整 Hessian 并补偿剩余权重）、SparseGPT（2023，把 OBS 做到大模型）。AdaPruner 元素级里的 ½·wₖ·Hₖₖ·wₖ 用 gₖ² 近似 Hₖₖ（Fisher 近似），是一种便宜的二阶近似。

## 5. 编程要点

| 要点 | 说明 |
|---|---|
| 方法链从左往右读 | `.sum().abs()` 是向量级（先求和再取绝对值），`.abs().sum()` 是元素级 |
| `with` 语句 | 上下文管理器：进入时做一件事，离开时自动撤销，类似 C++ 的 RAII |
| `torch.no_grad()` | 原地改需要梯度的权重时**必须**用；只要数值的前向**应该**用（省内存）；要求梯度的前向**不能**用（在里面 `backward()` 会报"does not require grad and does not have a grad_fn"） |
| 副作用 | 函数只做它名字说的事。`true_delta` 初版偷偷对原模型做了 `backward`，掩盖了"漏跑第 3 格"的问题，去掉后才暴露出来 |
| 读报错 | 从最下面一行往上看：最后一行是错误类型，上面几行指出位置。`'NoneType' object is not subscriptable` 出现在 `.grad[...]`，说明还没做过反向 |
| Notebook 状态 | 变量的状态取决于按什么顺序跑过哪些格；改了前面的格，要从改动处往下依次重跑 |
| 全局变量 | 函数里可以直接读外面定义的 x、y；`model(x)` 会调用 `forward` |
