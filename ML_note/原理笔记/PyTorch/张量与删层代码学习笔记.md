# 张量与删层代码学习笔记

为 [ShortGPT BI 删层实验](../../实验/ShortGPT_BI删层/README.md) 里的两个函数学的 Python / PyTorch 基础：`bi_from_pair`（由一层的输入和输出算 BI）和 `drop_layers`（删层）。有 C++ 基础，所以很多地方用 C++ 来类比。

---

## 1. 张量和"在哪一维上算"

- 张量（tensor）就是多维数组。钩子抓到的隐藏状态形状是 `[batch, seq_len, hidden]`：比如 `[2, 5, 64]` 表示 2 句话、每句 5 个 token、每个 token 一个 64 维向量。
- `F.cosine_similarity(a, b, dim=-1)`：`dim` 决定**沿哪一维取向量**，比较的永远是 a 和 b。
  - `dim=-1`（最后一维）：每个 token 取一个 64 维向量，比 a 和 b 的同一个 token，结果形状 `[2, 5]`。BI 要的就是这个。
  - `dim=0`：在每个（位置，特征）上把两句话的值凑成 2 维向量来比，结果 `[5, 64]`，没有意义。
- **写错 `dim` 不会报错**，只会算出一堆看起来正常的错误数字。所以要用已知答案测试：输出 = 输入时 BI 必须是 0，输出 = −输入时必须是 2。

## 2. 写 `bi_from_pair` 用到的操作

| 操作 | 作用 |
|---|---|
| `.float()` | 转成 float32。FP16 最大约 65504，4096 维向量的平方和容易溢出成 inf，余弦就成了 NaN |
| `1 - cos` | 张量和数字直接运算，每个元素都算 |
| `.sum()` | 所有元素求和，结果仍是只有一个数的张量 |
| `.item()` | 把只有一个数的张量取成普通 Python 数字 |
| `.numel()` | 元素个数 |
| `assert 条件, "说明"` | 条件不成立就报错，用来检查形状等前提 |

返回"总和 + 个数"而不是平均值：多批数据要先累加，最后再相除，才是全体 token 的平均。

## 3. 写 `drop_layers` 用到的知识

| 知识点 | 说明 | C++ 类比 |
|---|---|---|
| `nn.ModuleList` | 专门装层的列表。放进去的层会登记到模型上，`parameters()`、搬到 GPU、保存权重时才看得到。删层后必须装回 `ModuleList` | `std::vector<Module*>`，外加登记 |
| 前向怎么连接各层 | `for layer in self.layers: h = layer(h)`，按顺序遍历，层之间没有"下一层"指针。从列表里拿掉一层，循环自然跳过它 | 遍历 `vector`，不是链表 |
| 引用而不是拷贝 | `nn.ModuleList([layers[i] for i in keep])` 装的是原来的层对象，权重没有被复制 | 类似指针或 `shared_ptr` |
| 列表推导式 | `[i for i in range(n) if i not in drop]`，等价于 for 循环 + append | `std::copy_if` |
| `list` 和 `set` | `x in 列表` 是线性查找 O(k)；`x in 集合` 是哈希查找，平均 O(1) | `vector` / `unordered_set` |
| `range(n)` | 产生 0, 1, …, n−1。`len()` 返回一个整数，不能直接 `for` 遍历 | `for (int i = 0; i < n; ++i)` |
| `enumerate` | 每次给出 `(下标, 元素)` 一对值，要写成 `for i, layer in enumerate(...)` | 带下标的循环 |
| `getattr(对象, "名字", 默认值)` | 安全读取可能不存在的属性，比如旧版 config 没有 `layer_types` | 运行时才确定有没有的成员 |

**为什么删层后要重新编号**：生成时 KV cache 按每层的 `self_attn.layer_idx` 存取，大小由 `config.num_hidden_layers` 决定。删掉第 1、3 层后，剩下的层还叫 0、2、4、5，就会越界或用错位置。算 PPL 时 `use_cache=False`，不会触发这个 bug；只有 `generate` 才会，所以自测里专门用 KV cache 生成了一次。

**关于性能**：36 层、最多删 9 层，`list` 和 `set` 的差别是微秒级，加载一次模型却要几分钟。用 `set` 是为了意图清楚，不是为了性能。优化之前先测出时间花在哪里。

## 4. 在 Kaggle 上遇到的问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `Expected all tensors to be on the same device ... cuda:0 ... cuda:1` | 模型切在两张卡上。PyTorch 的 forward hook 拿到的是 Accelerate 搬运前的输入，交界那一层的输入在 cuda:0、输出在 cuda:1 | 在 hook 里先 `x_in = x_in.to(x_out.device)`（GPT 审阅时提前指出过） |
| 加载时 `CUDA out of memory`，但每张卡只设了 11 GiB 上限，却已经用了 14 GiB | 同一个内核里旧模型还占着显存，又加载了一份 | 换模型前重启内核；代码里先 `del model`、`gc.collect()`、`torch.cuda.empty_cache()` |
| pip 打印 `ERROR: pip's dependency resolver ...` | 只是提醒：为了装 transformers 4.x 降了 huggingface-hub，和用不到的 gradio、diffusers 冲突 | 每一步都显示 `done` 就是装好了；装完重启内核 |

## 5. 易混点

| 容易说错的 | 正确说法 |
|---|---|
| `dim=0` 算的是两个句子的相似度 | `dim` 只决定沿哪一维取向量；比较的永远是 a 和 b 的对应位置 |
| token 个数是 `x.size(-1)` | 最后一维是 hidden；token 个数是 batch × seq_len，即 `bi.numel()` |
| 删层后要把前后两层"连起来" | 前向是按列表顺序遍历，删掉就自动跳过；要补的是重新编号 |
| 新列表里的层是复制出来的 | 是原来的对象；改新列表里的层，原来的也会变 |

| `keep` 和删层后打印的编号 | 都是没被删的编号 `[0, 2, 4, 5]` | ✓ |
