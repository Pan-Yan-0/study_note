# DeBERTa 与 IMDB 三条路学习笔记

对照网页《IMDB 情感分类三条路》逐节学习的记录，这一轮学到网页 §5.3。BERT 的基础结构见 [BERT 原理笔记](../BERT/BERT原理笔记.md)，这里只记这一轮新弄清的内容。文中的玩具数字都能用 [toy_numbers.py](toy_numbers.py) 复现，向量只有 2 维或 4 维（真实模型是 768 维），权重是手工设的。

## 0. 全局：IMDB 的三条路

| 路线 | 做法 | 交给 Kaggle 的分数 | 本笔记 |
|---|---|---|---|
| A 微调编码器 | BERT / DeBERTa 加分类头，在 20,000 条有标签影评上训练 | 分类头 softmax 后的正类概率 | 第 2–4 节 |
| B 提示大模型 | 零样本或少样本指令，不训练 | 第一个 token 的概率换算成 p(正面) | 第 5 节 |
| C 大模型参与训练 | LoRA 微调大模型、嵌入 + 分类器、蒸馏 | 概率 | [解码器大模型与路线 C 学习笔记](../LLM/解码器大模型与路线C学习笔记.md) |

Kaggle 按 ROC-AUC 计分，所以先弄清 AUC（第 1 节）。

## 1. AUC：只看排序

玩具数据：12 条影评，6 条正面、6 条负面，每条有一个模型给出的正面得分。

| | 得分 |
|---|---|
| 正面影评 | 0.97、0.91、0.84、0.62、0.55、0.38 |
| 负面影评 | 0.71、0.45、0.30、0.22、0.10、0.05 |

### 1.1 TPR 与 TNR

- **TPR（真正率）** = 被判成正面的正面影评 ÷ **全部正面影评**
- **TNR（真负率）** = 被判成负面的负面影评 ÷ **全部负面影评**

分母是真实标签的总数，这里固定是 6 和 6，和“判成正面的有几条”无关。比如阈值取 0.25 时，判成正面的有 9 条（6 条正面 + 3 条负面），TPR = 6/6 = 1，TNR = 3/6 = 0.5。

ROC 曲线的横轴是 FPR = 1 − TNR，纵轴是 TPR；AUC 是曲线下的面积。

### 1.2 AUC = 随机抽一对，正面得分更高的概率

把每条正面和每条负面配成一对，共 6 × 6 = 36 对。正面得分更高记 1 分，相等记 0.5 分，更低记 0 分：

| 正面影评 | 0.97 | 0.91 | 0.84 | 0.62 | 0.55 | 0.38 |
|---|---:|---:|---:|---:|---:|---:|
| 赢了几条负面 | 6 | 6 | 6 | 5 | 5 | 4 |

合计 32，AUC = 32/36 = 0.889。它只看排序，不看分数的绝对大小：所有分数同时乘 0.5，AUC 不变。

### 1.3 只交 0/1 标签会丢什么

阈值 0.5 时，正面影评只有 0.38 被判成 0，负面影评只有 0.71 被判成 1。分数只剩 0 和 1，很多配对变成平手：

| 配对 | 对数 | 得分 |
|---|---:|---:|
| 正面得 1，负面得 0 | 25 | 25 |
| 正面得 1，负面得 1（0.71 那条） | 5 | 2.5 |
| 正面得 0（0.38 那条），负面得 0 | 5 | 2.5 |
| 正面得 0，负面得 1 | 1 | 0 |
| 合计 | 36 | **30** |

AUC = 30/36 = 0.833 = (TPR + TNR)/2 = (5/6 + 5/6)/2；正负各半时也等于准确率。阈值 0.25 时则是 (1 + 0.5)/2 = 0.75：交标签时，阈值一变，AUC 就跟着变。

丢掉的是“有多确定”：

- 正面 0.97 对负面 0.71：交概率得 1 分，交标签时两条都是 1，只得 0.5 分。
- 正面 0.38 对负面 0.30：交概率得 1 分，交标签时两条都是 0，只得 0.5 分。
- 两条影评模型都判成正面，p 分别是 0.99 和 0.62：交标签时两者没有区别，交概率时前者排在前面。0.62 说明模型不太确定。

所以 GloVe 六模型（交标签）和 BERT、DeBERTa（交概率）的 Kaggle 分数不能直接比较。大模型如果只回答 “1” 或 “-1”，同样只能算出标签式的 AUC，要读概率才行（第 5.2 节）。

## 2. BERT 回顾：这一轮补上的细节

### 2.1 输入：三个向量逐位相加

词向量、位置向量、段落向量都是 768 维，**逐位相加**，结果仍是 768 维。如果拼接，就会变成 768 × 3 = 2304 维，BERT 没有这样做。4 维的例子：

| | 维1 | 维2 | 维3 | 维4 |
|---|---:|---:|---:|---:|
| 词向量（bad） | 0.2 | 0.5 | −0.1 | 0.3 |
| 位置向量 | 0.1 | 0 | 0.2 | −0.1 |
| 段落向量（A 句） | 0 | 0.1 | 0 | 0 |
| 逐位相加 | 0.3 | 0.6 | 0.1 | 0.2 |
| LayerNorm 后 | 0 | 1.60 | −1.07 | −0.53 |

- BERT 的位置向量不是公式算的，而是一张 512 × 768 的**可学习的表**：随机初始化，预训练时靠反向传播更新，微调时默认也会继续更新。每次只有用到的那几行会收到梯度。
- 原版 Transformer 的位置编码用正弦、余弦公式算出来，固定不变，不参与训练。
- 表只有 512 行，第 513 个 token 没有位置向量可取，所以长影评要截断（第 4.3 节）。

### 2.2 LayerNorm

- **一行一行地做**：每个词的 768 个数各自减去均值、除以标准差，再乘 γ、加 β。形状不变。
- **尺度不变**：[1, 2, 3, 4] 和 [10, 20, 30, 40] 归一化后都是 [−1.34, −0.45, 0.45, 1.34]。
- **embedding 后面那一层 LayerNorm 的作用**：
  1. 词向量表里不同词的向量大小可能差很多，不统一的话，第 1 层的 q·k 有的很小（softmax 几乎平均分配）、有的很大（softmax 只看一个词）。
  2. 后面每一层的输出都做过 LayerNorm，在 embedding 后面也做一次，第 1 层的输入就和其他层一样了。γ、β 可以学习，但所有词共用一组，不会出现某个词特别大、某个词特别小的情况。
- BERT-base 一共有 25 个 LayerNorm：embedding 后 1 个，12 层每层 2 个。

### 2.3 一层的数据流与形状

以 `[CLS] not bad [SEP]` 为例，n = 4：

```text
输入 H                                   4 × 768     每个 token 一行
├─ 注意力层
│  ① 投影  Q = H×W_q   K = H×W_k   V = H×W_v   各 4 × 768（W 都是 768×768）
│  ② 切头  768 列切成 12 段，每段 64 列           每个头 4 × 64
│  ③ 每个头各自做：
│          分数 = Q_h × K_hᵀ / √64                4 × 4
│          softmax（按行）→ 权重                  4 × 4，每行加起来等于 1
│          权重 × V_h                             4 × 64
│  ④ 12 个头拼接                                  4 × 768
│  ⑤ 乘 W_o                                       4 × 768
├─ 残差 + LayerNorm①：H + ⑤ 的结果 → A           4 × 768
├─ 前馈层：× W_1 → GELU → × W_2                  4 × 3072 → 4 × 768
└─ 残差 + LayerNorm②：A + 前馈输出 → H_next      4 × 768，交给下一层
```

```python
def bert_layer(H):                       # H: n × 768
    A = layer_norm_1(H + attention(H))   # 注意力 + 残差 + LN
    H_next = layer_norm_2(A + ffn(A))    # 前馈层 + 残差 + LN
    return H_next

for layer in range(12):
    H = bert_layer(H)                    # 这一层的输出 = 下一层的输入
```

- **只有“权重 × V”这一步会把不同的词混在一起。** 投影、W_o、LayerNorm、前馈层都是每个词单独算：not 那一行变了，bad 那一行的 LayerNorm 和前馈输出不变，注意力输出会变。
- **两个残差各跨一个子层**：第一个加 H（注意力的输入），第二个加 A（前馈层的输入），不是加最开始的 H。
- 前馈层的输出就在 H_next 里；下一层的 q 是 H_next 乘**下一层自己的** W_q 得到的。
- 每层把每个词的向量更新两次（x + Δx），12 层共 24 次。
- 两个子层是同一个模板：算出 Δx → 加残差 → LayerNorm。Δx 来自子层的最后一个矩阵：注意力子层是 W_o，前馈层是 W₂。
- W_o 和 W₂ 后面都没有激活函数。Δx 要能取正负两种值，才能把特征调大或调小；非线性只要夹在 W₁ 和 W₂ 之间就够了，两个矩阵直接相乘仍然只是一个线性变换。
- **隐藏维度**（BERT-base 是 768）指每个 token 那一行的长度。第一层的入口是词向量加位置向量，之后每一层都保持这个长度，但行里已经混进了上下文。多头把 q、k、v 各切成头数那么多段，每头的维数 = 隐藏维度 ÷ 头数；拼接再乘 W_o 后回到隐藏维度，才能和 x 相加。
- BERT 是先相加再 LayerNorm（Post-LN）。GPT-2 以后的很多模型改成先归一化再进子层、最后相加（Pre-LN），比如 `H + attn(norm(H))`；Qwen 用的归一化是 RMSNorm。

### 2.4 Q、K、V 与多头

| | 比喻（图书馆找书） | “not bad” 里，从 bad 的角度看 |
|---|---|---|
| Q（query） | 想找什么 | bad 想知道：前面有没有否定词？ |
| K（key） | 书的标签，用来被匹配 | not 的标签：我是否定词 |
| V（value） | 书的内容，匹配上以后真正拿走的东西 | not 交出去的信息：反转情感 |

三者都由同一个词的 x 乘不同的投影矩阵得到。“投影矩阵”就是一个可学习的矩阵，向量乘它得到一个新向量。

**2 维玩具**：H(bad) = [1.0, 0.5]，H(not) = [0.8, −0.6]，W_q = [[1, 0], [0, 2]]，W_k = [[0, 1], [1, 0]]，W_v 取单位矩阵。

- q_bad = [1, 1]，k_bad = [0.5, 1]，k_not = [−0.6, 0.8]
- bad 看 not：q_bad · k_not = 0.2；bad 看自己：1.5
- 除以 √2 后 softmax：[0.285, 0.715]
- Δx_bad = 0.285 × v_not + 0.715 × v_bad = [0.943, 0.186]

**为什么点积越大越匹配**：两个向量在同一维上都大（方向一致），乘积才大。更根本的原因是，“越大越匹配”是人为规定的，softmax 给分数高的词更多权重，训练会把 W_q、W_k 学成“想从谁那里拿信息，和谁的点积就大”。

**为什么除以 √d**：点积是 64 项相加，数值约在 ±8（标准差 √64 = 8），项数越多数值越大。数值大了，softmax 会变得极端，梯度接近 0，学不动：

| 分数 | softmax |
|---|---|
| 不除：[16, 0, −8] | ≈ [1, 0, 0] |
| 除以 8：[2, 0, −1] | [0.84, 0.11, 0.04] |

每个头除以的是 √64，不是 √768。

**为什么要多头**：一个头只有一次 softmax，每个词只有一套加起来等于 1 的权重。“the movie is not bad” 里，bad 既想看 not（前面有没有否定词），又想看 movie（我在评价什么）。只有一个头时，权重只能在两者之间分，结果是混合的平均；多个头时，各问各的，结果放在拼接后的不同列里。每个头问什么不是人规定的，是训练出来的。事后分析发现，有的头专门看前一个词，有的头大量看 [SEP]，有的头会盯住动词的宾语（Clark 等，2019）。

**为什么每个头 64 维、为什么不加更多头**：总维度固定 768，分给 12 个头，每个头 64 维（BERT-large 是 1024 维、16 个头，每个头也是 64 维）。头越多，每个头的维度越少，一次 q·k 能表达的东西越少。原版 Transformer 固定计算量，只改头数（翻译 BLEU，越高越好）：

| 头数 | 1 | 4 | 8 | 16 | 32 |
|---|---:|---:|---:|---:|---:|
| 每个头的维度 | 512 | 128 | 64 | 32 | 16 |
| BLEU | 24.9 | 25.5 | 25.8 | 25.8 | 25.4 |

**为什么还要 V**：bad 那一行的权重有 n 个数，长度随句子变化，没法交给后面的层；用权重给 V 做加权求和，才得到固定 64 维的内容向量。V 和 K 分开，是因为“被找到的标签”和“交出去的内容”可以不同。

**W_o（o 是 output）**：注意力层的最后一步。12 个头的 64 维结果拼成 768 维，只是并排放着，乘 W_o 以后，每一维才能从所有头取信息。它也是每个词单独算的。

- **头是并排的**：同一层里 12 个头同时算，拼接后乘 W_o。
- **层是叠起来的**：12 层依次算。BERT-base 的头数和层数恰好都是 12。每层有自己的 W_q、W_k、W_v、W_o 和前馈层，不共享。

一层的参数量里有一个巧合，容易把 W_o 误记成前馈层的参数：

| | 计算 | 参数 |
|---|---|---:|
| 注意力 W_q、W_k、W_v、W_o 加偏置 | 4 × (768×768 + 768) | 2,362,368 |
| 前馈层 W_1 加偏置 | 768×3072 + 3072 | 2,362,368 |
| 前馈层 W_2 加偏置 | 3072×768 + 768 | 2,360,064 |

因为 3072 = 4 × 768。一层前馈层共 4,722,432 个参数，12 层约 5,667 万。

### 2.5 参数与中间结果

| | 有哪些 | 特点 |
|---|---|---|
| 参数（学出来的） | W_q、W_k、W_v、W_o，前馈层 W_1、W_2，LayerNorm 的 γ、β，词向量表、位置表 | 训练时靠反向传播更新，训练完固定，所有句子共用 |
| 中间结果（算出来的） | q、k、v、分数、权重、权重 × V、Δx、每一层的 x | 每来一句话重新算一遍，用完就丢 |

“更新 x”说的是这句话里每个词的向量被一层一层改写；前向计算时参数不会变。

### 2.6 三个“让路好走”的设计

| 设计 | 防止什么 | 作用在哪 |
|---|---|---|
| 除以 √d | 分数太大，softmax 饱和，梯度接近 0 | 注意力打分 |
| LayerNorm | 数值尺度忽大忽小、逐层变大 | 每个子层之后，以及 embedding 之后 |
| 残差连接 | 信息被后面的层冲掉；梯度消失 | 每个子层外面 |

残差的求导：x + f(x) 对 x 的导数是 1 + f′(x)。链式法则把每层的导数连乘，每项都小于 1 时乘二十几次就接近 0；有了这个 1，梯度总有一条直通的路。这里解决的是**梯度消失**，梯度下降是训练算法本身。

### 2.7 “能学会”不等于“好学会”

问题：如果 embedding 后面不做 LayerNorm，而位置向量在 ±2、词向量在 ±0.05，x 主要反映位置，第 1 层的注意力主要按位置分配。既然是有标签的监督学习，训练不是可以把模型调成关注想要的东西吗？

要分清两件事：

- **表达能力**：模型有没有可能表示出想要的函数。只要参数合适，模型能把词义那一部分放大，这一点没错。
- **可优化性**：梯度下降能不能又快又稳地找到它。LayerNorm 解决的是这个。

原因有三个：

1. **一个学习率管不了尺度差很多的参数**，就像吴恩达课里的特征缩放。模拟：房价 = 0.1 × 面积 + 20 × 卧室数，面积在 300–2000，卧室数在 1–5（200 条数据）。

   | 设置 | 结果 |
   |---|---|
   | 不缩放，第一步梯度 | 面积 −249,772，卧室数 −600，差 400 多倍 |
   | 不缩放，学习率 2e-6 | 50 步就发散 |
   | 不缩放，学习率 1e-6，1000 步 | w_面积 = 0.143，w_卧室 = 0.061（应为 20） |
   | 先标准化，学习率 0.1，100 步 | w_面积 = 0.100，w_卧室 = 20.00 |

2. **softmax 饱和后梯度接近 0**，模型一开始只看位置，就很难再改过来。
3. **位置和词义怎么平衡，主要是在预训练里学的**。MLM 的标签就是被遮住的词，属于自监督学习；微调只有几轮、学习率 2e-5，只能在预训练的基础上做小幅调整。

另外，问题不只出在参数尺度上，还出在前向传播的数值上。微调时 Trainer 默认用的 AdamW 已经给每个参数各自的步长，仍然需要 LayerNorm，因为每层的 x + Δx 会让数值逐层变大。

一句话：**损失函数决定往哪走，归一化决定走不走得动。**（BERT 的默认配置里，词向量和位置向量都用标准差 0.02 初始化，一开始尺度本来就差不多；上面的问题是假设出来的极端情况。）

三种归一化的公式相同，统计方向不同：

| | 对谁求均值和标准差 |
|---|---|
| 吴恩达课里的特征缩放（z-score） | 同一个特征，跨所有样本（一列） |
| BatchNorm | 同一个特征，跨一批样本（一列） |
| LayerNorm | 同一个样本，跨它的所有特征（一行） |

## 3. DeBERTa

### 3.1 改动总览

| 版本 | 改了什么 | 解决什么问题 | 小节 |
|---|---|---|---|
| v1 | 解耦注意力：内容分 + 两项相对位置分 | 词义和位置混在一个向量里 | 3.2–3.6 |
| v1 | EMD：绝对位置在最后才加 | 只用相对位置，分不清句中角色 | 3.7 |
| v2 | 128K 词表、相对位置对数分桶、位置与内容共用投影矩阵 | 模型更大、更省参数 | 3.3、3.5 |
| v3 | RTD：替换词检测 | MLM 只有 15% 的位置有训练信号，输入里还有 [MASK] | 3.8 |
| v3 | GDES：E_D = sg(E_G) + E_Δ | 生成器和判别器共用词向量时互相拉扯 | 3.9 |

一层里的流程（投影、切头、softmax、乘 V、拼接、W_o、残差 + LayerNorm、前馈层）和 BERT 一样，**只改了每个头里“算分数”这一步**。

### 3.2 输入：只有词向量

| | 进入第 1 层的 x |
|---|---|
| BERT | 词向量 + 绝对位置向量 + 段落向量，再 LayerNorm |
| DeBERTa | 只有词向量，再 LayerNorm |

所以 DeBERTa 的 x 只表示“这个词是什么意思”，叫**内容向量 H**。相对位置在每一层打分时另外加入。

### 3.3 相对位置表 P 与 δ

- **P 表**：2k 行，每行一个向量，代表一种“距离”。k 是最多区分到多远，是事先设定的超参数：v1 里 k = 512（1024 行），玩具里 k = 4（8 行）。表里的数随机初始化、靠反向传播学习；**所有层共用同一张 P**。
- **δ**：把两个词的距离换成查表的行号，是固定的公式，不是学出来的。i、j 是 token 在句子里的序号（0、1、2……）。

```python
def delta(i, j, k=4):
    r = i - j                     # 距离：query 的位置减 key 的位置，可能是负数
    if r <= -k: return 0          # 太远，并到第 0 行
    if r >= k:  return 2*k - 1    # 太远，并到最后一行
    return r + k                  # 平移 k，变成 0 到 2k−1 的行号
```

| 距离 r | ≤ −4 | −3 | −2 | −1 | 0 | +1 | +2 | ≥ +3 |
|---|---|---|---|---|---|---|---|---|
| 行号 δ（k = 4） | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |

BERT 查位置表时，位置号直接就是行号；DeBERTa 的行代表距离，距离可能是负数，所以要平移。超出范围的距离并到两端：v1 里隔 600 个词和隔 5000 个词查到的是同一行。v2 起改成对数分桶，近处每个距离一行，越远分得越粗。

### 3.4 位置怎么影响打分

**先看简化版**：如果每一行只存一个数，表示“隔这么远加多少分”（T5 就是这样做的），那么分数 = 内容分 + 距离加分。分数高，softmax 后权重就大，bad 的 Δx 里混入的 not 就多。

**DeBERTa 的做法**：每一行存一个向量，加分 = 内容向量 · 这一行，所以加分还取决于“谁在问”：

| | 查第 5 行（r = +1），P[5] = [0.9, 0.4] | 查第 7 行（r = +4），P[7] = [−0.1, 0] |
|---|---:|---:|
| bad，H = [1.0, 0.5] | 1.10 | −0.10 |
| the，H = [−0.5, 1.0]（假设） | −0.05 | 0.05 |

bad 很在意紧挨在它前面的位置，the 几乎不在意。

```text
not 的位置变了 → 距离 r 变了 → 查到 P 表的另一行 → 位置加分变了
→ 总分变了 → softmax 权重变了 → bad 的 Δx 里混入多少 not 变了
```

### 3.5 解耦注意力：一个头内部的维度

以 “not very bad” 为例，n = 3，每个头 64 维，玩具 2k = 8：

```text
输入：H  3 × 768（内容）          P  8 × 768（相对位置表，所有层共用）

投影：Q_c = H × W_q,c    3 × 64     Q_r = P × W_q,r    8 × 64
      K_c = H × W_k,c    3 × 64     K_r = P × W_k,r    8 × 64
      V_c = H × W_v,c    3 × 64     （没有 V_r）

① 内容→内容   c2c = Q_c × K_cᵀ                3 × 3
② 内容→位置   c2p_all = Q_c × K_rᵀ            3 × 8   每个词 × 每种距离
              第 i 行第 j 列：取 c2p_all[i, δ(i,j)]   → 3 × 3
③ 位置→内容   p2c_all = K_c × Q_rᵀ            3 × 8
              第 i 行第 j 列：取 p2c_all[j, δ(j,i)]   → 3 × 3
④ 三张表逐格相加，除以 √(3 × 64)               3 × 3
⑤ softmax（按行）                              3 × 3
⑥ 权重 × V_c                                   3 × 64   这个头的输出（Δx 的一段）

12 个头拼接 → 3 × 768 → × W_o → + H → LayerNorm → 前馈层 → ……（和 BERT 一样）
```

- **三张表是相加，不是拼接**：第 i 行第 j 列只装一个数，“第 i 个词看第 j 个词打多少分”。三项是这一个分数的三个组成部分：词义配不配 + 我在不在意这个距离 + 对方在这个距离上值不值得看。softmax 需要每对词只有一个分数。
- **先算“所有可能”，再挑数**：c2p_all 是 3 × 8，挑完才变成和 c2c 一样的 3 × 3。
- **c2p 用 query 那一行，p2c 用 key 那一行**。p2c 的距离从 key 的角度算，相当于把方向倒过来。
- **除以 √(3d)**：三项相加，方差约是单项的 3 倍。论文说这一点对稳定训练很重要。
- **位置→位置这一项被去掉了**：两边都是相对位置，不含任何内容，论文认为它提供不了多少额外信息。
- **softmax 在每个头里面做**，在乘 V 之前；12 个头拼接、乘 W_o 之后才加回 x。
- v1 里位置这边的投影矩阵 W_q,r、W_k,r 是另外一套；v2 起和内容这边共用，W_k,r = W_k,c、W_q,r = W_q,c。

“not very bad” 里每一格的 δ(i,j)：

| query \ key | not（0） | very（1） | bad（2） |
|---|---|---|---|
| not | r = 0 → 4 | −1 → 3 | −2 → 2 |
| very | +1 → 5 | 0 → 4 | −1 → 3 |
| bad | +2 → 6 | +1 → 5 | 0 → 4 |

bad 看 not 时：内容→位置取 c2p_all 第 2 行（bad）第 6 列；位置→内容取 p2c_all 第 0 行（not）第 δ(0, 2) = 2 列。

**为什么位置没有 V**：V 是最后真正混进输出的内容。DeBERTa 让位置只决定“看谁、看多少”，不作为内容交出去：P 表里只有距离信息，和这句话说了什么无关；给它 V 的话，每个词的输出里又会混进“距离向量”，回到 BERT 把位置和词义搅在一起的老问题。位置信息仍然会间接传下去：它改变了权重，权重决定 bad 混入多少 not 的内容。

### 3.6 完整数字例：“not bad”

设定：not 在位置 0，bad 在位置 1；2 维、1 个头、所有投影取单位矩阵（Q_c = K_c = V_c = H，Q_r = K_r = P），k = 4。

P 表（8 行）：

| δ | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| P[δ] | [−0.2, 0.1] | [−0.1, 0.2] | [0.1, 0.3] | [0.6, −0.2] | [0, 0] | [0.9, 0.4] | [0.2, 0.1] | [−0.1, 0] |

**① 内容→内容**（行是 query，列是 key）

| | 看 not | 看 bad |
|---|---:|---:|
| not | 1.00 | 0.50 |
| bad | 0.50 | 1.25 |

**② 内容→位置**：先算 bad 对 8 种距离各有多在意，H(bad) 依次点乘 P 的每一行：

| δ | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| bad · P[δ] | −0.15 | 0 | 0.25 | 0.50 | 0 | **1.10** | 0.25 | −0.10 |

bad 看 not：r = +1，取第 5 列，得 1.10；bad 看自己：r = 0，取第 4 列，得 0。

**③ 位置→内容**：not 对 8 种距离的值是 [−0.22, −0.20, −0.10, **0.60**, 0, 0.48, 0.10, −0.08]。bad 看 not 时，从 not 的角度算距离 r = 0 − 1 = −1，取第 3 列，得 0.60。

**④ 相加，除以 √6**（d = 2）

| | 看 not | 看 bad |
|---|---:|---:|
| not | 1.00 → 0.408 | 2.20 → 0.898 |
| bad | 2.20 → 0.898 | 1.25 → 0.510 |

**⑤ softmax**：bad 那一行 [0.898, 0.510] → [0.596, 0.404]。

**⑥ 乘 V，更新 x**：Δx_bad = 0.596 × [0.8, −0.6] + 0.404 × [1.0, 0.5] = [0.881, −0.155]；x + Δx = [1.881, 0.345]，再做 LayerNorm、过前馈层。

**对比**：只用内容→内容（除以 √2）时，bad 那一行的权重是 [0.37, 0.63]；加上两项位置分后是 [0.596, 0.404]，not 的权重从 0.37 升到 0.60。

**改变距离**（bad 看 not，内容分始终是 0.50）：

| not 在 bad 前面第几个 | δ(i,j) | δ(j,i) | 内容→位置 | 位置→内容 | ÷√6 后的分数 |
|---|---:|---:|---:|---:|---:|
| 1（not bad） | 5 | 3 | 1.10 | 0.60 | 0.898 |
| 2（not very bad） | 6 | 2 | 0.25 | −0.10 | 0.265 |
| 4 | 7 | 0 | −0.10 | −0.22 | 0.073 |

表里 not→bad 和 bad→not 都是 2.20，是因为投影都取了单位矩阵；真实模型里各个 W 不同，不会对称。

**相对位置的好处**：“not bad” 出现在句首（位置 1、2）和第 40、41 个位置时，BERT 加的是位置表的不同行，“否定词就在前一位”这个规律要从不同的绝对位置组合里分别学；DeBERTa 两次都是 r = +1，查的都是第 5 行，规律只需学一次，在句子哪里都能用。

### 3.7 绝对位置从哪里来：锚点与 EMD

**[CLS] 和 [SEP] 是锚点**（这是根据结构做的推理，论文没有专门验证）：[CLS] 永远在第 0 个位置，第 i 个词和它的距离 r = i，正好等于绝对位置。

```text
第 i 个词看 [CLS] → 距离 r = i → 查 P 表的第 δ(i, 0) 行
→ 分数随 i 变 → 给 [CLS] 的权重随 i 变 → Δx 随 i 变 → 位置信息进入 H
```

[SEP] 在最后一个位置，和它的距离就是“离结尾还有多远”。限制有两点：这是间接的，要模型自己学会利用；太远的距离会并到同一行（v1 超过 512），v3 的对数分桶在远处也分得比较粗。

**EMD（增强的掩码解码器）**：论文的例子 “a new store opened beside the new mall”，把 store 和 mall 都遮住让模型猜。两个空左边都是 new，相对位置看到的局部上下文几乎一样，但第一个是主语、第二个是介词后的宾语，区分它们需要绝对位置。

| | 绝对位置在哪里加 | 第 1–12 层的注意力能看到绝对位置吗 |
|---|---|---|
| BERT | 输入时，和词向量相加 | 能，而且一直和词义混在一起 |
| DeBERTa | 12 层全部算完之后、预测被遮词的 softmax 之前 | 不能，只用相对位置 |

```text
带 [MASK] 的句子 → 词向量（不加位置）→ LayerNorm
→ 12 层解耦注意力编码器（只用相对位置 P）
→ EMD：加上绝对位置 → 再过 2 层 Transformer（两层共享权重）
→ 预测每个 [MASK] 是词表里的哪个词
```

论文推测，像 BERT 那样一开始就加入绝对位置，可能会妨碍模型充分学习相对位置。EMD 只为预训练里“预测被遮的词”服务，做 IMDB 分类时用不到。

### 3.8 v3：替换词检测（RTD）

**MLM 浪费在哪**：一句 512 个 token 的话，全部要过完 12 层，但只有约 15% 被遮的位置有标签、能算损失。其余 85% 的位置不直接产生学习信号（它们作为上下文，梯度仍会经过它们）。另外，预训练时输入里有 [MASK]，微调和使用时从来没有，80/10/10 只能缓解。

**RTD**（来自 ELECTRA）需要两个模型：

| | 任务 | 规模 | 预训练完以后 |
|---|---|---|---|
| 生成器 | 做 MLM：猜被遮的词，填一个看起来合理的词 | v3 里宽度相同、层数减半 | 丢掉 |
| 判别器 | 对每个词判断：原来的还是被换过的 | 大，就是最终的 DeBERTa | 保留，拿去微调 |

```text
原句：         the  movie  is  not    bad
生成器的输入： the  movie  is  [MASK] bad     ← [MASK] 只出现在这里
生成器的输出： the  movie  is  very   bad     ← 猜成了 very
判别器的标签： 原   原     原  换     原      ← 每个位置都有标签
```

- 100% 的位置都有标签，每份算力都换来训练信号。
- 判别器的输入里没有 [MASK]，预训练和微调的输入一致。
- **生成器碰巧猜回原词时，标签是“原”**：判别器只看到生成器填完的句子，“从没被遮过的 not”和“被遮后又被猜回来的 not”输入完全一样，如果标签不同，就是判别器不可能学会的噪声。ELECTRA 论文报告这样规定对下游任务有一定提升。判别器判断的是“这个词和原文一致吗”。

### 3.9 v3：GDES

生成器和判别器都需要一张词向量表（v3 是 128K × 768）。ELECTRA 让两者共用一张表，但两个任务的要求相反：

| | 想要什么 | 对 good 和 great |
|---|---|---|
| 生成器（MLM） | 意思相近的词向量靠近，因为两个词都能填进同一个空 | 拉近 |
| 判别器（RTD） | 分辨“这里原来是 good，还是被换成了 great” | 推开 |

GDES：**E_D = sg(E_G) + E_Δ**

- E_G：生成器的词向量表，只由 MLM 训练。
- sg（stop gradient）：判别器可以读 E_G，但 RTD 的梯度不传回去改它。
- E_Δ：判别器自己的修正表，**从全零开始**，只由 RTD 训练。
- 预训练结束后，E_G + E_Δ 合并成一张表，存为判别器的词向量。下载到的 deberta-v3 里没有单独的 E_Δ。

如果去掉 sg，就退化成 ELECTRA 的共用词向量：RTD 把 good 和 great 推开 → 生成器的 MLM 学不好 → 替换词质量变差、太容易被识破 → 判别器学到的东西变少。DeBERTa v1、v2 用的是 MLM，没有生成器和判别器，所以不存在这个问题。DeBERTaV3-large 在 GLUE 上平均 91.37。

### 3.10 微调 IMDB 时剩下什么

| 部件 | 还在吗 | 原因 |
|---|---|---|
| 生成器 | ✗ | 只负责给判别器出题，预训练完就丢掉 |
| 判别器的 12 层编码器 | ✓ | 就是 deberta-v3-base 本身 |
| 相对位置表 P | ✓ | 每一层打分都要用 |
| EMD | ✗ | 只为预测被遮的词服务 |
| 单独的 E_Δ | ✗ | 已经合并进词向量表 |
| 池化层、分类头 | ✓，新加的 | 随机初始化，微调时从头学；加载时 Hugging Face 会提示它们是新初始化的，不是报错 |

微调时的数据流：影评 → 词向量 → 12 层编码器 → 取 [CLS] 那一行 → 池化层 → 分类头 → 正面 / 负面。

## 4. 微调（路线 A）要点

### 4.1 学习率要小：防止灾难性遗忘

```text
分类头随机初始化 → 一开始几乎瞎猜，损失大 → 梯度又大又乱，一路传回 12 层编码器
→ 学习率也大的话，每一步都大幅改动预训练好的参数 → 预训练学到的东西被冲掉
```

| 设置 | 值 | 作用 |
|---|---|---|
| 学习率 | 2e-5 | 每一步只改一点。BERT 预训练用 1e-4，论文推荐的微调学习率是 2e-5 到 5e-5 |
| warmup | 前 10% 的步数 | 学习率从 0 慢慢升到 2e-5，分类头还在瞎猜时步子最小 |
| 线性衰减、3 轮 | | 后期学习率降回 0，训练时间短，参数不会离预训练状态太远 |

Sun 等（2019）在 IMDb 上用的也是 2e-5 和 10% warmup。

### 4.2 LoRA 为什么能用大得多的学习率

LoRA 冻结原来的 W，只学一个低秩修正量：W′ = W + B·A。**B 初始化为全零**，所以第一步时 W′ 就等于预训练好的 W，从一个好的起点出发再慢慢改。W 被冻结，学习率再大也伤不到预训练的知识；B、A 学歪了，拿掉就能恢复原样。

“原来的 + 学一个修正量”这个思路这一轮出现了三次：

| | 原来的 | 学的修正量 |
|---|---|---|
| 残差连接 | x | Δx |
| GDES | E_G | E_Δ |
| LoRA | W | B·A |

我的 BERT LoRA 沿用了全量微调的 2e-5：验证 AUC 0.935947 → 0.947399 → 0.949744，到第 3 轮还在涨，Kaggle AUC 0.95315，比全量的 0.97522 低约 0.02。LoRA 论文给 RoBERTa-base 的 LoRA 学习率是 4e-4 到 5e-4。学习率偏小、没学完是候选解释，还没用实验验证。

### 4.3 长影评截断

IMDb 影评平均 292 个 WordPiece 词片，最长 3,045，12.69% 超过 512（Sun 等，2019）。他们用 BERT-base 比较了几种做法：

| 方法 | IMDb 测试错误率 |
|---|---:|
| 只取开头 510 | 5.63% |
| 只取结尾 510 | 5.44% |
| 开头 128 + 结尾 382 | **5.42%** |
| 分段后取平均 | 5.89% |
| 分段后取最大 | 5.71% |
| 分段后再做注意力 | 5.49% |

影评常常是背景、分析、总结的结构，结论多在结尾，所以结尾比开头重要；也有一上来就下结论的，所以开头留 128 个。几种方法相差不到 0.5 个百分点，因为只有超过 512 的影评才受影响。我的 BERT 只取开头 256，看不到长影评最后的总结句，被截断的影评也比截到 512 时多。网页 §4.2 有替换 `tokenize_frame` 的代码。

DeBERTa 预训练时的序列长度是 512，所以通常也截到 512。

### 4.4 batch 与梯度累积

- **batch**：看完一批数据，把这一批的梯度取平均，再更新一次参数。batch 越大，平均出来的梯度越稳，但这一批要同时放进 GPU，显存占用越多。
- **`train_batch_size`**：GPU 一次放进去几条，决定显存占用。
- **`gradient_accumulation_steps`**：攒几次梯度才更新一次参数。
- **有效 batch** = 两者相乘，即每次更新时平均了多少条数据的梯度。

以训练集 20,000 条跑一轮为例：

| 设置 | 有效 batch | GPU 前向 + 反向次数 | 参数更新次数 |
|---|---:|---:|---:|
| 16 × 1 | 16 | 1,250 | 1,250 |
| 8 × 2 | 16 | 2,500 | 1,250 |
| 4 × 4 | 16 | 5,000 | 1,250 |
| 1 × 16 | 16 | 20,000 | 1,250 |
| 1 × 1 | 1 | 20,000 | 20,000 |

- **攒梯度时参数一直不变**，16 个梯度都是在同一组参数上算的，和一次放 16 条算出的平均梯度相同，所以不存在“攒久了梯度过时”。过时梯度是另一种场景：多台机器异步训练，A 还在用旧参数算梯度，B 已经更新了参数。
- **1 × 16 的代价是慢**：每次只放 1 条，GPU 的并行算力用不满，还要多付很多次调用的开销。序列越短、模型越小，差距越明显。1 × 1 同样慢，而且每一步只根据一条数据更新，方向很乱。
- 实际做法：先选显存放得下的最大 batch，不够的部分用累积补齐。微调 BERT 常用的 batch 是 16 或 32（BERT 论文推荐）。
- 梯度里有些噪声有时对泛化有好处，batch 不是越大越好。
- 有 BatchNorm 的模型，batch 大小会改变它统计的均值和标准差；BERT、DeBERTa 用 LayerNorm，每个词单独归一化，不受影响。

## 5. 大模型（路线 B）

### 5.1 三种用法

| 用法 | 怎么做 | 能算什么 |
|---|---|---|
| 只要答案 | 模型回答 -1 或 1（SST-2 实验就是这样） | 只有准确率 |
| 读概率 | 只生成 1 个 token，读 “1” 和 “-” 的概率 | AUC，能提交 Kaggle |
| 让它学 | LoRA 微调、嵌入 + 分类器、蒸馏 | 和路线 A 一样的分类器 |

### 5.2 从回答里读出概率

大模型的最后一层和 BERT 的 MLM 头是同一种结构：最后一个位置的向量 × 输出矩阵 → 词表里每个 token 一个分数 → softmax → 每个 token 的概率。temperature = 0 时选概率最大的那个输出。只拿回答的话，这张概率表就被丢掉了，和交标签丢掉概率是一回事。

**为什么只看第一个 token**：SST-2 的输出 token 数对得上“-1 是两个 token”：

- DeepSeek：预测 -1 的 456 条 × 2 + 预测 1 的 416 条 × 1 = 1,328
- Qwen3.5 4B（每条多一个结束符）：442 × 3 + 430 × 2 = 2,186

“-1” 被切成 “-” 和 “1”，“1” 只有一个 token。第一个 token 是 “1” 就是正面，是 “-” 就是负面，所以 `max_tokens = 1` 就够了，费用几乎全是输入。

**换算**：接口返回的是对数概率 logprob，先取指数，再只在两个候选之间归一化：

| | logprob | 概率 |
|---|---:|---:|
| “1” | −0.05 | e^−0.05 = 0.9512 |
| “-” | −3.2 | e^−3.2 = 0.0408 |
| 其他所有 token | | 0.0080 |

p(正面) = 0.9512 ÷ (0.9512 + 0.0408) = 0.959。其他 token（“Positive”、空格等）不参与。

注意：DeepSeek 的 `logprobs`、`top_logprobs` 参数是从第三方整理的接口文档里查到的；Ollama 从 0.12 起支持 logprobs（Kaggle 上用的是 0.40.3）。批量跑之前先发一条，确认返回里确实有 logprobs。两个候选都不在 top_logprobs 里的影评要单独报告，不要偷偷填 0.5。

### 5.3 少样本

在要判断的影评前面放 k 条带答案的例子：

```text
指令：判断情感，回答 -1 或 1
### Question: 例子 1（正面）  ### Response: 1
### Question: 例子 2（负面）  ### Response: -1
……
### Question: 要判断的影评    ### Response: ← 模型从这里接着写
```

| 规则 | 防止什么 |
|---|---|
| 例子只从训练集里挑 | 用了验证集的影评就是把答案泄露给模型，验证分数虚高（数据泄露） |
| 正负各半、打乱顺序 | 例子多数是正面，或最后一条是正面，模型会倾向于跟着回答；顺序本身也会影响结果 |
| 挑短的当例子 | IMDB 影评平均约 300 个 token，放几条长例子，每次请求的输入会翻几倍 |

例子里的回答都写成 “1” 和 “-1”，也给模型示范了格式，第一个 token 更容易落在 “1” 或 “-” 上。

**少样本不更新参数**：没有损失函数，没有反向传播，例子只是输入里多出来的一段文字，请求结束后模型和原来一样。它起作用靠的是注意力：在 “### Response:” 这个位置生成答案时，它的 q 能和前面所有 token 的 k 打分，包括例子里的 token，例子的信息直接混进 Δx。所以它不需要和预训练数据“竞争”，“4 条例子相对预训练数据量太少”这个比较不成立。“会看样例照着做”这种能力是预训练中学会的，叫**上下文学习**（in-context learning）。

情感分类这种任务，模型零样本已经很懂（SST-2 零样本 93.8%–95.2%），少样本的提升可能不大，更大的作用可能是统一格式、让概率更稳。到底多大，要用同一批 1,000 条验证影评比较 k = 0、2、4 才知道。

## 7. 易混点

| 我的理解 | 更正 |
|---|---|
| 三个向量相加是拼接（768 → 更多维） | 逐位相加，仍是 768 维 |
| DeBERTa 的三张分数表拼接起来 | 逐格相加，每对词只有一个分数 |
| 多头合并、LayerNorm 之后再 softmax | softmax 在每个头里面、乘 V 之前 |
| 一个头的输出直接加回 x | 12 个头拼接、乘 W_o 之后，才和 x 相加 |
| 残差加的是本层的输出 | 加的是子层的输入：注意力后加 H，前馈后加 A |
| 残差解决梯度下降的问题 | 解决的是梯度消失 |
| LayerNorm 只是学习率的问题 | 也管前向传播的数值稳定，用 AdamW 也需要它 |
| 位置和词义怎么平衡是微调时学的 | 主要在预训练里学，MLM 本身有标签（自监督） |
| “权重 × V” 是学出来的 | 是每句话现算的中间结果；W_v 才是参数 |
| 梯度累积是分块训练 / 跨的步数一样 | 攒几个小批的梯度，再更新一次参数 |
| 攒久了梯度会过时 | 攒的过程中参数不变，不会过时 |
| 判别器的输入里有 [MASK] | [MASK] 只在生成器的输入里 |
| 两个方向的注意力分数不同，是因为谁对谁更重要 | 那是结果；原因是看的一方乘 W_q、被看的一方乘 W_k，W_q ≠ W_k |
| LayerNorm 在 12 层之后；每层残差和 LayerNorm 各一次 | 每层两次：注意力后一次、前馈层后一次，12 层各 24 次 |
| 隐藏维度就是词向量 | 只有第一层入口是词向量加位置；之后每层每行长度不变，但已混入上下文 |
| 8 × 2 和 4 × 4 训出来不一定一样 | 每次更新都是同一组参数上 16 条数据的平均梯度，基本一致 |
