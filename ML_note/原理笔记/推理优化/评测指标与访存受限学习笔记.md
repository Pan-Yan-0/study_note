# 评测指标与访存受限学习笔记

读 [ShortGPT BI 删层实验](../../实验/ShortGPT_BI删层/README.md) 正式结果时学的：表里每个指标是什么意思，PPL 和准确率为什么会给出相反的结论，删层为什么能加速，以及 KV cache 怎么存。显存大小的估算见 [显存估算学习笔记](显存估算学习笔记.md)。

## 1. 质量指标

### PPL（困惑度，perplexity）
- 让模型在一段文本上逐个预测下一个 token，取每一步正确 token 的 −ln p 的平均值，再取 exp。
- PPL = 10，相当于每一步平均在 10 个同样可能的词里犹豫。**越低越好。**
- 用到的 p 是 softmax 之后，模型在整个词表（Qwen3 约 15 万个词）上给**正确那个词**的概率，看的是概率的**绝对值**。

### 零样本选择题（lm-eval）
| 任务 | 考什么 | 选项数 | 随机水平 |
|---|---|---|---|
| piqa | 物理常识 | 2 | 50% |
| arc_easy | 小学科学题 | 4 | 25% |
| winogrande | 代词指代 | 2 | 50% |

- **打分方式**：模型不生成答案，而是对每个选项算"问题 + 选项"整段的对数概率（log-likelihood），选最高的。看的是选项之间的**相对顺序**。
- **零样本**：提示里不给例题。
- **acc 和 acc_norm**：acc 直接比总对数概率，会偏向短选项；acc_norm 先按选项长度归一化再比。
- **看准确率先找随机水平**：二选一的 52% 几乎是乱猜，四选一的 52% 不是。也可以算"高出随机的部分还剩多少"。

### PPL 和准确率为什么会不一致
| | PPL | 选择题 |
|---|---|---|
| 要做的事 | 在约 15 万个词里给正确词高概率 | 只比较 2–4 个选项谁高 |
| 看的是 | 概率的绝对值 | 选项的相对顺序 |

例：删掉最后两层后，p(mat) 从 0.5 降到 0.0001，p(rug) 从 0.1 降到 0.00002。这一步的交叉熵从 0.69 涨到 9.2，PPL 爆炸；但 mat 仍然比 rug 大，选择题照样选对。

## 2. 速度指标

| 指标 | 含义 | 好坏 |
|---|---|---|
| prefill | 把整段输入一次性算完，存进 KV cache | |
| decode | 一个一个地生成新 token，每生成一个都要把整个模型跑一遍 | |
| TTFT（首 token 时间） | 从请求到第一个 token 的时间，约等于 prefill | 越短越好 |
| decode 吞吐（tok/s） | 每秒生成多少个 token | 越高越好 |
| batch size（bs1、bs8） | 一次同时服务几个请求；bs8 的吞吐是 8 个请求加起来的 | |
| 加速比（speedup） | 删层后的速度 ÷ 原模型的速度 | |

## 3. 访存受限（memory-bound）

batch 1 decode 时，每生成一个 token 要把权重从显存读一遍，每个权重只参与约 2 次运算。以 T4 上的 Qwen3-8B 为例：

| | 量 | T4 的能力 | 时间 |
|---|---|---|---|
| 读权重 | 约 15 GB | 带宽约 320 GB/s | 约 47 ms |
| 计算 | 约 15 GFLOP | 约 65 TFLOPS | 约 0.23 ms |

读数据的时间是计算的约 200 倍，叫**访存受限**；反过来计算占主导叫**计算受限（compute-bound）**。这时 decode 速度 ≈ 带宽 ÷ 每个 token 要读的字节数，所以**少读字节就是加速的主要手段**：删层少读整层，量化让每个参数少占字节，KV cache 压缩少读缓存。

**为什么删 9 层的加速比接近层数之比（1.33），而不是参数之比（1.27）**：生成一个 token 时，词嵌入只查当前词的那一行，几乎不读；解码层和 lm_head 要全部读。

| 部分 | 参数量 | 每个 token 要读 |
|---|---|---|
| 词嵌入 | 0.62B | 只读 1 行 |
| 36 个解码层 | 6.95B | 全部 |
| lm_head | 0.62B | 全部 |

完整模型每个 token 实际要读 6.95 + 0.62 = 7.57B 个参数，删 9 层后要读 6.95 × 27/36 + 0.62 = 5.83B，比值约 1.30，和实测的 1.31 吻合。每层还有一份固定开销（启动 GPU 小任务），也会让加速比更接近层数之比。

**batch 为什么能提高吞吐**：权重读一次，可以同时给多个请求各算一个 token，读权重的成本被分摊了。实测 bs8 吞吐约是 bs1 的 4 倍，没到 8 倍，因为 KV cache 也要读，还有其他开销。

**深还是宽**：同样的参数量，宽而浅的模型推理通常更快（依次经过的层少、固定开销少）；但质量上，深一些的模型往往更好。这是质量和速度的权衡。

## 4. KV cache 怎么存

- 存的就是原始的 FP16 数字。
- **HF transformers**：每层一个 K 张量和一个 V 张量，形状 `[batch, KV 头数, 已有 token 数, head_dim]`，新 token 用 `torch.cat` 拼到末尾。类似 `std::vector` 不停 `push_back`，容量不够就重新申请、整体拷贝。
- **vLLM 的 PagedAttention**：借用操作系统的分页思想，把 KV cache 切成固定大小的块（如每块 16 个 token）按需分配；一个请求的块可以不连续，用块表记录顺序。好处是不用按最大长度预占显存、没有碎片、多个请求能共享相同前缀的块。
- 也可以不按原始位数存：KV 量化（INT8 / FP8）、GQA（少存 KV 头）、KV 淘汰（少存 token）。

## 5. 易混点

| 容易说错的 | 正确说法 |
|---|---|
| "深层"指中间的层 | 深层是离输入远、编号大的层；靠近输入的叫浅层 |
| BI 高低是训练时梯度大小造成的 | BI 是在训练好的模型上只做前向测出来的。深层 BI 低，是因为残差不断累加，单独一层的 Δx 相对于 x 很小；第 0 层要把词嵌入改造成内部表示，最后一层要转换成预测词的形式，所以变化大 |
| PPL 低的删法，选择题也一定好 | PPL 看绝对概率，选择题看相对顺序，两者可以给出相反的结论 |
| 参数少了多少，就快多少 | decode 时要看每个 token 实际读多少字节；词嵌入几乎不读 |
| bs8 的 48 tok/s 是单个请求变快了 | 是 8 个请求加起来的吞吐 |

## 6. 检查题与作答

| 题目 | 我的作答 | 判定与要点 |
|---|---|---|
| X 的 PPL 20、winogrande 52%，Y 的 PPL 5、70%，哪个好？ | Y 好；X 的 52% 几乎是乱猜（随机 50%）；PPL 20 是平均在 20 个词里犹豫 | ✓ |
| BI 最低的层在哪一段？为什么第 0 层和最后一层偏高？ | 后段（25–33），和 ShortGPT 一致；用梯度传递和残差解释，最后一层要配合后面的分类器；预测第 33 层也偏高 | △。位置对；"深层"的意思原以为是中间层；BI 是前向测量，不能用梯度解释；第 33 层数据不支持 |
| 删 9 层后 PPL 和准确率掉得一样多吗？ | PPL 涨约 110 倍；三个任务相对下降 20% / 47% / 19%，高出随机的部分剩 12.0 / 17.6 / 4.8 个点；不一致，删后段会严重影响后面的分类，恢复很重要 | 计算 ✓；解释 △，关键是绝对概率与相对顺序 |
| 加速比更接近层数之比还是参数之比？ | bs1 1.30、bs8 1.32；层数之比 1.33、参数之比 1.26，更接近层数；猜是每层有额外开销 | 数字 ✓；原因 △，主要是词嵌入几乎不读 |
| 4B FP16、带宽 400 GB/s，batch 1 decode 的上限？INT4 呢？ | 8 GB / 400 GB/s = 0.02 s，约 50 tok/s，计算可以忽略；INT4 是 2 GB，约 200 tok/s | ✓。INT4 要有专门的 kernel 支持才能兑现 |
| BI 删 9 层和从后往前删 9 层，谁好？ | 按 PPL 是 BI 好，按准确率是从后往前删好；区别在 25、26 和 34、35 层，最后两层要配合后面的分类；汇报不能只报一个指标，要说清各指标的结果和权衡 | ✓ |
| 这套评测没测哪些能力？ | 推理能力 | △。还有自由生成、长上下文、遵循指令和写代码 |
| 主动提问 | 堆参数还是堆层更好；KV cache 到底怎么存；"绝对值"是不是 softmax 的结果 | 都是好问题，见第 3、4 节 |
