## 一、原始笔记整理

### 80 · 机器学习的迭代开发
ML 开发是一个**循环**：选模型/设计特征 → 训练 → 诊断 bias/variance → 判断缺什么 → 换模型/改特征/加数据 → 再训练……不是一条路走到黑，而是转着圈逼近好模型。

### 81 · 误差分析（error analysis）
- 人工翻看模型**分错的样本**，按错误类型分类统计，优先解决「占比最大」的那类错误——不要在稀有片段上死磕。
- 例子：垃圾邮件里「药品类」样本少且难判，先把能显著提升整体的部分做好。
- **这是性价比思维：改进方向的优先级 = 错误类型占比 × 可改进空间。**

### 82 · 添加数据
- 两条路：
  1. **数据增强（data augmentation）**：对现有数据做变换造新数据——图像旋转/扭曲/镜像最成熟（CV 方向常用），也可以人工合成类似样本；
  2. **人工标注新数据**：贵但有效。
- 注意适用条件（77 集结论）：只有 **high variance** 时加数据才有用。

### 83 · 迁移学习 ⭐（本轮最有价值的一集）
- 你的理解正确：拿一个在**超大数据集**上预训练好的网络，用自己的小数据集继续训练 = **微调（fine-tuning）**。
- 两种用法：
  - 只训练最后一层（前面全冻结）——小数据时；
  - 全部参数继续训练（用小学习率）——数据稍多时。
- 「这跟开源差不多」——洞察准确：预训练模型就是开源社区共享的「知识底座」，HuggingFace 整个生态建立在这上面。

### 84 · 机器学习项目的完整周期
确定项目范围 → 收集数据 → 训练模型 → **生产部署** → 监控 + 持续回流数据优化。
- 部署侧要点：用户隐私；部署后能收集真实使用数据反哺模型（数据飞轮）；上线后要持续监控性能衰减。

### 85 · 公平、偏见与伦理
- 部署前：组建多元团队头脑风暴可能出错的事（尤其对弱势群体的伤害）、检索行业标准、做危害审计、制定缓解计划。
- 部署后：持续监控危害。
- 机器学习要尽力不带偏见——严肃但必要的一课。

## 二、答疑 / 印证区

### Q1（ep82 印证）：为什么数据增强主要是 CV 在用？
你的观察对。因为图像的「语义不变变换」好找（旋转、裁剪、变色后猫还是猫），文本很难：改一个词可能直接反转情感（「好看」→「不好看」）。所以 NLP 更依赖迁移学习（预训练模型自带语言知识），这正是你 IMDB 项目从 GloVe 系走到 BERT 系的原因——**NLP 的「数据增强」很大程度上就是预训练本身**。

### Q2（ep83 印证）：你的迁移学习理解 = 你已经在做的事
- 冻结 GloVe 词向量（imdb 手写教程里的 `requires_grad=False`）= 迁移学习的「只练最后一层」模式；
- DistilBERT 微调 2–3 epoch = 「全部参数小学习率继续练」模式；
- 84 集的「数据飞轮」（部署→收数据→再训练）就是你导师实验室方向的雏形，也是 Kaggle 比赛排行榜的运行逻辑。
