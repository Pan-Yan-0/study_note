# 对照赛题原文的检查与 v3.1 改进计划

依据：2026 研赛 E 题题面原文，以及 v2 全量结果包的数据核对。v3 正在运行，本计划待 v3 结果出来后再定细节。

## 一、读题后必须处理的四件事（合规与可交付）

### 1. 附件3 没有 raw_text，v3 的 DeBERTa 输入在附件3 上不一致

- **数据事实：** 附件3 只有 `audio`、`vision`、`text_bert`、`id` 四个字段，既没有 `raw_text`，也没有 `text`。附件4 六个字段都有。
- **v3 的做法：** 训练、验证、测试、附件4 都用 `raw_text` 恢复大小写和标点再送进 DeBERTa。附件3 没有 `raw_text`，只能退回“从 BERT 子词拼回的小写文本”。所以正好在题目要求提交的附件3 上，输入分布与训练不一致。
- **题面口径：** `raw_text` 是“原始英文转写文本，**用于阅读核查，非数值特征**”；并且“应在训练、验证和专项测试中保持同一特征版本和**同一输入接口**”。
- **改法：** DeBERTa 的输入只从 `text_bert` 还原，不再读 `raw_text`，所有数据集走同一个接口。
  - v1/v2 的 BERT 路线本来只用 `text_bert`，是合规的。
  - `text_bert` 是附件2/3/4 唯一都有的文本字段（附件3 没有 `text`），这一点正好可以写进论文，作为选这个接口的理由。

### 2. 附件总大小 ≤ 50 MB，而且必须包含“模型参数文件”

- **题面要求：** 可复现材料包括问题二、问题三两类专项模型的“核心代码、说明文档、**模型参数文件**、配置文件”，外加问题一 100 条样本的特征文件，总计 ≤ 50 MB。
- **体积估算（可训练参数，冻结的主干不用交，写明版本即可）：**

| 模型 | 可训练参数 | fp32 | fp16 |
|---|---|---|---|
| BERT 系（LoRA r=8 q/v + 头部） | 约 0.76M | 约 3 MB（mg 约 4 MB） | 约 1.5 MB |
| DeBERTa 单模型（LoRA r=16 全部线性层 + 头部） | 约 7.68M | 29 MB | 15 MB |
| DeBERTa 5 种子集成 | 约 38M | 147 MB | 73 MB |

- **结论：** 5 种子集成交不上去。
- **改法：**
  - 部署规则事先加上体积上限；
  - 部署单个模型（fp16），或者把集成蒸馏成一个学生模型：用集成的软标签，只在训练集上训练；学生保留集成的大部分收益，体积仍约 15 MB。

**预算核算（问题一特征文件约 16 MB，已确认）：**

| 项目 | 体积 |
|---|---|
| 问题一：100 条样本特征 | 约 16 MB |
| 问题二：单个 DeBERTa 模型（LoRA + 头部，fp16） | 约 14.6 MB |
| 问题三：共享问题二的编码器，只交自己的可解释融合头（fp16） | 约 1 MB |
| 代码、说明、配置、两个结果 CSV（不含图片和日志） | 约 1–2 MB |
| **合计** | **约 33–34 MB，余量约 16 MB** |

- 如果问题二、问题三各交一个独立训练的 DeBERTa（fp16），合计约 47 MB，余量只有约 3 MB，不稳妥。
- 如果交 5 种子集成：fp16 要 73 MB，int8 也要约 38 MB，都超限。所以集成只能作为“参考上限”报告；要部署，就必须蒸馏成单个模型。
- 冻结的预训练主干（DeBERTa-v3-large、bert-base-uncased、MMS 对齐模型）都是公开模型，不放进附件，论文里写明名称和版本即可。
- 参数一律以 fp16 导出，并核对导出前后在验证集上的预测是否一致。

### 3. 题目要求“两类专项模型”，问题三需要自己的模型

- **题面要求：**
  - 问题三 (1) 要写可解释性模型的“建模原理、网络结构、目标函数、训练方案与关键参数”；
  - 附件提交也要“问题2和问题3两类专项模型”的参数文件。
- **现状：** 问题三直接用问题二的部署模型做事后解释，容易被认为没有“构建可解释性模型”。
- **建议（兼顾 50 MB 预算）：** 问题三专项模型 = 共享问题二的编码器（冻结）+ 问题三自己的“模态可加分解融合头”。
  - **结构：** 每个模态一个小网络，输出各自的类别对数几率和强度分布对数几率；三者相加，再加一个受惩罚的小交互项。每个模态的贡献可以直接从结构读出，再用精确 Shapley 核对。
  - **训练方案：** 在完整输入上做“模态子集随机整路丢弃”，覆盖全部 8 个子集。这样 Shapley 用到的 8 个子集取值都在训练分布内，模态作用度的忠实性有了依据。
  - **成本：** 编码器冻结，所以训练集的编码可以先缓存，训练融合头只要几分钟；参数约 1 MB。
  - 局部证据仍用遮挡得分，并用删除检验复核。

### 4. 身份信息

- v2 的 `log.txt` 中，输入路径含 Kaggle 用户名，共 74 处。代码本身没有。
- 提交材料若包含日志或报告，打包前要脱敏；v3.1 可以在日志里只记相对路径。

## 二、题面强调、目前做得不够的地方

1. **“常规固定权重融合……性能急剧下降”：**
   - 我们的 base 用了掩码池化，本身就很稳（≤50% 局部缺失只掉约 2 个 F1 点），论文里缺少“常规做法”的对照。
   - 建议加一个朴素零填充融合的 base：缺失位置当作真实的 0 参与池化，文本缺失位置保留注意力。同种子训练，画退化曲线。
   - 这样可以把“掩码池化 / 缺失增广 / 门控补偿”各自的贡献分开量化；这也正是审阅意见指出缺少的“去掉掩码池化”的匹配对照。
2. **“稳定输出”：** 各面板加两项稳定性指标：与完整输入相比的类别翻转率，以及强度变化 |Δŷ|。
3. **“缺失时长”：** aligned_50 的位置是词级，没有秒级时间。除了缺失比例，再按绝对缺失位置数分组（1–2 / 3–5 / 6–10 / >10）。
4. **评价口径：** 题面只写“F1 值”，没有说宏平均还是加权平均，应写明并两者都报。以 v2 base 为例：

| 集合 | 宏 F1 | 加权 F1 | Acc | MAE | Corr |
|---|---|---|---|---|---|
| 验证 | 0.620 | 0.641 | 0.641 | 0.567 | 0.685 |
| 测试 | 0.648 | 0.689 | 0.692 | 0.610 | 0.699 |

   题面要求的“基础性能评价”在验证集上，而验证集比测试集难：Acc 低约 5 个点，宏 F1 低约 3 个点。如果 F1、Acc ≥ 0.70 以验证集为准，宏 F1 需要提升约 8 个点，Acc 约 6 个点。
5. **附件3 的实际缺失形态（事后只读描述量，不参与训练与选择）：**
   - 30 条样本的文本全部完整；声学、视觉各有 27 条存在缺失；
   - 平均缺失比例约 21%，最大 50%，最长缺口不超过参照区间的 23%。

   结合我们的发现（声学、视觉的局部缺失几乎不改变预测），附件3 的预测质量主要取决于完整文本下的模型精度，MG 的文本补偿在附件3 上基本用不到。

## 三、与题面一致、可以保留并在论文中强调的做法

- 文本接口只用 `text_bert`，并且能说明理由：它是三个附件唯一共有的文本字段。
- 题面插图中的词级时间戳用的是 wav2vec2 CTC 强制对齐，与我们附件4 用 MMS 强制对齐的思路一致；再加上对齐置信度和人工核验，可复核性更强。
- 只在训练集上学参数、只在验证集上选结构、超参数与阈值，测试集只用于最后报告。
- DeBERTa、MMS 属于允许的开源预训练模型（通用语料预训练，未用情感数据），论文需写明名称、版本与核心参数。
- 题面参考文献中 CMAD（缺失模态蒸馏）、知识蒸馏与动态调整、EMOE（动态模态专家）与我们的自蒸馏、门控补偿方向一致，可以在论文中对照引用。

## 四、v3.1 改进计划（v3 结果出来后确定细节）

### P0 合规与可交付

1. DeBERTa 输入只从 `text_bert` 还原，不再读 `raw_text`；重训 DeBERTa。
2. 部署规则加体积上限：问题二模型 ≤ 20 MB（fp16）；集成只作参考。部署单模型或集成蒸馏学生，fp16 导出，并报告各文件大小。
3. 问题三专项模型：共享问题二的编码器，配上自己的可加分解融合头，用 8 子集整路丢弃训练；问题三的输出全部由它产生。
4. 日志与报告脱敏。

### P1 回应题面叙事

5. 朴素零填充固定融合对照（同种子）。
6. 稳定性指标；按绝对缺失长度分组。
7. 宏 F1 与加权 F1 同报；以验证集为官方口径。

### P2 可选

8. 缺失—性能退化律：用逐样本预测拟合“正确概率 ~ 剩余文本比例 + 位置 + 模态”的逻辑回归，给出带区间的系数。
9. 模态可加分解头。

## 五、v3 结果带来的决定（详见 `claude/v3结果与结论.md`）

1. **附件3 的输入不一致已证实：** 训练集 3392/3395 条用原文恢复了大小写，附件3 的 30 条全部是小写还原文本。所以必须只从 `text_bert` 还原文本并重训。
2. **单模型与集成的差距：** 在 VC 上，集成比部署种子 s17 高约 1.6 个宏 F1 点、1.0 个 Acc 点，MAE 低 0.023；在测试集上两者几乎相同。
   - 交得上去的只有单模型；
   - 集成蒸馏值得做一次，但要按事先定好的规则在 VS 上与 s17 比较后再决定部署哪个。
3. **目标：**
   - Acc 与 MAE 已达标；
   - 宏 F1 集成差 0.3–1.4 个点，单模型差约 2.5 个点，瓶颈仍是中性类；
   - 加权 F1 已过 0.70。
4. **新增 P0：** 最终输出一律做极性与强度的一致化。v3 的部署集成没有执行这一步，附件3/4 出现了“负向却给正强度”“中性强度不为 0”的情况。
5. **新增 P1：**
   - 文本证据改为逐个整词遮挡；
   - LoRA 权重做指数滑动平均，减小选 epoch 的噪声；
   - 在 VS 上做温度缩放。
