## Q1：连续三项斐波那契数之和

斐波那契数列满足 `F[k+2] = F[k] + F[k+1]`，所以连续三项的和是：

```text
F[k] + F[k+1] + F[k+2] = 2 * F[k+2]
```

这些和组成 `2, 4, 6, 10, 16, ...`，仍然是前两项相加得到下一项。

代码先排除奇数，特判 2 和 4，再生成这个序列，直到等于或超过 n。偶数不一定满足条件，比如 8 就不在这个序列里。

时间复杂度 `O(log n)`，空间复杂度 `O(1)`。题目中 `n <= 10^9`，循环最多生成到 `1,402,817,466` 就会退出，int 足够。

## Q2：选择质数子集 I

这题要求总和不超过 s，并且质数数量最多。先用埃氏筛找出不超过 n 的质数，再从小到大选。

贪心的依据是：任意 k 个质数的总和，都不会比最小的 k 个质数更小。如果最小的 k 个都超预算，就不可能选出其他满足预算的 k 个质数。

我最开始的代码有两个问题：

- 质数判定除了几个特判外，一直返回 false。`6k±1` 只是必要条件，25、35 也满足这个形式，但不是质数。
- sum 把非质数也加进去了，导致过早用完预算。应该只在选中质数后累加。

最终使用埃氏筛，sum 用 long long，时间复杂度 `O(n log log n)`，空间复杂度 `O(n)`。

## Q4：选择质数子集 II

这题的三个要求有先后顺序：先使总和最大，再使数量最少，最后使递增数组的字典序最小。

我刚开始以为，数量最少就应该从大到小选，字典序最小又应该从小到大选，所以不太清楚怎么同时处理。实际上可以先用 DP 确定最优值，再重建具体答案。

### DP 定义和转移

```text
dp[i][t]：使用数值在 [i,n] 内的质数，精确凑出 t 的最少数量。
```

这里的 i 是整数数值，不是质数数组的下标。不是质数的数只能跳过。

边界是 `dp[n+1][0] = 0`：没有候选数剩余时，只能用 0 个数凑出总和 0。其他状态先设成 1001，表示不可达。

```text
不选 i：dp[i+1][t]
选 i：  dp[i+1][t-i] + 1
```

选择分支必须满足 i 是质数，并且 `t >= i`。两个分支取最小值。因为当前行依赖下一行，所以 i 从 n 向 0 遍历。

算完以后，从 s 向下找第一个可达总和 target，得到最大总和和对应的最少数量。

### 重建答案

从小到大考察质数 i。如果满足：

```cpp
prime[i] && target >= i &&
dp[i][target] == 1 + dp[i+1][target-i]
```

就选择 i，并令 `target -= i`。

等式说明选 i 后，仍然可以用最少数量完成剩下的总和。如果选和不选都能保持最优，就优先选当前较小的质数；它会让第一个不同位置更小，因此得到字典序最小的答案。

### 为什么想到后缀状态

重建时，每次都需要问：选了当前质数以后，只用后面更大的质数，还能不能完成剩余总和并保持最少数量？后缀 DP 正好能回答这个问题。

如果两条选择历史都来到同一个 i、同一个剩余目标 t，那么它们剩余可用的质数和需要凑出的总和完全相同，可以共用同一个 DP 结果。这个结果只计算未来新增的数量。

转移也可以直接证明：所有方案都能分成选 i 和不选 i 两类，取两类中的最优值即可。如果某个方案的剩余部分还能用更少的数完成，那么替换它后，整个方案也会更好。这就是最优子结构。

### 这次修正的错误

- 凑出 0 的数量应该是 0，不能初始化成 1。
- 必须初始化终止行 `dp[n+1][0]`。
- 内层循环变量统一为 t。
- 转移和重建都要检查 `t >= i` 或 `target >= i`，避免负下标。

本题 `n,s <= 1000`。DP 的时间、空间复杂度都是 `O(ns)`；算上筛法，整体时间是 `O(ns + n log log n)`，空间是 `O(ns+n)`。
