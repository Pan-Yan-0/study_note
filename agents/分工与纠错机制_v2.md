## 2. Google Drive 主工作区与 GitHub 同步架构

**核心原则（Pan-Yan-0 已定）**：以 **Google Drive（`Pan-Yan-0_工作区`）作为所有端共同读写的主工作区**，**GitHub 保存同步副本、运行 Actions 补充复核并保留版本历史**。

| 内容类别 | Google Drive（所有端共同读写主工作区） | GitHub（同步副本、Actions 复核与版本历史） |
|---|---|---|
| **分工、各线状态、学习存档** | 当前权威版本，各端从这里开工 | 同步到对应公开（`study_note`）或私有仓库（`personal_study_image`） |
| **NLP 论文、素材、图片、音频、视频** | 原文件和正式产物统一保存 | 保存需要版本管理的文字、索引和引用 |
| **SemEval 代码、配置、运行包** | 保存对应版本，供各端读取和交接 | 同版本代码用于 `diff`、测试和 Actions |
| **权重、逐条预测、结果 ZIP** | 完整保存，附 `SHA-256` 哈希 | 保存指标摘要、清单和哈希 |
| **审阅意见、自动检查回执** | 写回对应任务目录，所有端可读 | 保存运行记录与必要的审计证据 |

### 2.1 可见范围隔离与文件管理 6 项必要信息

1. **Drive 内两级可见状态与发布前拦截位置**：
   - **`工作区私有`（默认）**：所有新草稿、私有记录、个人画像、中间讨论默认处于该状态，只留在 Drive 私有工作区或同步至私有仓库。
   - **`允许公开发布`**：拟从 Drive 导出进入公开仓库 `study_note` 的笔记、实验文档与代码，**必须在本地 `git commit / git push` 之前**（而非等到 push 后才靠 Actions 事后报错）通过 `agents/check_repo_hygiene.py --require-public-ready --require-task-scope --verify-receipt` 硬门禁与对应内容审阅，标记为 `允许公开发布` 且状态为 `通过` 后方可推送；GitHub Actions 在 push 后运行相同参数做补充复核。
2. **交接与任务文件固定记录 6 项必要信息**（由 `agents/check_repo_hygiene.py --require-handoff-header` 自动校验）：
   - `任务与当前负责人`（如 `TASK-LEARN-001 | Gemini 网页端`）
   - `允许修改范围`（如 `ML_note/原理笔记/`、`ML_note/实验/ShortGPT_BI删层/`）
   - `来源版本`（记录源 Git commit、Drive `fileId` 与输入内容 `SHA-256`）
   - `可见范围`（`工作区私有` 或 `允许公开发布`）
   - `当前状态`（`待提稿` / `待审` / `退回` / `通过`）
   - `正式结果链接`（及拟合入仓库的 `目标仓库路径`；正式文件原位更新保留同一链接，旧交接稿移入归档目录，统一入口只指向当前版本；更新 Drive 副本前核对源 commit 与内容哈希，避免两边各自修改后互相覆盖）。

### 2.2 互通与防覆盖的三步闭环同步

1. **统一入口读取与方向边界下发**：各端先从 Drive 的统一入口（`00_入口/当前任务与交接入口.md`）读取当前任务的大致方向与四条硬边界（目标、允许修改范围、数据源、公开/私有红线）；具体实现方式随 `Pan-Yan-0` 在各端实操反馈动态调优。
2. **确定版本送检**：Antigravity 基建把 Drive 上的确定版本拉取到本地检查，记录 **Drive 文件 ID、实际字节 `SHA-256` 哈希和基线 Git commit** 的对应关系；学习线同时联动运行 `check_repo_hygiene.py` 与 `check_archive.py`。
3. **版本绑定回执写回 Drive 与发布前校验**：
   - 自动检查生成的回执（`CHECK_RECEIPT_<任务ID>.md` 与 `.json`）写回 Drive 对应任务目录，同时记录双检查器结果与被检文件的实际字节 `SHA-256`。
   - **明确区分“格式检查通过”与“内容审阅通过”**：处于 `工作区私有` / `待审` 状态的交接稿，回执显式标注“仅代表格式/隐私/任务范围检查通过；内容待审，尚未获准公开发布”。
   - 若写作者在检查期间又改了文件，或校验时未传入待审文件的实际字节（空输入），`--verify-receipt` 直接报错拦截。

### 3.1 把“任务允许改哪里”与“公开发布门禁”接入自动检查

1. **任务范围自动绑定（`--require-task-scope` + [`agents/current_task.json`](current_task.json)）**：
   - 本地 `pre-push` 钩子与 GitHub Actions 均启用 `--require-task-scope`。若未显式传入 `--task-manifest` / `--allowed-prefixes` / `--expected-line`，检查器自动从对应 commit 或工作区的 `agents/current_task.json` 读取当前任务的 `expected_line` 与 `allowed_prefixes`；若缺失则直接报错退出（`未完成任务范围验收`）。
   - 即使单次提交未混改多条线（如 B1 任务期间只改了学习笔记），只要越出 `agents/current_task.json` 绑定的允许范围即报错拦截。
2. **公开发布门禁覆盖全部扫描模式（`--require-public-ready`）**：
   - 在 `--files`、commit 范围扫描与暂存区/工作区扫描中同步执行：凡带有 `可见范围: 工作区私有` 或 `当前状态: 待审/退回/待提稿` 的文件均报错拦截。
   - 发布前检查位置：从 Drive 导出文件至公开仓库 `study_note` 时，**在本地提交/推送前**运行检查（可通过 `python3 agents/check_repo_hygiene.py --repo . --install-pre-push-hook` 安装本地 `pre-push` 钩子自动拦截），Actions 作为远端补充复核；首次推送新分支（远端 SHA 为全零 `0000...`）时扫描全部将被发布的可达历史，不退化为只检查最后一个 commit。
3. **非空双向回执校验（`--verify-receipt`）**：
   - `verify_bound_receipt` 拒绝空输入 `{}`，强制要求传入 `--files` 读取待审文件的实际字节并双向核对回执中的 `file_hashes` 清单。

### 3.2 把审查限定在本次产物及受影响的地方

1. **写作者前置自检**：交接前先完成已有脚本检查，并在 Drive 任务目录附上与当前文件 `SHA-256` 绑定的检查回执（注：自动检查通过仅代表格式/隐私/范围合规，不代表学科内容已审核通过）。
2. **审阅者聚焦四类实质问题**：只检查会改变**正确性、结论、可运行性和隐私边界**的问题：
   - **SemEval 实验线重点**：`fold` 隔离、标签方向（`F`/`B`）、对照条件、指标定义和运行回执。
   - **NLP 学习笔记与论文阅读重点**：概念定义、公式推导、张量形状（tensor shape）及具体例子。
   - **多模态试验产物重点**：图表数字、公式和模型结构仍由原始数据或代码核对。
3. **复验与收敛边界**：修订后只复验原问题及受影响的部分，通过即结束；文字润色仅作为可选建议，不阻塞通过；新实验、新功能另立新任务。

## 4. 错误分级与四档修法

每被纠正一次，按顺序选修法，前一档做不到才选下一档并写明原因：
1. **改结构**：让错误没机会发生（例：Drive 作为唯一共同读写入口；仓库 `agents/current_task.json` 绑定当前任务范围；回执绑定文件实际字节 `SHA-256` 快照；发布前本地门禁先于 `git push` 执行）。
2. **自动检查**：活干完自动过一遍，犯了马上拦下（例：`check_archive.py`、`check_drafts.py`、`agents/check_repo_hygiene.py` 及 GitHub Actions `repo-hygiene.yml`）。
3. **写成规矩**：前两档做不到时才加；一条规矩被违反一次即升为“中度”，必须改成第 1 或第 2 档。
4. **Pan-Yan-0 抽查**：只留给硬规则与每周抽查清单，不作为修法。

| 级别 | 判定标准 | 处理步骤 |
|---|---|---|
| **轻** | 被已有自动检查拦下；或只影响单个未交接的文件 | 当场改，不记台账 |
| **中** | 越过了本该拦住它的环节，到了另一端或 Pan-Yan-0 手里；或同类错第二次出现；或别人已基于错误状态干活 | 止损 → 找本该拦住它的那一层 → 用第 1 或第 2 档修 → 注入错误做回归测试 → 记进 [纠错台账](纠错台账.md) |
| **重** | 进了给导师看的结论；隐私进了公开仓库；造成数据、算力或已发布帖子的不可逆损失 | 停掉这条线 → 回滚 → 改结构 → 回归测试 → 同步所有端 → 再恢复 |

历史纠错记录与扫描验收回执统一在 [纠错台账](纠错台账.md) 单点维护，不在本文重复抄写。
