## 2. Google Drive 主工作区与 GitHub 同步架构

**核心原则（Pan-Yan-0 已定）**：以 **Google Drive（`Pan-Yan-0_工作区`）作为所有端共同读写的主工作区**，**GitHub 保存同步副本、运行 Actions 补充复核并保留版本历史**。

| 内容类别 | Google Drive（所有端共同读写主工作区） | GitHub（同步副本、Actions 复核与版本历史） |
|---|---|---|
| **分工、各线状态、学习存档** | 当前权威版本，各端从这里开工 | 同步到对应公开（`study_note`）或私有仓库（`personal_study_image`，由 `Pan-Yan-0` 本机或已配置该私有库写入凭据的环境备份） |
| **NLP 论文、素材、图片、音频、视频** | `30_资料/` 存论文原件，`素材/` 存试生产物与素材卡 | 公开仓库仅保存经审核的文字、索引和引用 |
| **SemEval 代码、配置、运行包** | 保存对应版本，供各端读取和交接 | 同版本代码用于 `diff`、CPU 测试和 Actions |
| **权重、逐条预测、结果 ZIP** | 完整保存，附 `SHA-256` 哈希（二进制权重`工作区私有`） | 公开仓库保存脱敏指标摘要、OOF/预测（用 `git add -f`）和哈希 |
| **审阅意见、自动检查回执** | 写回对应任务目录，所有端可读 | 保存公开运行记录与必要的审计证据 |

### 2.1 可见范围隔离与文件管理 6 项必要信息

1. **Drive 内两级可见状态与发布前拦截位置**：
   - **`工作区私有`（默认）**：所有新草稿、私有记录、个人画像、中间讨论默认处于该状态，只留在 Drive 私有工作区或同步至私有仓库。
   - **`允许公开发布`**：拟从 Drive 导出进入公开仓库 `study_note` 的笔记、实验文档与代码，**必须在本地 `git commit / git push` 之前**（而非等到 push 后才靠 Actions 事后报错）通过 `agents/check_repo_hygiene.py` 硬门禁与对应内容审阅：
     - 从 Drive 导出单文件核验时运行 `--files <导出文件> --target-rel-path <目标相对路径> --require-public-ready --require-task-scope --verify-receipt <回执JSON>`（注意：文内交接表头不得越权覆盖 `HEAD:agents/current_task.json` 的范围绑定）；
     - 即使被审定稿件已人工剥离交接表头（正文中不再带 `可见范围 / 当前状态` 表），检查器仍依据 `agents/current_task.json` 中匹配任务的 `visibility` 与 `status` 实施兜底拦截：只要匹配任务本身为 `工作区私有` 或（非 `infra` 任务的）`待审/退回/待提稿`，`--require-public-ready` 仍会在 `--files`、commit 扫描与工作区扫描中一律报错；
     - 在本地推仓前由 `pre-push` 钩子自动拦截全部拟推送 commit；GitHub Actions 在 push/PR 后运行 `--ownership-mode error --require-task-scope --require-public-ready --check-task-pool` 做补充复核。
2. **明确区分 `status`（产物放行门禁状态）与 `task_state`（任务执行进度）**：
   - **`status`（文件/任务放行状态，供 `--require-public-ready` 自动校验）**：仅取 `待提稿` / `待审` / `退回` / `通过`。对于已获批准可直接按范围开发并向公开仓库提交代码与脱敏指标的 SemEval 公开任务（`TASK-SEMEVAL-A1-ARCHIVE`、`TASK-SEMEVAL-A1-RECALC`、`TASK-SEMEVAL-B1`），其任务条目 `visibility="允许公开发布"` 且 `status="通过"`，代表**准许公开代码/结果入库**，不代表实验已跑完；具体开发、阻塞与复算进展由 `task_pools/*.json` 的 `task_state` 描述。
   - 对于学习线等默认私有任务（如 `TASK-LEARN-001`），在审阅完成并获准公开发布前，其交接稿与 `agents/current_task.json` 必须保持 `visibility="工作区私有"`、`status="待审"`。
3. **交接与任务文件固定记录 6 项必要信息**（由 `agents/check_repo_hygiene.py --require-handoff-header` 自动校验）：
   - `任务与当前负责人`（如 `TASK-LEARN-001 | Gemini 网页端`）
   - `允许修改范围`（如 `ML_note/原理笔记/`、`ML_note/实验/ShortGPT_BI删层/`）
   - `来源版本`（记录源 Git commit、Drive `fileId` 与输入内容 `SHA-256`）
   - `可见范围`（`工作区私有` 或 `允许公开发布`）
   - `当前状态`（`待提稿` / `待审` / `退回` / `通过`）
   - `正式结果链接`（及拟合入仓库的 `目标仓库路径`；正式文件原位更新保留同一链接，旧交接稿移入归档目录，统一入口只指向当前版本）。

### 2.2 互通、单点写入与防覆盖的五步闭环同步

1. **统一入口读取与方向边界下发**：各端先从 Drive 的统一入口（`00_入口/当前任务与交接入口.md`）及本任务 `POOL_<TASK-ID>.md` 读取任务目标、单点写入允许与禁止范围、权威数据源、公开/私有红线；具体实现方式随 `Pan-Yan-0` 在各端实操反馈动态调优。
2. **确定版本送检与双检查器联动（学习线四步合入流 SOP）**：
   - **步骤 ①（Drive 私有伴读编辑）**：`Gemini 网页端`在 Drive `10_交接/学习/` 完成伴读批改与原位更新 `TASK-LEARN-001_NLP笔记交接稿.md` 及 `学习存档.md`（交接稿顶部保持 `可见范围: 工作区私有`、`当前状态: 待审`）。
   - **步骤 ②（基建双检查器绑哈希出回执）**：`Antigravity 基建对话`从 Drive 拉取交接稿、`学习存档.md` 与 `SKILL_cognitive-tutoring.md`（平铺 Drive 风格自动暂存为 `archive_stage/skill/SKILL.md` 并构造真实 `.md` 镜像仓库检验目标路径 `ML_note/原理笔记/...`），联动运行 `check_repo_hygiene.py` 与 `check_archive.py`（检查 Unicode 下标、断链与存档版本号），把绑定了**交接稿 SHA-256 + `学习存档.md` SHA-256 + `SKILL` SHA-256** 的回执写回 Drive `CHECK_RECEIPT_TASK-LEARN-001.md`。
   - **步骤 ③（GPT 聊天端只读终审）**：`GPT 聊天端`只读 Drive 交接稿与 `CHECK_RECEIPT_TASK-LEARN-001.md` 核对概念、公式、tensor shape 与数字出处；通过后在对话给出放行结论。
   - **步骤 ④（`current_task.json` 单独升级再剥头发布）**：`Antigravity 基建对话`先**单独 commit 修改 `agents/current_task.json`**（将该任务 `visibility` 与 `status` 更新为 `允许公开发布` / `通过`），再从交接稿剥离交接表头、将正文写入 `ML_note/原理笔记/推理优化/ShortGPT删层与INT8量化离群值.md`，运行 `check_repo_hygiene.py --files ... --require-public-ready --require-task-scope` 与 `check_archive.py` 校验通过后提交推送 `study_note`。
3. **版本绑定回执与空输入拦截**：
   - `verify_bound_receipt` 拒绝空输入 `{}`，强制要求传入 `--files` 读取待审文件的实际字节并双向核对回执中的 `file_hashes` 清单。
   - 若写作者在检查后又改了文件，旧回执自动失效，必须重检。
4. **任务级分端信息共享池（消除跨端“产物位置不明或某端持有但未同步”的信息盲区）**：
   - 信息共享池**按“每个任务 × 每个端”分立维护**（不混成全体大杂烩），在 Drive `00_入口/当前任务与交接入口.md` 第 1.1 节、`10_交接/<工作线>/POOL_<TASK-ID>.md` 与仓库 [`agents/task_pools/<TASK-ID>.json`](task_pools/) 登记每个活跃任务在各端及存储位置的文件持有状态、`SHA-256` 及**待核验/待同步项**。
   - `check_repo_hygiene.py --check-task-pool` 自动校验 `agents/task_pools/*.json` 与 `current_task.json` 的 `task_id / expected_line / owner / allowed_prefixes / forbidden_prefixes` 一致性，拦截重复 `task_id`、孤立 pool 文件与 `github_repo: "synced"` 的假同步。
5. **交付前独立子 agent 自审查门禁（防 C-006 同类事实与路径错误）**：
   - 凡向 `Pan-Yan-0` 或其他端交付**跨端启动提示、任务入口变更、交接包或复算结论**前，起草端**不得仅靠主上下文凭记忆直接输出**，必须先派生至少 1 个**只读独立审查子 agent**，逐字核对仓库最新 commit 中的实验组名/臂名与表头、冻结计划与 README 原文协议条件、实际存在的文件路径及 `SHA-256`、`agents/current_task.json` 与 `agents/task_pools/` 的单点写入范围。

### 3.1 把“任务允许改哪里”与“公开发布门禁”接入自动检查

> 定位说明：下列自动检查实现的是**“任务范围自动检查＋单点写入约定”**（核查改动路径是否落在活跃任务范围内、且与任务清单申报的 `owner` 对应），**不验证实际执行者身份，也不是身份权限系统**；现行 31/31 门禁已足够约束大方向与边界，按 `Pan-Yan-0` 与 `GPT Codex 端` 建议**停止继续扩大基建**，优先推进实际实验阻塞。

1. **活跃任务列表绑定、单点拆分与防单次自改（`--require-task-scope` + `--check-task-pool` + [`agents/current_task.json`](current_task.json)）**：

2. **公开发布门禁覆盖全部扫描模式与全平台安装（`--require-public-ready`）**：

## 4. 错误分级与四档修法

每被纠正一次，按顺序选修法，前一档做不到才选下一档并写明原因：
1. **改结构**：让错误没机会发生（例：Drive 作为唯一共同读写入口；仓库 `agents/current_task.json` 单独提交绑定单点写入范围；回执绑定交接稿与存档/Skill 的实际字节 `SHA-256` 快照；发布前本地门禁先于 `git push` 执行）。
2. **自动检查**：活干完自动过一遍，犯了马上拦下（例：`check_archive.py`、`check_drafts.py`、`agents/check_repo_hygiene.py` 及 GitHub Actions `repo-hygiene.yml`）。
3. **写成规矩**：前两档做不到时才加；一条规矩被违反一次即升为“中度”，必须改成第 1 或第 2 档。
4. **Pan-Yan-0 抽查**：只留给硬规则与每周抽查清单，不作为修法。

| 级别 | 判定标准 | 处理步骤 |
|---|---|---|
| **轻** | 被已有自动检查拦下；或只影响单个未交接的文件 | 当场改，不记台账 |
| **中** | 越过了本该拦住它的环节，到了另一端或 Pan-Yan-0 手里；或同类错第二次出现；或别人已基于错误状态干活 | 止损 → 找本该拦住它的那一层 → 用第 1 或第 2 档修 → 注入错误做回归测试 → 记进 [纠错台账](纠错台账.md) |
| **重** | 进了给导师看的结论；隐私进了公开仓库；造成数据、算力或已发布帖子的不可逆损失 | 停掉这条线 → 回滚 → 改结构 → 回归测试 → 同步所有端 → 再恢复 |

历史纠错记录与扫描验收回执统一在 [纠错台账](纠错台账.md) 单点维护，不在本文重复抄写。
