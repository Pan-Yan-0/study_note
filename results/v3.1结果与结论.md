## 二、结论

1. **统一输入接口的代价**
   - 与 v3（DeBERTa 读 raw_text）相比，单模型种子均值在验证集上宏 F1 低约 1.2 个点、Acc 低约 1.0 个点。
   - MAE 反而略好（0.494 对 0.503），可能来自 EMA。
   - 丢失的主要是大小写信息：`text_bert` 是 uncased 分词，还原出的文本全是小写，而 DeBERTa-v3 是区分大小写的模型。
2. **集成不再有优势**
   - v3.1 的 5 种子集成在验证集上宏 F1 为 0.653，低于单模型均值 0.661。
   - 与 s17 的视频配对差：验证 [−3.4, +0.5] 个点，测试 [−0.7, +2.8] 个点，都不显著。
   - 集成主要改善 MAE 与相关系数，但中性类召回下降（0.457，单模型约 0.48）。概率平均偏向置信度高的正、负类。
   - v3 里集成的优势（验证宏 F1 +1.3）在 v3.1 里消失了。所以把集成量化后放进附件（约 22 MB，总计约 40 MB）技术上可行，但以现在的成员不会更接近目标。
3. **蒸馏学生没有收益**：与 s17 的配对差，验证集宏 F1 为 [−3.0, +1.7] 个点。部署规则按事先定好的方式选了 s17（VS 折外 J：0.6507 对学生 0.6453）。
4. **与目标的差距（部署 s17）**
   - 验证集：Acc 0.692、加权 F1 0.690，各差约 1 个点；宏 F1 0.667，差 3.3 个点，瓶颈是中性类（F1 0.48，中性样本错误率 54%，最多的错误是“中性→正向”79 条）。
   - 测试集：Acc 0.710、加权 F1 0.711，达标。
   - MAE：各集合都在 0.48–0.52，达标。
5. **合规项全部通过**
   - 附件3/4 的极性—强度不一致都是 0 行。
   - 提交文件夹共 16.8 MB（问题二 14.7 MB，问题三融合头 1.3 MB）。
   - fp16 往返完全一致：推理本来就在混合精度（fp16）下计算，所以问题二 max|Δp| = 0；问题三为 1e-4 量级。
   - 日志已脱敏。
6. **朴素零填充对照（回应题面“常规固定权重融合”）**
   - 完整输入时与 base 相当。
   - 文本整段缺失时比 base 低 16.7 个点（验证）/ 19.0 个点（测试）。
   - 三模态同时缺失 90% 时低 4.6 个点。
   - 只删声学或视觉时，类别翻转率是 base 的 3–10 倍（2–9% 对 0.5–3%）。
   - 结论：常规做法的问题主要是输出不稳定，以及某个模态整段缺失时崩溃；并非所有缺失都会“急剧下降”。
7. **问题三专项模型**
   - 验证集宏 F1 0.662、Acc 0.681、MAE 0.492，与问题二 s17 接近。
   - 可加贡献与精确 Shapley 的主导模态一致率为 97.9%。
   - 文本整词删除检验：删高分位置的概率下降比删随机位置多 0.21 [0.16, 0.27]；声学、视觉约为 0。
   - 融合头在第 1 个 epoch 就被选中，VS 曲线噪声较大。
8. **共形预测（α = 0.1）**：强度区间的测试覆盖为 0.869–0.893，中、重度缺失桶略低于 0.90。
